# Panel: infisical-secrets
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-09-30

- [x] [critical] Any name in the Infisical environment is injected into the host compose process and overrides ambient values; only `COMPOSE_*` was refused, so `LD_PRELOAD`, `DOCKER_HOST`, `BASH_ENV`, `CONFIRM` or `AUTOLOGGER_TEST` would run code as the docker-group operator or retarget docker. Evidence: `Infisical/cli packages/cmd/run.go` -> "add all existing environment vars ... now add infisical secrets ... environmentVariables[k] = v.Value"; reserved list is only HOME, PATH, PWD, SHELL, USER, TERM and a few others. Resolved: design D1 inner stage refuses any injected name outside the environment's allowed set (D3) before any docker call; `env -i` base; spec scenario "A hostile secret name is refused"; test in task 3.2.
- [x] [major] Change estimated at about 700 counted lines against the 400 budget: README counts, and deleting the templates counts 111 lines. Evidence: `scripts/lib/check_change.py:413-414` -> `int(added) + int(deleted)`; `wc -l docker/.env*.example` -> `111 total`. Resolved: invariant 16, `secrets.example` and `keys-diff` cut; one allowlist file via `extends`; runbook detail moved to `docs/infisical-secrets.md` (excluded from the budget); template deletion deferred to the owner after cutover; new estimate about 350; task 5.3 checks `size` ≤ 400.
- [x] [major] Invariant 15 ("pin is literal or null passthrough") fails the committed tree: `PUBLIC_BASE_URL` is interpolated in all three stacks. Evidence: `compose.yaml:100`, `docker/compose.dev.yaml:57`, `docker/compose.stage.yaml:40`. Resolved: that invariant is dropped (it added no security; invariants 6 and 7 pin the posture). The new invariant 15 checks only that the allowlist file equals the resolved passthroughs.
- [x] [major] Invariants 14 and 15 would fire on the prod + e2e overlay that `check-envs.sh` already resolves (`env_file: !override`, `IP_ALLOWLIST: ${E2E_IP_ALLOWLIST:-}`). Evidence: `e2e/container/compose.e2e.yaml:12-15`; `check-envs.sh:354`. Resolved: invariant 14 explicitly exempts prod + e2e; invariant 15 checks only prod `api` and dev `app`.
- [x] [major] Invariants must read `--no-interpolate`: `--no-env-resolution` fills passthroughs from the caller, and overlays turn `environment` into an array. Evidence: panel toy `--no-interpolate` -> `"FOO":null`; stage `.services.api.environment|type` -> `"array"`. Resolved: design D5 and task 2.2 use `--no-interpolate` and handle both shapes.
- [x] [major] The Makefile wrapper `sh -c '... "$@"' sh` in a make variable expands `$@` as make's own variable, which drops every compose subcommand. Evidence: toy Makefile `make -s dev-up` -> `ARG[/dev/null] ARG[]`. Resolved: no `sh -c` in make; each target calls `compose-run.sh ENV STEP...` (D1).
- [x] [major] The run step got neither the domain nor the CA, so it would fall back to Infisical Cloud. Evidence: `packages/cmd/root.go` -> default `INFISICAL_DEFAULT_US_URL`, precedence "Flag > environment variable > config file > default". Resolved: D1 passes `INFISICAL_DOMAIN` and `SSL_CERT_FILE` to both login and run; asserted in task 3.2.
- [x] [major] `infisical secrets --plain` prints `KEY=VALUE`, and task 1.2 pasted the output of a prod read attempt. Evidence: `packages/cmd/secrets.go` -> `PrintfStdout("%s=%s\n", ...)`. Resolved: not used. Names come from `jq -rn 'env|keys[]'` inside the run; task 1.2 pastes only an exit code.
- [x] [major] Guard and compose fetched separately (a time-of-check to time-of-use gap), with several logins per target and partial failure mid-`dev-restart`. Evidence: `Makefile:35-52`. Resolved: one login and one `infisical run` per target, with guards and every compose step in the same child (D1).
- [x] [major] Null passthroughs took values from the operator's shell (for example a stale `API_TOKEN` or the host `server/.env`), a new leak path compared with `env_file`. Evidence: panel toy `API_TOKEN=fromshell ... config` -> `{"API_TOKEN":"fromshell",...}`. Resolved: `env -i` base (D1); spec scenario "Shell variables do not leak into a stack".
- [x] [major] Ambient-override behaviour was left open, though the CLI source already shows Infisical wins, contradicting the `compose-env.sh` comment. Evidence: `compose-env.sh:30-31`; `run.go` override order. Resolved: D3 decides that ambient overrides no longer apply; the comment and docs change (tasks 3.3, 4.2).
- [x] [major] `make-guards.sh urls` and `reset` still resolve with `.env.dev`/`.env.stage`, which breaks once those files are deleted and contradicts the spec. Evidence: `make-guards.sh:94,103,139-146`. Resolved: both run inside the inner stage with `/dev/null` (task 3.3); task 3.4's grep check.
- [x] [major] Hand-typed `docker compose up -d` (the documented runbook) would start `api` silently with no secrets. Evidence: `README.md:1054,1268,1324,1378`. Resolved: `AUTOLOGGER_STACK` `:?` sentinel (D4) and spec scenario; runbook rewritten (task 4.1).
- [x] [major] Token TTL, scope and revocation were unspecified; the token sits in `/proc/<pid>/environ` during long `logs -f`. Evidence: design v1 D1 had no TTL. Resolved: D6 sets read-only identities, 15-minute TTL and 1-hour max, Trusted IPs and rotation; task 1.2.
- [x] [major] "Agent-unreadable" was overstated: `Bash` `cat`, `docker inspect`, `docker exec env` and `/proc/*/environ` all bypass the Read deny rule. Evidence: `.claude/settings.json` deny list has no `Bash(cat …)`; `docs/security.md:68`. Resolved: design risk section and task 4.3 state the residuals.
- [x] [major] Owner name checks (`cut -d= -f1`, `keys-diff`) could print values from malformed or multi-line lines. Evidence: design v1 D4 item 5, tasks v1 1.3. Resolved: `keys-diff` cut; the owner command matches `^[A-Za-z_][A-Za-z0-9_]*=` only; the wrapper prints only valid-identifier names and counts the rest.
- [x] [major] Cutover sequencing: deleting env files after merging into `supabase-migration` breaks `main` checkouts, and prod first runs through Infisical untested at the big merge. Evidence: tasks v1 "Owner-owed after merge". Resolved: deletion is gated on reaching `main` plus a verified Infisical backup and restore test; `make prod-check` dry run on the deploy host (D7).
- [x] [major] No break-glass path, and deleting the env files cannot be undone if Infisical's data or its `ENCRYPTION_KEY` is lost. Evidence: `Makefile:107-113`; `~/infisical/README.md` "Copy `.env` somewhere safe off this machine". Resolved: D7 break-glass in `docs/infisical-secrets.md`; deletion gated on a restore test.
- [x] [major] Plain HTTP and disabled TLS were not refused. Evidence: design v1 D4 item 3. Resolved: `https://` required, messages never suggest insecure workarounds (D1, spec), and a test case in 3.2.
- [x] [major] REMOVED "Env files are untracked and templated" dropped the ignore rule for the still-present `.env*` files and the "don't reuse prod secrets" warning. Evidence: current spec lines 344-351. Resolved: the ADDED requirement keeps the ignore rule for `.env`, `.env.dev` and `.env.stage`, the tag format note, and the warning.
- [x] [major] The proposal named `docker/.env.infisical.example` while the other artifacts named `docker/infisical-credentials.example`; the former matches `Read(**/.env.*)`. Evidence: proposal v1 line 59. Resolved: the proposal now uses `docker/infisical-credentials.example` throughout.
- [x] [minor] Child environment still carried `SSL_CERT_FILE` and `INFISICAL_DOMAIN` into docker and buildx. Evidence: panel `env -u INFISICAL_TOKEN ... env` -> both present. Resolved: the inner stage unsets `INFISICAL_*` and `SSL_CERT_FILE` (D1); asserted in 3.2.
- [x] [minor] Debug logging and `sh -x` could echo secrets. Evidence: `run.go` debug log of injected vars. Resolved: `set +x` and no debug flag (D1).
- [x] [minor] `--expand` defaults to true and would mangle values containing `$` or `${`. Evidence: CLI docs `run --expand`. Resolved: `--expand=false` (D1), asserted in 3.2.
- [x] [minor] The allowlist grep misses child-process passthroughs (`HTTP_PROXY`, `HTTPS_PROXY`, `NO_PROXY`, `NODE_EXTRA_CA_CERTS`). Evidence: `aiChatRunner.ts:84`, `aiV2SdkSpawn.ts:110`, `ytdlp.ts:124`. Resolved: noted in D2; the owner name check (task 1.3) decides whether they are needed.
- [x] [minor] `.gitignore` was listed under Impact but needs no change. Evidence: `git check-ignore -v` -> `.gitignore:3:.env.*`, `.gitignore:4:!*.example`. Resolved: removed from Impact.
- [x] [minor] Comments and `:?` messages naming the old env files weren't covered by a task. Evidence: `compose.yaml:4,73`, `compose.dev.yaml:5-10`, `compose.stage.yaml:7-10`. Resolved: listed in task 3.1.
- [x] [minor] Some failure modes had no test-first case, and there was no scratch-path test hook. Evidence: tasks v1 3.2. Resolved: committed `test_compose_run.sh` and `test_check_envs.sh` with the `AUTOLOGGER_TEST=1` scratch-root hook; cases listed in 3.2.
- [x] [minor] The 1.1 to 1.4 split existed only in the proposal, not in ADR 0021. Evidence: `grep -n '1\.1' docs/decisions/0021-*.md` -> no match. Resolved: task 4.3 updates the ADR.
- [ ] [minor] Availability coupling: Infisical binds only `192.168.0.100` on this host, so a DHCP change or an Infisical `make reset` (which issues a new CA) blocks dev and stage starts. Evidence: `~/infisical/README.md` "`make reset` creates a new CA". Accepted in the design risks; the owner may reserve the IP.
- [ ] [minor] Three credentials files repeat the domain and CA path. Evidence: proposal, one identity per environment. This follows from the owner's decision; no change.

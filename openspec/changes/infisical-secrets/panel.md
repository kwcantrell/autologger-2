Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-09-30

## Re-panel 2026-09-30

Scope delta since approval (e85aa7a): delivery switched from `infisical run` to `infisical export` into memory, validated before any program starts with the values. This was the owner's decision, after implementation showed `LD_PRELOAD` acts at child start. Scope addition: pre-commit `check-yaml --unsafe` (owner). Reviewers: assumption tester, failure and abuse, scope and simplicity (fresh, delta only).

- [x] [critical] A non-string `value` bypasses the name allowlist: for an array, `@sh` emits several quoted words, so the eval'd `export` also sets `LD_PRELOAD` (or `PATH`, `IFS`, script variables). Evidence: `json='[{"key":"API_TOKEN","value":["x","LD_PRELOAD=/tmp/evil-value.so"]}]'; eval "$(... jq -r '.[] | "export \(.key)=\(.value|@sh)"')"; /bin/true` -> `export API_TOKEN='x' 'LD_PRELOAD=/tmp/evil-value.so'`, then an `ld.so` preload attempt. Resolved: D1 step 3 has one jq program that requires string `key` and `value`, an exact allowed-set match and a valid identifier, and emits from the same validated key; test rows in 3.2.
- [x] [major] A jq failure inside `eval "$(…)"` is swallowed (eval's status is the evaluated text's), exporting a partial set and continuing. Evidence: `dash -c 'set -e; eval "$(echo "[1" | jq -r ".[]")"; echo continued'` -> `continued`. Resolved: `exports=$(…) || die`, then `eval "$exports"` (D1 step 3).
- [x] [major] `null` or boolean values become the literal strings `null`/`true`; `API_TOKEN=null` would enable token auth with a guessable token (`server/src/env.ts:69` checks non-empty only). Evidence: `jq -r '.[]|"export \(.key)=\(.value|@sh)"'` on `{"value":null}` -> `export API_TOKEN=null`. Resolved: string-type requirement (D1 step 3).
- [x] [major] Validator (`.key // .Key`) and emitter (`.key`) read different fields, so an unvalidated name is exported (`export false='v'`, `export null='v'`). Evidence: panel jq runs. Resolved: the fields are known to be lowercase (`models/cli.go` `json:"key"`, `json:"value"`); one program validates and emits the same key.
- [x] [major] The design allowed validation outside jq; a line-based `grep -vxF` check is bypassed by a NUL in a key (GNU grep prints "binary file matches", and dash drops the NUL), which runs commands through eval. Evidence: panel `dash v.sh` -> `validation passed`, and the `PWN3` file was created. Resolved: D1 step 3 mandates the exact in-jq membership check (`index([$k])`) with `\A…\z` anchors; NUL is refused.
- [x] [major] An empty `INFISICAL_TOKEN` makes `export` fall back to the interactive user login, which writes `~/.infisical/infisical-config.json` and can write a secrets backup. Evidence: `env -i … HOME=h2 INFISICAL_TOKEN= infisical export …` -> an email prompt on stdout; `find h2` -> `h2/.infisical/infisical-config.json`. Resolved: empty token refused before export (D1 step 1); test row in 3.2.
- [x] [major] proposal.md "What Changes" still described `infisical run` as current. Evidence: `grep -n 'infisical run' proposal.md` -> line 26. Resolved: reworded.
- [x] [major] The fetch stage inherited the operator's `PATH`, contradicting the spec's "fixed base" and letting the shell choose which `docker`/`jq`/`infisical` see the secrets. Evidence: design v2 `env -i PATH="$PATH"`. Resolved: fixed `PATH=/usr/local/bin:/usr/bin:/bin`, plus a test-only path via the outer-stage `AUTOLOGGER_TEST` hook (D1 step 3).
- [x] [minor] `export` includes imported secrets by default, so a prod value imported into dev arrives under an allowed name. Evidence: `export.go` `--include-imports` default true. Resolved: `--include-imports=false`; asserted in 3.2.
- [x] [minor] An empty result (`[]`, or `null` from an empty Go slice) was accepted, starting stacks with no secrets. Evidence: `export.go` has no empty handling; `echo null | jq '.[]'` -> error. Resolved: `null` is mapped to `[]`, and at least one secret is required.
- [x] [minor] The `^…$` anchors in jq accept a trailing newline. Evidence: `jq -n '"API_TOKEN\n"|test("^[A-Za-z_][A-Za-z0-9_]*$")'` -> true. Resolved: `\A…\z` anchors.
- [x] [minor] A NUL in a value is silently altered (dropped by command substitution, or `\0` from `@sh`). Evidence: panel `xxd` output -> `'a\0b'`. Resolved: values containing NUL are refused.
- [x] [minor] jq's escape error printed the first bytes of a secret to stderr. Evidence: `object ({"s":"super...) can not be escaped`. Resolved: the program never escapes non-strings (type check first), and jq stderr is discarded; messages come from the `#refused` line only.
- [x] [minor] `LOG_DESTINATION=stdout` would put CLI logs into the JSON. Evidence: `infisical export --help` -> `--log-destination ... Can also set via LOG_DESTINATION`. Resolved: D1 lists `LOG_*`, `INFISICAL_*`, `DOCKER_*` and `COMPOSE_*` as never crossing `env -i`.
- [x] [minor] A crash could core-dump `$json`. Evidence: design v2 fetch stage. Resolved: `ulimit -c 0` in the fetch stage.
- [x] [minor] `check-yaml --unsafe` applied to every YAML file, dropping duplicate-key detection (for example a duplicate `high_risk_paths: []` in `openspec/config.yaml` would pass). Evidence: `check-yaml --unsafe dup.yaml` -> rc=0. Resolved: `--unsafe` scoped to compose files with `files:`; the others use the safe loader (task 3.6).
- [x] [minor] `--fetch` entry point, stdin hand-off and `AL_*` cleanup had no test cases; the fd-3 mechanism was unnamed. Evidence: design v2 D1. Resolved: D1 names a pipe (not a here-doc); `--fetch` fails closed without fd 3; test rows added.
- [x] [minor] The task 3.2 table had overlapping `LD_PRELOAD` rows with v1 wording, and 3.6 sat before 3.5. Resolved: merged and reordered.
- [x] [minor] v1 resolutions in this file claimed the superseded `infisical run` fix. Resolved: each is annotated.
- [x] [minor] The size estimate was stale (the wrapper draft is 140 lines; the total is about 380 to 450). Resolved: Risks updated; at task 5.3 the owner chooses a `size-override` or a split into a second PR.
- [ ] [minor] Exported secrets are in the environ of every guard, jq and docker child for the target's lifetime; readable by the same uid and root only. Inherent to passing secrets to compose; accepted.
- [x] [minor] proposal.md was edited after `Approved-by:`; re-approval is required (AGENTS.md rule 3). Resolved: re-approval requested from the owner.

## Re-panel 2026-09-30 (v3: Node wrapper over the Infisical HTTP API)

Scope delta since the v2 re-panel (1dc9c60 to 122a199): the owner moved the wrapper to Node calling Infisical's HTTP API directly (no CLI, no SDK), and asked that all stack shell tooling move to Node. Because of the size budget, this change converts the wrapper and the secret-bearing guards; a follow-up, `node-stack-tooling`, converts the rest. Reviewers: assumption tester, failure and abuse, scope and simplicity (fresh, delta only).

Superseded mechanisms: the v1 and v2 resolutions above that cite `infisical run`, `infisical export`, jq and `eval`, `set +x`, `ulimit -c 0`, the fd-3 hand-off, `SSL_CERT_FILE`/`INFISICAL_DOMAIN` unsetting, `--expand=false` or `test_compose_run.sh` now map to v3 as follows: the explicit child env built on `Object.create(null)` (H6, H12); `expandSecretReferences=false` and `includeImports=false` in the fetch query; Node has no shell parsing of values; the H4 output rules; and `compose-run.test.mjs`. The concerns stay covered, by different mechanisms.

- [x] [critical] An uncaught `JSON.parse` error on a malformed or truncated response makes Node's crash printer write the whole body line (every secret, or the token) to stderr; even a caught `e.message` quotes about 10 characters of input. Evidence: `node client.mjs /trunc` -> `<anonymous_script>:1 {"secrets":[{"secretKey":"API_TOKEN","secretValue":"SUPERSECRET123"  SyntaxError ...`. Resolved: H4 (try/catch with a fixed message, `uncaughtException`/`unhandledRejection` handlers, no parse of non-200 bodies); a test with a truncated body holding a sentinel asserts it is absent from the output.
- [x] [major] `NODE_TLS_REJECT_UNAUTHORIZED=0` in the operator's shell disables verification even with `ca` pinned. Evidence: `NODE_TLS_REJECT_UNAUTHORIZED=0 node tls.mjs` -> `wrong CA: OK 200`; with explicit `rejectUnauthorized:true` -> `UNABLE_TO_VERIFY_LEAF_SIGNATURE`. Resolved: H2 (explicit `true` on every request) and H1 (the variable is stripped by `env -i` and refused at start-up); test rows added.
- [x] [major] Node variables in the operator's env change the wrapper: `NODE_DEBUG=http` logs `Authorization: Bearer`, a `NODE_OPTIONS=--require` preload sees the token, `--inspect` opens a debugger, and `NODE_USE_ENV_PROXY` with `HTTPS_PROXY` reroutes. Evidence: `NODE_DEBUG=http,https node client.mjs | grep -i bearer` -> `Authorization: 'Bearer TOKENSECRET'`; `NODE_OPTIONS="--require ./pre.cjs"` -> `PRELOAD saw {"Authorization":...}`. Resolved: H1 (Makefile `env -i` before `node`, plus a start-up refusal of `NODE_*` and `HTTP(S)_PROXY`).
- [x] [major] It was unclear whether later steps run after a failure; `reset` lost its `dev|stage` restriction, so `prod reset 'compose down -v'` was not refused. Evidence: design v3 D1 step 7; `make-guards.sh:139-141`. Resolved: H8 (stop at the first failure; `reset` refused for prod); test rows added.
- [x] [major] The credentials file was checked only for readability. A writable file, a symlink or another owner, or an unchecked CA file (`/dev/zero`, a FIFO) could repoint the domain and CA to collect the client secret, or hang the process. Evidence: design v3 D1 step 1. Resolved: H7 (`lstat`: a regular file owned by the user with mode `& 0o077 == 0`; the CA a regular file, not group- or other-writable, at most 64 KiB).
- [x] [major] `secretValueHidden`: an identity without ReadValue gets the literal `<hidden-by-infisical>`, which passed every check. Evidence: backend `secret-fns.ts` `INFISICAL_SECRET_VALUE_HIDDEN_MASK = "<hidden-by-infisical>"`; the v4 schema has `secretValueHidden: z.boolean()`. Resolved: H5 (send `viewSecretValue=true`, refuse `secretValueHidden !== false`).
- [x] [major] `node --test docker/scripts/` fails ("Cannot find module"), which would fail `npm test` in CI and the Stop hook. Evidence: `node --test nt/sub/` -> `Error: Cannot find module`. Resolved: the root `test` script names `docker/scripts/compose-run.test.mjs`; a bare `node --test` would also pick up `server/src/test/fixtures/*.mjs`.
- [x] [major] The size estimate was unrealistic (about 600 to 700 lines against a stated 350), and the fallback split could not work, because the committed sentinel breaks the old Makefile until 3.4 lands. Evidence: `git diff --numstat ee02cb1 -- . ':!openspec' ...` -> 168 already. Resolved: superseded guards are left for `node-stack-tooling` to delete; README becomes a pointer to `docs/`; the estimate is now about 520 to 580; the PR needs the owner's `size-override` (task 5.3); the broken split plan is removed.
- [x] [major] The spec requires a Node-version failure, but no design step or test covered it. Evidence: spec "Node older than 22.12". Resolved: H1 start-up version check; test row added.
- [x] [major] The test CA source was unspecified; `node:crypto` can't create certificates, and a committed key would trip gitleaks. Evidence: `crypto.createCertificate` -> `undefined`. Resolved: `openssl` generates the CA and certificate into a temp dir at test time (assumption 17).
- [x] [major] `Approved-by:` predates v3. Evidence: `proposal.md:6`. Resolved: re-approval requested from the owner.
- [x] [minor] No timeout or body cap (slow-loris, endless body). Resolved: H3 (15 s connect, 30 s total, 1 MiB, no decompression).
- [x] [minor] Redirects and non-2xx statuses weren't specified; a 3xx or 4xx body containing `accessToken` would be accepted. Evidence: `node client.mjs /redir` -> `status 302` handed to the parser. Resolved: H3 (exactly 200, no redirect following, `node:https` only).
- [x] [minor] Prototype keys (`__proto__`, `constructor`) pass the identifier regex and defeat object lookups; `spawn` copies inherited enumerable properties. Evidence: `"constructor" in {}` -> true; a polluted prototype reached `env`. Resolved: H6 (`Set`, `Object.create(null)`, test rows).
- [x] [minor] `INFISICAL_DOMAIN` was string-concatenated; a path, query or userinfo would change the request. Resolved: H2 (`new URL`, strict parts, options from `hostname`/`port`).
- [x] [minor] Infisical's `message` was printed verbatim (escape sequences), and it is an array on 422. Evidence: login probe -> `422 {"message":[{"code":"invalid_type",...}]}`. Resolved: H4 (strings sanitized and cut to 200; arrays print `path`/`code` only).
- [x] [minor] Test hooks were live in prod and accepted relative paths. Resolved: H10 (absolute only, refused for prod, a stderr banner). Task 1.2 no longer uses the hooks.
- [x] [minor] The test stand-in could bind every interface. Evidence: `listen(port)` -> `address "::"`. Resolved: it binds `127.0.0.1` only (design, task 3.2).
- [x] [minor] Signal handling was unspecified (an orphaned child on SIGTERM; lost status on Ctrl-C). Evidence: `node sig.mjs` -> `node exit=143`, the child still running. Resolved: H9; test row added.
- [x] [minor] The child env lacked `TERM`, which breaks `dev-shell` and colour. Resolved: `TERM` passed (H12).
- [x] [minor] The step-to-argv rule was unspecified. Resolved: H11 (split on spaces; a word whitelist; test row).
- [x] [minor] The "exactly these env vars" test row was wrong for the compose path (`sh` adds `PWD`; stage adds placeholders). Resolved: the test asserts the env the wrapper spawns with, and the row lists the additions.
- [x] [minor] Stale text: assumption 7 said the CA was optional; D3 blamed the CLI for ambient overrides; tasks mentioned an "outer stage" and "install the CLI"; committed comments name `compose-run.sh`. Resolved: rewritten; task 3.2 renames the committed references.
- [x] [minor] The follow-up `node-stack-tooling` was recorded only in the proposal. Resolved: task 4.3 records it in ADR 0021 with its scope (including amending the "Static invariant check" tooling clause and moving `test_check_envs.sh` into `node --test`).

# Panel: postgres-catalog-adapter
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-01

Each reviewer ran as a separate subagent with fresh context. The failure-and-abuse reviewer and
the assumption tester probed the pinned image with postgres.js 3.4.9; their scripts are in the
session scratchpad under `panel-fa/` and `panel-at/`. Findings that two reviewers raised are
merged, and their sources are named.

- [x] [critical] (failure and abuse) A `COMMIT` sent on an aborted transaction resolves with tag `ROLLBACK`, so `tx` could resolve "committed" while nothing was written. Scenario: a body drops `t.run(...)` (unawaited), and the statement is still in flight at the end protocol. Evidence: `panel-fa/p1.mjs` -> `P1 dropped rejects 23505`, `P1 commit resolved command= ROLLBACK`, `P1 rows 0`. Resolved: design A11 and D4. The end protocol drains the attempt's chain before deciding and re-checks `failed`, and any `COMMIT` tag other than `COMMIT` fails the transaction. Spec: a transaction resolves only on a confirmed commit, plus the scenario "A dropped failing statement fails the transaction". This is a new shared-suite case and a unit case.
- [x] [major] (failure and abuse; assumption tester) The slot's `onclose` also fires on the adapter's own `end()`, about 3 ms after `end()` resolves, with a connection id as its argument. A recycled client's late close would fail the next attempt on the replacement, and that could cascade. Evidence: `panel-fa/p6.mjs` -> `idle end resolved | idle onclose`; `panel-at/p4.mjs` -> `50ms after end(): [["onclose","number","3ms"]]`. Resolved: design A9 and D3. `onclose` closes over its client object and acts only if the slot still holds that client and the adapter didn't start the close. Unit test "a recycled client's late `onclose`".
- [x] [major] (failure and abuse) `BEGIN`, `COMMIT` and non-deadline `ROLLBACK`s had no time bound, and postgres.js's `connect_timeout` defaults to 30 s, so a partition or db restart could hold slots and callers for minutes. Evidence: `index.js:453` `connect_timeout : 30`; `panel-fa/p5.mjs` (paused container) -> statement unresolved after 5 s. Resolved: design D1 and D6. `connect_timeout: 5`, `BEGIN`/`COMMIT` are bounded by the remaining budget plus a grace period, `ROLLBACK` by 1 s, and an expired bound recycles the slot. Spec: "no step SHALL wait on the server without a bound".
- [x] [major] (failure and abuse) A lost `COMMIT` reply leaves the outcome unknown, but would have been reported as an ordinary failure, followed by a meaningless `ROLLBACK` on a reconnected socket. Evidence: `panel-fa/p1.mjs` -> `P3 rollback after commit resolves command= ROLLBACK`. Resolved: design A12 and D4. A new `CatalogCommitUnknownError` (with `cause`) is never retried and sends no `ROLLBACK`, and the slot is recycled. Spec scenario "A commit with no reply is reported as unknown"; unit tests for the lost and the hung `COMMIT`. Mapping it to a response is a 4c item.
- [x] [major] (failure and abuse) A slot waiter whose deadline passes was never removed from the queue, so a dead waiter could be granted a slot it never releases, and overload would drain the slots for good. Resolved: design D3. A waiter is removed from the queue when it times out, and a slot is never granted to a rejected waiter. Spec scenario "A queued transaction times out cleanly", with a pg test.
- [x] [major] (failure and abuse) `close()` racing in-flight work was unspecified: recycling after close would leak clients, and queued waiters or retries could start new attempts. Resolved: design D7. After close, waiters and new calls reject with `CatalogAdapterBrokenError("closed")`, nothing recycles or retries, and `close()` resolves once every client has closed. Spec "Closing" plus the scenario "Closing with work in flight", with a pg test checking that no app connection remains.
- [x] [major] (failure and abuse; assumption tester) `cancel()` returns `null`, so it can't be awaited, and `.catch` on it would throw inside a timer. A late cancel can land on the next statement, possibly another caller's. Evidence: `query.js:53`; `panel-at/p6c.mjs` -> `cancel() return value: null`, `next tx on same slot failed: {"57014":3,"25P02":1}`. Resolved: design A4 and D6. `cancel()` is called in a `try` for its side effect only, and a slot that had a cancel sent is always recycled, never reused. Unit test "cancel() returning null".
- [x] [major] (assumption tester) `end({timeout:0})` leaves a backend that is running a statement alive, still holding its locks and a role connection, so neither the deadline nor a recycle really ended the server-side transaction. Evidence: `panel-at/p3.mjs` -> `active … locks 3` at +5006 ms; `p8.mjs` -> `53300` at 20; `p4.mjs` with `client_connection_check_interval: '1s'` -> `backend gone after 835 ms`. Resolved: design A10, D1 and D3. Every client sets `client_connection_check_interval = 1s`. The pg deadline test asserts the backend is gone within 3 s.
- [x] [major] (assumption tester) The test factory as written can't work: unqualified tables land in `public`, while the app role's `search_path` is `catalog`. Evidence: `panel-at/p1.mjs` -> `42P01`, `schema of t: public`, `catalog.t insert as app ok (default privileges)`. Resolved: design A16 and D8. The factory creates `catalog.t` and `catalog.log`, and default privileges grant them.
- [x] [major] (scope and simplicity) The design never considered postgres.js's own `sql.begin()`, which the reviewer read as releasing only at idle and rejecting on `onclose`. Resolved: probed and rejected, design A7. `probe4b6` and `probe4b7` show that after a loss, `begin()` itself sends `COMMIT` on the dead connection once the body returns, even when the body sends nothing. That gives `UNCAUGHT Cannot read properties of null (reading 'write')`, and the pool then `HUNG`.
- [x] [major] (scope and simplicity; assumption tester) The size estimate of about 290 wasn't credible. The SQLite adapter alone is 311 lines, and the panel fixes add more. Evidence: `wc -l asyncCatalogStore.ts` -> `311`. Resolved: re-estimated at about 450 in design D8. The owner chose one PR over budget instead of a split (2026-10-01), so the PR needs the human-applied `size-override` label. `TxState` is duplicated, not extracted, because extraction costs about 200 counted lines and 4e deletes the SQLite adapter.
- [x] [minor] (assumption tester) A7 was overstated. About half the time, a statement sent right after the kill goes out before `onclose` and rejects with `CONNECTION_CLOSED`. Evidence: `panel-at/p5.mjs` -> `closedBeforeNext 22/40`, `CONNECTION_CLOSED: 18`, `leaked rows 0`. Resolved: design A8 and D4. A `CONNECTION_*` rejection also sets `lost`.
- [x] [minor] (assumption tester) The client option `prepare: true` has no effect on `unsafe()`, and with no binds `unsafe` uses the simple protocol. Evidence: `index.js:119-126`; `p2.mjs` -> 26 ms vs 108 ms. Resolved: design A14 and D1. Every statement passes `{ prepare: true }`.
- [x] [minor] (assumption tester) `select '?' as q, ? as v` returns `v` as a string, and `SUM`/`AVG` over bigint return `numeric` as a string. Evidence: `p2.mjs` -> `{"v":"5"} string`, `s:1700 … a:1700`. Resolved: the test uses `?::bigint` (D8), and `numeric` aggregates are a 4c item (A17, task 4.2).
- [x] [minor] (assumption tester) The contract cases weren't portable as written: SQLite error codes, `r.inTransaction`, synchronous counts, `AUTOINCREMENT`, and a 50 ms deadline. Evidence: grep of `asyncCatalogStore.test.ts` -> lines 16, 122, 140, 422, 594. Resolved: design D8. The factory supplies `rows()`, `uniqueViolation` and `txTimeoutMs`; `log` drops `AUTOINCREMENT`; SQLite-specific assertions stay in the SQLite file.
- [x] [minor] (assumption tester; failure and abuse) A pg test that fails to close its adapter would hold connections against the role's limit of 20, and a recycle briefly holds an extra connection. Resolved: design D7 and D8. `afterEach` always closes, the budget drops to 3 + 5 = 8, and 4c keeps one adapter per process.
- [x] [minor] (failure and abuse) The failed deferred-FK `COMMIT` case should be in the shared suite. Resolved: design D8 moves it there.
- [x] [minor] (failure and abuse) The design relies on postgres.js silently re-running a `RevalidateCachedQuery`. Resolved: design Risks names it, alongside the other postgres.js internals the tests pin.
- [x] [minor] (scope and simplicity) The per-attempt chain was justified as "costs nothing". The real reason is to stop a statement being sent to a reconnected socket, where it would autocommit. Resolved: design D4 step 4 says so.
- [x] [minor] (scope and simplicity) Retry jitter added randomness for no measured gain. Resolved: design D5 retries at once, with no backoff.
- [x] [minor] (scope and simplicity) `40P01` and "no other failure is retried" had no tests. Resolved: design D8 adds `RAISE … '40P01'` on the first run (2 runs), `40001` every run (3 runs), and `23505` (1 run). The spec scenario is "Retries are bounded and selective".
- [x] [minor] (scope and simplicity) One scenario named an implementation detail: "more than the number of transaction connections". Resolved: it now says "more than the adapter's concurrent-transaction limit".
- [x] [minor] (scope and simplicity) ADR 0021 lists `close()` as a 4c item, but 4b delivers it. Resolved: task 4.2 moves it.
- [x] [minor] (scope and simplicity) Dropping `onBroken` is consistent with the SQLite requirement's scope, but 4c must drop its wiring. Resolved: design D7 and task 4.2 (a 4c item).
- [x] [minor] (scope and simplicity) Capability placement in `core-ports-architecture` is right, there's no conflict with the owner decisions, and no task strays into the non-goals. Resolved: no change needed.
- [x] [minor] (scope and simplicity) The size exclusions are right: the shared suite matches `**/test/**`, and the ADR falls under `docs/**`. Resolved: no change needed.

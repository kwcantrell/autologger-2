# Panel: ci-db-test-selection
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-07

- [x] [critical] The D4 post-merge run fails on every push to `supabase-migration` before any test runs. A push has no `GITHUB_BASE_REF`, so `resolve_base` falls back to `origin/main` (486 commits behind). The commit stage's `change` check then fails with "one change per branch" (43 archive dirs), and under bash `-e` the full suite never starts, leaving the branch permanently red. Raised by all three reviewers. Evidence: at `origin/supabase-migration` 415cca6b, `env -u GITHUB_BASE_REF CI=1 GITHUB_EVENT_NAME=push scripts/check-change.sh --stage commit` -> `FAIL  change  one change per branch; found ['openspec/changes/archive/2026-09-30-infisical-secrets', ...]`, `SKIP risk-floor blocked: change failed`, exit=1. Resolved: a push to `supabase-migration` runs only `FULL_TESTS=1 scripts/check-change.sh --only commands,audit`, and a push to `main` keeps `--stage commit` (proposal What Changes, design D4 with the `github.event.before` alternative). New task 3.2 simulates the push run before merge. A local check shows a push env with `--only` runs non-change gates: `CI=1 GITHUB_EVENT_NAME=push scripts/check-change.sh --only guide-size,workflows` -> both PASS, rc=0.
- [x] [major] The proposal and design disagree on when selection applies. The proposal said "locally at the `hook` and `pr` stages", while D3 has no stage condition, and `--only` runs get `ctx.stage == "custom"`. Tasks 2.2/2.3 use `--only commands`. Raised by assumption tester and scope reviewer. Resolved: one rule, no stage condition (`--stage hook`, `--stage pr` and `--only commands` select alike). Stated in proposal What Changes and design D3 condition 2.
- [x] [major] The design's mitigation "the gate message shows the skip" doesn't hold locally. Pre-push and the Stop hook call the checker with `--quiet`, which prints failures only. Evidence: `.pre-commit-config.yaml` `entry: scripts/check-change.sh --stage hook --quiet`; `check_change.py` `if not args.quiet or status == "FAIL" or (status == "WARN" and name == "yaml")`. Resolved: D3 now prints the `commands` line under `--quiet` whenever it skipped DB tests. Pre-push already has `verbose: true`, so a passing push shows it. Task 2.2 adds a `--stage hook --quiet` check.
- [x] [major] The time saving isn't measured before approval. The Assumptions table still has the `TIMING` placeholder, and the 509s isn't split between pg/integration and typecheck/unit/audit. Raised by the scope reviewer. Evidence: design.md Assumptions last row; `find server/src -name '*.int.test.ts' | wc -l` -> 89; `*.pg.test.ts` -> 12 in server, 3 in storage. Resolved: measured locally and recorded in the design.md Assumptions table. The pg and integration projects took 597s against 96s for server/storage unit, web and typecheck combined, so skipping them removes most of the test time on a skipped PR. CI hardware differs, and task 3.3 records the CI before/after.

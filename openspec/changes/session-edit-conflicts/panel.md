# Panel: session-edit-conflicts
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-06

- [x] [critical] The inline base fell back to the cached version (`inlineDrafts.baseVersion(id) ?? event.version`), so (a) focus-without-typing after another person's change, (b) a save queued behind a Keep-theirs, and (c) a row remounted while the prompt was open could each overwrite the other person silently (failure and abuse; assumption tester found (b) independently). Resolved: design D3 now bases every save on a feed-owned seed (the server row the controls were filled from) that survives unmount, with no cache fallback, and compares controls against the seed so an untyped visit sends nothing; D5 settles queued saves on the row without sending after Keep theirs or dismiss, and Keep theirs bumps a row epoch so every mounted copy refills; spec scenarios "Leaving a row without typing sends nothing" and "A queued save after Keep theirs is not sent"; tests in tasks 5.3 and 6.1.
- [x] [critical] `TopicsRow.startEdit` re-snapshots the row on every focus, so after a dismissed conflict a refocus replaced the operator's text with theirs and the next blur sent nothing (failure and abuse). Resolved: D3 adds the `prev ??` guard and stamps the seed only when `edit` is created; task 7.2 tests dismiss, refocus, blur, dialog.
- [x] [major] Prompts relied on unmount at session switch, but the feeds stay mounted across sessions, so a prompt and its overwrite could run against the next session (failure and abuse). Resolved: D5 `useVersionedSave(sessionId)` dismisses the open and queued prompts and drops queued saves when the session changes; `send` captures the session at `run`; the spec and decision 3 say drafts then follow the existing session-change clear; task 5.3 test.
- [x] [major] The per-row chain released before the caller rebased, so a queued save could read the old base and conflict with the operator's own write; topics passed a value instead of a thunk (failure and abuse; scope and simplicity found the same hole). Resolved: D4 runs the outcome handlers (`onSaved` etc.) inside the row's chain before the next save reads its base; topics pass a thunk over the seed store; timing tests in 5.3, 6.1 and 7.1.
- [x] [major] Word bases were undefined and `TranscribeRow`'s frozen `edit` snapshot let a seed track the cache (silent revert) or stay at mount (false conflict) (failure and abuse; assumption tester). Resolved: D3/D9 stamp the word seed when `edit` is created and compare against it.
- [x] [major] After a one-field word Overwrite or save, sibling controls kept pre-conflict text that a later blur would send with the newer base (assumption tester). Resolved: D4's three-way rebase refills controls that still show the old seed's text from the response row; task 7.1 test.
- [x] [major] Word Keep theirs cleared sibling draft fields the dialog never showed (failure and abuse). Resolved: D5 lists every field holding operator text in the row, so Keep theirs discards only what was shown; spec bullet and task 7.1 test.
- [x] [major] On the event feed, `saveInline` compared stale focused controls against the live row, so an untyped visit produced a conflict (or today, a silent revert) (assumption tester). Resolved: D3 compares against the seed; spec scenario "Leaving a row without typing sends nothing".
- [x] [major] Two reseed mechanisms for the event row (the outcome reseed and the "adopt the refetched row while focused" fix) (scope and simplicity). Resolved: the adoption fix is dropped from the design, spec and proposal; the seed rebase on `saved` covers it, and the focus guard is unchanged.
- [x] [major] Rewriting `TopicsRow.test.tsx` PATCH-body cases fell outside the allowed test-change categories, so the plan's own stop rule would fire (assumption tester). Resolved: D10 category 5 added and task 7.2 reworded.
- [ ] [major] Task 8.4 skipped `scripts/check-change.sh` citing a standing owner instruction that the record does not show for this change; AGENTS.md phase 8 and CLAUDE.md require it (scope and simplicity). Changed: 8.4 now runs `check-change.sh --stage hook` and `--stage pr`; open for the owner to keep or waive at approval.

## Re-panel (2026-10-06, failure and abuse, fresh reviewer, on the revised design)

- [x] [critical] The event row's seed followed `current` through the existing unfocused resync while a draft survived (a dismissed conflict, or a failed save followed by another person's change), so the next save overwrote the other person silently. Resolved: D3's rule is now that the seed follows the server only while the row's controls do (no draft, no batch values, no `edit`, no save in flight or queued, and for event inline rows not focused); otherwise the resync may refill untouched controls but leaves the seed alone. The spec's "When the seed changes" bullet is restated; scenario "A dismissed event edit asks again"; task 6.1 tests.
- [x] [major] A 409 for a request in flight at a session switch still prompted, and could overwrite, after the switch. Resolved: D5 checks a session generation after every await in the loop and resolves `dismissed` with no prompt or send; spec bullet; task 5.3 test.
- [x] [major] Batch and delete bases came from a seed that did not follow the server outside inline mode, which produced false conflicts. Resolved: the feed applies the follow rule on every list change in every mode, so batch and delete bases are the row on screen; spec "Batch and delete" bullets; task 6.2 test.
- [x] [major] The modified draft-clear sentence listed the clears exhaustively and contradicted the existing spent, batch-entry and session-change clears. Resolved: it now names those clears and adds Keep theirs as the only new one.

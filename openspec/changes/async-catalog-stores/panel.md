# Panel: async-catalog-stores
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-01

Probes are in the session scratchpad (`panel3d-assume/`, `panel3d-failure/`), run with `node_modules/.bin/tsx`.

- [x] [major] The artifacts reasoned as if 3d made awaits into real yields. The 3c adapter only ever yields microtasks, so in production a request's catalog awaits finish before another request's I/O callback runs. The ADR hazards stay latent until slice 4, and only in-process tests (same tick, or a held transaction) interleave. Evidence: `interleave.mts` -> two `setImmediate` macrotasks: 1 winner; 200 concurrent real HTTP requests: 0 interleavings; same tick: 2 winners; held transaction across a timer: 2 winners. Resolved: added as design A7; the proposal has a "Concurrency, honestly stated" section; ADR task 3.1 says the hazards stay latent through 3d; tasks.md describes the concurrency tests as slice 4 guards.
- [x] [major] The scope reviewer said the opposite: that 3d makes hazards 5 and 8-14 live, and that "No HTTP change" holds only for sequential traffic. Evidence: ADR 0021 "harmless while storage is synchronous and real once it does I/O". Resolved: A7's probe shows production interleaving is unchanged by 3d, so the claim stands for production. The ADR preface is reworded so the hazards' timing is explicit (latent through 3d, live with slice 4's I/O), and the proposal states it.
- [x] [major] Store-internal read-then-write sequences interleave once awaited (`authEnsurePrefsRow`, `adminCreateStudio`, `adminDeleteStudio`'s show count, `authSeedPrefsFromGlobals`, the `getStudioSettingsBlob` self-heal), turning a validation 400 or a no-op into a raw 500. Evidence: `ensure.mts` -> `ensurePrefs x2: [ 'ok', 'UNIQUE constraint failed: user_prefs.user_id' ]`, `createStudio x2: [ 'ok', 'UNIQUE constraint failed: studio_definitions.id' ]`. (Assumption tester; the scope reviewer flagged `adminDeleteStudio` separately as hazard 13.) Resolved: all five run inside a `withDb` transaction (design D2), with a spec scenario "Concurrent first reads do not collide" and test 1.4 "interleaved create-if-missing". Latent in production (A7), but the code is being rewritten anyway, and slice 4 needs it.
- [x] [major] The claim that slice 4 can swap engines "without touching … a test" was false while seeds wrote raw SQL through a synchronous better-sqlite3 connection, because postgres.js is async-only. Evidence: design D7 as drafted; 606 seed call sites (`grep -rnE "\bseed(Studio|User|Show|Session|edSession)\("`). Resolved: the owner chose async seeds (2026-10-01), reversing the slice 3 decision. The seeds call the real store methods and every site awaits (D7). That also removes the second connection, its `SQLITE_BUSY` hang (`seedblock.mts` -> `seed failed after 1003 ms: SQLITE_BUSY`), the foreign-key gap and SQL drift.
- [x] [major] The scenario "No async costume" said stores never await "an async wrapper around a synchronous adapter", which is exactly what `AsyncSqliteCatalogDb` is. Evidence: `asyncCatalogStore.ts` `all() { return this.root(() => this.db.prepare(sql).all(...)) }`. Resolved: reworded to "never wrap a synchronous call in `async` themselves", and scoped "no synchronous catalog adapter" to production code.
- [x] [major] A missed `await` on a test read passes vacuously (`const user = catalogFor().auth.authGetUserByGoogleSub(…); expect(user).not.toBeNull()`), and nothing machine-checks tests. There are also 12 direct `env.ports.catalog` reads in tests that the plan didn't count. Evidence: `auth.int.test.ts:80-81, 113, 370, 389`; the hygiene filter excludes test files. Resolved: a new hygiene rule flags `expect(promise)` without `.resolves`/`.rejects` in test files (D6, spec scenario, test 1.1), and D7 and task 2.5 count the 12 direct reads.
- [x] [major] The cross-removal last-admin test was scheduling-dependent: the loser can get `404` from `requireTeamAdmin` or the member check outside the transaction. Evidence: `teams.ts:294-305` (hazards 8 and 12). Resolved: the test has both admins call `/leave` concurrently, where the loser can only get `409`. It is labelled characterization (green before), and the architecture spec no longer restates the team-management rule (D9).
- [x] [major] D5's "the restart policy brings it back" was false in dev: `tsx watch` keeps running after the child exits. Evidence: `timeout 4 tsx watch exiter.ts` -> `exit status: 124 (still running at timeout)`; dev `CMD ["npm","run","dev"]`. Resolved: the spec scopes the restart to supervised deployments (production and stage), and D5 documents the dev behaviour (`make dev-restart`).
- [x] [major] D7 said the catalog package tests would build stores over the adapter. None uses a database, and that would add a `catalog -> storage` edge the boundary test forbids. Evidence: `catalog.test.ts` stub `CatalogDb`; `packageBoundaries.repo.test.ts:279-280`. Resolved: D7 corrected; the package tests stay pure (A10).
- [x] [major] Docs that 3d makes stale were missing: the README architecture tree, the storage barrel comment, and the `config.ts` comment. Evidence: `README.md:642-643`; `packages/storage/src/index.ts:5-6`; `config.ts:45-46`. Resolved: added to tasks 2.2, 2.4 and 3.1.
- [x] [minor] There are 6 store transactions and 8 bodies in total, not 5 and 7. Evidence: `grep -n "\.tx(" packages/catalog/src/*.ts`. Resolved: counts corrected throughout.
- [x] [minor] `SessionIndexStore.withDb` passed root-bound dependencies through. Evidence: design D3 as drafted; `compose.mts` root use inside a body -> `CatalogTxMisuseError`. Resolved: it rebinds `studios` and `shows` with their own `withDb` (D3).
- [x] [minor] The sign-up rollback test duplicated an existing one. Evidence: `auth.int.test.ts:472-504` `'atomicity: a throw mid-materialization…'` via `vi.spyOn(AuthStore.prototype, …)`. Resolved: task 1.4 converts it and adds the missing assertions.
- [x] [minor] An adapter `close()` was cosmetic, SQLite-only and dev-only, and the end protocol would still hit a raw `TypeError` at `COMMIT`. Evidence: `main.ts:114-135`; the 3c `transaction()` end path. Resolved: deferred to slice 4's adapter (D5); the spec paragraph is removed.
- [x] [minor] `onBroken` wired inside `createBindings` would `SIGTERM` the vitest worker, because the harness uses `createBindings`. A graceful exit 0 also hides the fault. Evidence: `harness.ts:11,48`; `main.ts` `process.exit(0)`. Resolved: `onBroken` is a `createBindings` option passed only by `main.ts`, deferred with `setImmediate`, unable to throw; it logs at error level and sets `exitCode = 1` (D5, test 1.5).
- [x] [minor] Held-transaction tests have an `AsyncLocalStorage` trap: calls started inside the held body inherit its state and are rejected as misuse, instead of queueing. Evidence: `guardRoot()`. Resolved: D7 and the tasks preface require starting concurrent calls from the test's own context.
- [x] [minor] The facade's new `tx` contradicts "stores are the sole API surface", and `Object.keys(catalog)` is asserted to be exactly the stores. Evidence: `core-ports-architecture/spec.md:95-99`; `catalog.test.ts:18-24`. Resolved: that requirement is MODIFIED to allow `init` and `tx`, and the handle is a private `#db` field.
- [x] [minor] The async-callback scenario still said "server production code". Evidence: delta scenario text. Resolved: it says "server or catalog-package".
- [x] [minor] The widened hygiene filter could silently scan zero catalog files if module resolution changed. Evidence: `promiseHygiene.repo.test.ts:288-297` (the only guard is `files.length > 30`). Resolved: the test asserts that a `packages/catalog/src` file is scanned (D6, test 1.1).
- [x] [minor] D8's counting method was unstated, and the facade count was low (58 + 6, not about 50). Evidence: probe counts. Resolved: D8 states numstat added plus deleted, with an itemised table; the estimate is 650-750.
- [x] [minor] Test call sites in synchronous contexts need conversion, not just `await`: the `membersOf` lambda and the 3 `cat.init()` sites. Evidence: `bootstrapMemberships.int.test.ts:34`; `apiResponseFixtures:89`, `teams.int:19`, `catalog.int:11`. Resolved: D7 and task 2.5.
- [x] [minor] The `events.ts` comment ("safe while the catalog is synchronous") becomes literally false. Evidence: `events.ts:623-636`. Resolved: task 2.4 rewrites it (still safe because the adapter yields only microtasks; slice 4 hazard 4).
- [x] [minor] A registry refresh inside `catalog.tx` updates only the tx catalog's copy. Evidence: `studioRegistry.ts:209-228`. Resolved: recorded as a constraint in D3; no body does this.
- [x] [minor] Out of scope but worth recording: `/auth/google/start` writes one KV row per hit, purged only at boot; and hazard 15's "catch the conflict and retry" can't run inside a transaction under the any-error-fails rule. Evidence: `startupPurge.ts`; the 3c contract. Resolved: both are added to ADR 0021 (task 3.1).
- [x] [minor] The old SQLite-adapter phrase "a key/value call never joins a catalog transaction" was dropped. Evidence: delta text. Resolved: restored in the MODIFIED requirement.
- [x] [minor] Suggested a warning when a transaction holds the lock for more than about 100 ms. Evidence: the 3c deadline is 10 s. Resolved: not adopted. No body awaits non-catalog work (A3), and slice 4's pool changes the meaning; the deadline already bounds it.

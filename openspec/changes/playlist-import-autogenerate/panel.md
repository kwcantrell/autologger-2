# Panel: playlist-import-autogenerate
Tier: 2 · Reviewers: assumption tester (2026-11-12); failure and abuse, scope and simplicity to follow · Date: 2026-11-12

- [x] [major] The up-front `blocked` check does nothing for the common first import into an empty show (and for a show over 1000 sessions): the preview resolves the scope first and answers `400 No sessions to process.` / `A batch job can process at most 1000 sessions.` before it computes `blocked`, so the box never warns before hours of importing. Evidence: `grep -n "if (r.sessions.length === 0)\|blocked: await blockedFor" server/src/autogenerate/service.ts` -> `141:` (400 return) before `165: blocked: await blockedFor(p, steps)`. Resolved: when the preview does not answer `200`, the modal derives the verdict from the existing `GET /api/me/providers` (already read by Settings → Advanced through `useProviders`, fixture-checked) in the start route's order, mirroring `resolveLlmRoute` (no row; keyless `claude-cli` only while `claude_cli_allowed`) and `run_features_allowed`; no contract change. Residuals stated: an undecryptable saved key, and the dev-only `PROVIDER_DEV_MODE` Deepgram fallback (a false block on dev stacks); the confirm says providers are checked again when the import ends (spec "Up-front check" steps 1-3 and scenario "An empty show is still checked before importing"; design D6, A13-A16; tasks 1.1 `blockedFromProviders`, 4.1, 5.1).
- [x] [major] The ADDED requirement disables Start Import in cases where the in-flight `youtube-playlist-import` MODIFIED "Batch Import modal layout and actions" says it SHALL be enabled ("enabled when a show is selected, no run is in progress, and at least one of these is ready"), so the two specs contradict. Evidence: the enable rule and scenario "A playlist alone enables Start Import" in that requirement versus this delta's "Start Import SHALL also be disabled while the checkbox is ticked and no step is ticked … or more than 1000". Resolved: the delta now MODIFIES "Batch Import modal layout and actions", restating the whole requirement as synced on main by the archive (PR #144) with the narrowed enable rule (step ticked, at most 1000 checked, no blocked verdict while the box is ticked), the group's place, the confirm before the run and the autogenerate start after the log part; "A playlist alone enables Start Import" kept (box unticked) plus new scenario "Autogenerate options can disable Start Import"; the ADDED requirement points to it instead of restating the rule.
- [x] [major] Tier 1 understates the risk: one confirm commits unattended paid spend on the user's providers (up to 1000 × 4 runs) that starts hours later with no second prompt, and the change fixes an ordering guarantee (start only after every part, design D3) and a no-retry rule for a start with an unknown outcome (design D5); risk-tier says pick the higher tier when unsure. Evidence: `.claude/skills/risk-tier/SKILL.md` tier 2 list ("Concurrency, locking, retries or ordering guarantees"; "When unsure between two tiers, pick the higher one"). Resolved: raised to Tier 2 by the orchestrator and owner (proposal Tier and Tier reason); the remaining two tier-2 reviewers run after these fixes; tasks add the consistency read (5.3).
- [x] [major] "Qualifying sessions" counts a retry into this import's own unfinished session from an earlier run, which owner decision 1 ("created AND attached audio to") does not clearly allow; the design left it as open question Q1 although it changes the spec. Evidence: design D2 and the former Open question Q1. Resolved: owner decided 2026-11-12 to include such a session; recorded as proposal owner decision 5, Q1 closed in design (D2, Open Questions), the spec sentence names it and a scenario "A retried session from an earlier run qualifies" plus task 4.1 test it.

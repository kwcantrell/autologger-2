# Panel: retire-server-data-rule
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-09-30

- [x] [critical] The Why premise "prod runs in containers from the `autologger-data` named volume" is unsupported. The archived containerize-split-images design says the live server runs on another machine and `server/data` is the finished pre-seed copy for cutover. Cutover task 8.3 is recorded as not completed. If cutover is still pending, agent edits to `server/data` would be seeded into prod. Evidence: `docker volume ls | grep -i autologger` -> only `autologger-dev_*`; `openspec/changes/archive/2026-09-29-containerize-split-images/design.md:433-434` -> "The live server runs on another machine. `server/data` on this host is a finished pre-seed copy"; tasks.md:172 -> "left unticked at archive ... not a record of completion". Resolved: the owner confirmed (2026-09-30) that the cutover is done, prod runs from its container volume, and `server/data` will never seed prod again. The proposal's Why and the design's Assumptions are corrected
- [x] [major] "`server/data` is a backup" rests on the owner's word, and nothing says whether it is the only copy. It is gitignored and nothing else guards it, so an agent edit, `rm`, or a boot-time migration against it can't be undone. Suggested: keep a snapshot outside the repo and record which copy is authoritative. Evidence: `git check-ignore -v server/data` -> `.gitignore:11:data/`; design.md Assumptions -> "The agent didn't open the directory to check it.". Resolved: the owner confirmed (2026-09-30) that the authoritative backup is kept elsewhere and `server/data` is a disposable copy, recorded in the proposal's Decisions
- [x] [major] Removing the rule drops the only warning that the default `DATA_DIR` is `server/data`. A host `npm run dev`/`start` or test without `DATA_DIR` opens the backup read-write and may migrate it, and the README quick start still documents that path. Evidence: `server/src/node/config.ts:21` -> `const dataDir = procEnv.DATA_DIR || './data';`; `README.md:918-922` -> "cp server/.env.example server/.env ... npm run dev". Resolved: the owner allows dev use of the disposable copy (2026-09-30), so no warning is kept. The risk is recorded in design.md Risks ('Default `DATA_DIR`'). Owner to confirm at approval
- [x] [major] The design says "Destructive operations still need confirmation under the standing agent rules", but no such rule or check exists for file edits or `rm`. Evidence: `.claude/settings.json` deny = curl/wget/force-push/--no-verify, ask = `git push` only; `grep -rn -i destructive AGENTS.md docs/security.md` -> tier table and ASI row only. Resolved: the claim is removed from design.md. Risks now say nothing mechanical guards edits, and the owner accepts that for a disposable copy
- [x] [major] Transcripts and session titles become a new prompt-injection source (ASI01) that the threat model doesn't list. Evidence: `docs/security.md:10` -> ASI01 sources list issue/PR/web/README/fixture only. Resolved: recorded as residual risk in design.md and ADR 0022 (proposal What Changes, task 1.3). `docs/security.md` is not changed
- [x] [major] The PII exposure path is not recorded as residual risk. Data an agent reads lands in tool output, the provider's context, subagent reports, and potentially fixtures or docs. `.gitignore` covers only the directory itself. Evidence: `git check-ignore -v server/data/x.db` -> `.gitignore:11:data/`. Resolved: recorded as residual risk in design.md and ADR 0022 (proposal What Changes, task 1.3)
- [x] [major] "Non-container workflow retired" contradicts AGENTS.md's loopback rule, which stays and still recommends host `npm run build && npm run start`. Evidence: `AGENTS.md:95-96`. Resolved: the proposal's Non-goals say the loopback rule stays as written and that retiring the host workflow is follow-up work

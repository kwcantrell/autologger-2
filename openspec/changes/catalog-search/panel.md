# Panel: catalog-search
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-12

- [x] [critical] The catalog roles have no `USAGE` on schema `extensions`, so after the migration every write to sessions, topics and events would fail with 42501, and search would be refused (assumption tester and scope reviewer). Evidence: `has_schema_privilege('catalog_user','extensions','usage')` -> `f`; as `catalog_user`, `update catalog.sessions set title=…` -> `42501 permission denied for schema extensions`. Resolved: design D2 grants `USAGE` on `extensions` to `catalog_user` and `catalog_system`; the catalog-database delta adds the requirement and the "Ordinary writes still succeed" scenario; task 2.1 tests it.
- [x] [critical] The new functions don't meet "Catalog functions are not executable by public". A `SECURITY DEFINER` `refresh_transcript_chunks` callable by `catalog_user` would let a user rebuild chunks of any team's session (scope reviewer). Evidence: `catalog-database/spec.md:164-166`; `catalogRoles.pg.test.ts:131-151`; `20261007000000_catalog_policies.sql:80-85`. Resolved: D2 revokes every new function from public and lists the exact grants (the refresh and trigger functions get none); delta requirement and scenario "New functions are not public"; task 2.1.
- [x] [critical] The existing requirement "Session content tables" ("every index SHALL lead with `session_id`", "with these changes only") conflicts with the new search columns and GIN indexes on topics and events (scope reviewer). Evidence: `catalog-database/spec.md:555-562`. Resolved: a MODIFIED "Session content tables" delta, copied in full, allows exactly these two columns and indexes, with the scenario "Search columns are the only additions".
- [x] [major] GIN and trigram indexes can't be used under RLS, because `@@` and the pg_trgm operators aren't leakproof (assumption tester). Evidence: as `catalog_user`, `Seq Scan … Filter: (… AND (search_tsv @@ …))`; as `catalog_system`, `Bitmap Index Scan`. Resolved: D5 makes search one `SECURITY DEFINER` function, `catalog.search`, which applies the access sets from the policy helpers in every branch; task 3.1 asserts a GIN index scan with `EXPLAIN`.
- [x] [major] The pg test template has no `extensions` schema, so `create extension … with schema extensions` would fail there (assumption tester). Evidence: `psql -d template1 … nspname in ('extensions')` -> no rows. Resolved: the migration starts with `create schema if not exists extensions` (D2, task 2.3).
- [x] [major] The 3 s timeout is per statement, not per search. Four statements could exceed the 10 s transaction deadline and surface as a 500 (`CatalogTxTimeoutError` isn't mapped), and the design claimed a read-only transaction that `CatalogDb` doesn't offer (assumption tester and failure reviewer). Evidence: `postgresCatalogStore.ts:168,405`; `app.ts:239-254`. Resolved: D7 makes search one statement (`select catalog.search(…)`) under one `SET LOCAL statement_timeout = '3s'`, maps both `57014` and `CatalogTxTimeoutError` to the 503 timeout response, and drops the read-only claim; tasks 3.2 and 4.2.
- [x] [major] Searches can fill the 5 shared catalog slots and stall other users; an aborted request doesn't stop the database work; react-query retries each failure once (failure reviewer and assumption tester). Evidence: `txSlots = 5` (`postgresCatalogStore.ts:403`); `IndexRoot.tsx:14` `retry: 1`. Resolved: D7 adds a process-wide cap of 2 concurrent searches, answering `503 Search is busy; try again.` after a 1 s wait, and `useSearch` sets `retry: false`. The spec gains "Concurrency" and the scenario "Searches can't starve the app", and the contract gains the busy 503; tasks 3.2, 4.2 and 5.2.
- [x] [major] Session ranking or `match` computed over notes could leak hidden notes to ungranted members through result order (failure reviewer). Resolved: D5 computes `match`, rank and snippet for shows outside `accessible_shows` from `search_meta` and trigram only; the spec adds "Notes SHALL NOT influence the ranking or the `match` value" and the scenario "Hidden notes don't affect ranking"; task 3.1.
- [x] [major] An accent-folded match can return a snippet without the hit, because `ts_headline` on raw text can't find `cafe` in "Café" (failure reviewer). Evidence: the probe returned `w1 w2 … w8`. Resolved: D2 replaces `search_norm` in the vectors with the text-search configuration `catalog.search_english` (unaccent plus english_stem), so the headline highlights the raw text. Probe: `[Café] Noir, they were Divorced` (design A21). Scenario "An accented hit is highlighted"; task 3.1.
- [x] [major] Chunk writes were blocked only by missing RLS policies: new tables get `arwd` by default, so an UPDATE affects 0 rows silently instead of failing, which contradicts the spec scenario (failure reviewer). Evidence: `pg_default_acl` -> `{catalog_user=arwd/postgres,…}`. Resolved: D4 adds `revoke insert, update, delete on catalog.session_transcript_chunks from catalog_user`, and the spec now expects `42501`; task 2.2.
- [x] [major] Chunk sync relied implicitly on `sessionTx`'s session row lock; a writer outside it could race the delete-and-reinsert (23505 or a stale chunk) (failure reviewer). Evidence: `postgresCatalogStore.ts:170`. Resolved: `refresh_transcript_chunks` takes a per-session advisory transaction lock before reading words (D4); the spec requires serialised rebuilds; the scenario "Concurrent edits in one block"; task 2.2.
- [x] [major] `?topic=` and `?event=` used `useTimelineSeek().jump`, which plays audio when a clip covers the target and does nothing until status resolves, contradicting "without starting playback" and risking a silently lost seek (assumption tester). Evidence: `useTimelineSeek.ts:96-100`. Resolved: D8 computes the target with the feed placement helpers and seeks through `jumpTimelineToSec` (never plays). It waits for status and the timeline, and doesn't seek while rolling. Routing delta scenarios "Rolling session is not moved" and "Seek to seconds"; task 5.7.
- [x] [major] The `ShortcutsDialog` edit had no spec delta (its list is fixed by web-session-console), and Cmd-K behaviour with another dialog open was unspecified (scope reviewer). Evidence: `web-session-console/spec.md:131-136`. Resolved: the dialog edit is dropped (non-goal; the button tooltip names the shortcut instead). The palette doesn't open while another modal dialog or sheet is open (spec, D9, task 5.5).
- [x] [major] Server-side event `sec` duplicated the web's placement rule without its gating, and nothing used it (scope reviewer). Resolved: `sec` is null for topics and events and set only for transcript chunks (D5, spec, contract); events are placed by the web (D8).
- [x] [major] A moment in the session that's already open (a same-id navigation, no remount) was neither specified nor tested (scope reviewer). Resolved: D8 watches the URL's search string. The routing delta adds "Already open" and the scenario "Moment in the session already open"; the catalog-search spec adds "A moment in the open session"; task 5.7.
- [x] [major] "Exactly as the top-bar switcher does" fails for a show in another studio: TopBar's show switch sends the current studio, which the server rejects with 400 (scope reviewer). Evidence: `TopBar.tsx:113-123`; `profile.ts:137`. Resolved: D9 extracts `useSwitchActive` (keeping the `confirmSwitch` guard); a show hit sends `{active_studio_id: hit.studio_id, active_show_id: hit.id}` in one PUT. Spec text, D10 category 3, task 5.4.
- [x] [major] D10 forbade unavoidable inventory edits: the policy count 37 → 38, and the per-table policy conditionals in `catalogSchema.pg.test.ts` (scope reviewer). Evidence: `catalogPolicies.pg.test.ts:602`; `catalogSchema.pg.test.ts:823-835`. Resolved: D10 category 1 names both and adds `catalogRoles.pg.test.ts`; task 2.5.

## Re-panel 2026-10-12
Scope: the panel resolutions (D2 config, D4 locks, D5 definer search function, D7 budget and cap). Reviewer: fresh failure-and-abuse plus assumption tester.

- [x] [major] `catalog.search`'s `search_path = pg_catalog, catalog` lets a caller's temp table shadow catalog tables inside the definer body, bypassing RLS for anyone who reaches SQL as `catalog_user`. Evidence: definer probe returned `before|005e2862-…`, then `after|FAKE-FROM-TEMP` after `create temp table sessions`; `has_database_privilege('catalog_user', current_database(), 'TEMP')` -> `t`. Resolved: D4 and D5 use `search_path = pg_catalog, pg_temp` with schema-qualified names, as the policy helpers do; task 3.1 adds a temp-table shadowing test (design A26).
- [x] [major] The trigram branches as written (`word_similarity(…) >= 0.4`) can't use the trigram GIN indexes, so the session title predicate seq-scans. Evidence: on 20k rows, `Seq Scan … Filter` against `Bitmap Index Scan … (t %> 'christna')` with the operator form. Resolved: D5 uses `LIKE` (with `%` and `_` escaped) or `OPERATOR(extensions.<%)`, with a function-level `SET pg_trgm.word_similarity_threshold = 0.4`. `word_similarity` is used only for ranking (design A27).
- [x] [major] Task 3.1's "EXPLAIN shows a GIN index scan" has no working method: EXPLAIN shows only `Result` for a plpgsql call, `auto_explain` can't be loaded, and template-sized data prefers seq scans. Resolved: task 3.1 seeds at least 5,000 rows and diffs `pg_stat_user_indexes.idx_scan` across a call (after `pg_stat_force_next_flush()`); task 6.2 EXPLAINs owner-run copies of the branch queries (design A28).

## Re-panel 2026-10-12 (D11 post-approval tuning)
Scope: design D11, the spec edits for the tuning, proposal "Tuning after the dev-stack check", tasks group 7. Reviewers: fresh failure-and-abuse plus assumption tester, and fresh scope and simplicity.

- [x] [major] D10 didn't allow the rewrites group 7 needs in tests this branch already committed: the stop-word cases expecting empty moments (`catalogSearchQuery.pg.test.ts:450-455`), the 0.4 threshold (`catalogSearch.pg.test.ts:281`), the 4-argument signature (`:135`), the strict contract and int tests, the fixture, and the flat-list `SearchRoute` tests (scope reviewer). Resolved: D10 category 4 names these files and the assertions that may change; tasks 7.1 and 7.2 cite it.
- [x] [major] A lone common word passed the 3-character guard and blew the 3 s budget: `the` took 4397 ms and `and the` 1247 ms on 250k chunks, because the GIN recheck recomputes the normaliser per row (both reviewers). Resolved: D11.2 requires at least 2 words and 6 characters, and reads at most 2,000 candidate rows per source (a `LIMIT` inside the candidate subquery); spec scenario "A lone common word is not a phrase"; task 7.1 tests the bound (design A31).
- [x] [major] The "exact phrase" was a substring match: `'the band then' like '%and the%'` -> `t` (both reviewers). Resolved: whole-word matching with space padding (`' '||norm||' ' LIKE '% '||phrase||' %'`); spec scenario "Phrase matches whole words only"; task 7.1 (design A32).
- [x] [major] Mapping the match back "by word position" was unsound: punctuation-only tokens vanish (`—`), unaccent can split a token (`3½kg` -> `3 1/2kg`), and stripping tabs before collapsing merged words (`tab\there` -> `tabhere`) (failure reviewer). Resolved: D11.2 folds each original whitespace token separately and keeps an index from folded word to original token; the normaliser turns whitespace into spaces before removing punctuation; new catalog-database scenario "Whitespace separates words before punctuation is removed"; task 7.1 tests `—` and `½`.
- [x] [major] "Show N more" could promise more than one expansion shows: totals go up to 1000, but expansion is capped at 25 (both reviewers). Resolved: N is `min(total, 25) − shown`; past 25 the group ends with "Showing 25 of <total> matches in this session" and a link to the session (D11.3, spec text and scenario "Expanding a very busy session", task 7.3).
- [x] [major] The `session_id` filter contradicted itself: "narrows every group" against empty studios, shows and sessions (scope reviewer). Resolved: the Filters bullet now says `session_id` returns that session's moments only and points to "One session".
- [x] [major] Dropping the 4-argument `catalog.search` would break a server not yet upgraded during a rollout or rollback (`42883` -> 500), and "grants are reapplied" didn't say revoke from public (failure reviewer). Resolved: `p_session text default null` keeps 4-argument calls resolving, and the migration runs an explicit `revoke all … from public` and `grant execute … to catalog_user` (D11.3, task 7.1, which tests a 4-argument call).
- [x] [major] Nothing checked that the new phrase indexes are used (scope reviewer). Resolved: task 7.1 extends the existing `idx_scan` test to the chunk phrase index and the `p_session` path.
- [x] [major] Task 7.1's "`%`/`_` matched literally" couldn't be met, because the normaliser strips both from the query and the text (failure reviewer). Resolved: reworded to "act as no wildcard" (D11.2, task 7.1).

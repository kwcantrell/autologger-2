# Panel: show-wiki
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-13

- [x] [critical] The `/wiki` shell routes contradict web-frontend-platform "Shell routing from the shared route definition", which lists exactly `/`, `/sessions/:id` and `/teams` (and already omits `/search`); the change has no delta for it. Evidence: openspec/specs/web-frontend-platform/spec.md:132-133. Resolved: added a MODIFIED delta that keeps the full text, lists `/search`, `/wiki` and `/wiki/:pageId`, and adds the scenario "Nested wiki path stays 404"; proposal Modified Capabilities updated; task 4.4 tests it.
- [x] [major] The link check can be bypassed. The server's `](cite:` regex misses forms that react-markdown renders as links: reference definitions, autolinks, angle-bracket destinations, titles, padding, escapes, entities and upper-case schemes. So the rule "a citation's session is in the page's show" is false (all three reviewers; scratch render with react-markdown@10.1.0 showed live `cite:` links for each form). Resolved: D4 now parses with `mdast-util-from-markdown` 2.0.2 (the parser react-markdown uses) and walks link and definition nodes; schemes are matched case-insensitively and must be valid in lower case; the renderer makes only grammar-valid `cite:`/`wiki:` clickable (D5); the spec scenario "Other link forms are checked too" and tests 3.1, 3.2 and 5.3 were added.
- [x] [major] Mapping a `23505` and then looking up the holder can't work inside `catalog.tx`, because the aborted transaction gives `25P02` and a 500. Also, duplicate aliases within one request collide with the page's own row. Evidence: packages/ports/src/catalogDb.ts:7-10. Resolved: D3 pre-checks every name with a `SELECT` before writing; aliases are deduplicated on `search_norm` and an alias equal to the page's own title is dropped (spec "Duplicate aliases in one request collapse"); a stray `23505` re-runs the whole transaction once; tests in 3.2.
- [x] [major] A merge can exceed the body or alias limits, or duplicate B's aliases, and end in a 500. Resolved: the merge spec deduplicates aliases against B's title and aliases, and answers `422` if the result would exceed 100,000 characters or 50 aliases (scenario "Merge that would overflow is refused"; contract 422 list; tests 3.2 and 4.2).
- [x] [major] Titles and aliases allow newlines and Markdown, and merge pastes A's title raw into B's body, so a title can inject links or instruction-shaped structure that `show-wiki-ai` would later feed to an LLM. Resolved: the schema refuses control characters in titles and aliases (scenario "A title can't carry Markdown lines"); merge escapes A's title in the heading; every write that sets a body, including merge's assembled body and split, re-runs link validation (D4); tests 3.2 and 4.1.
- [x] [major] `GET …/revisions` returns all revisions with no limit, and nothing bounds revision writes; adding pagination later would change the frozen contract. Resolved: `limit` (1–100, default 50) and a `before` cursor with `next_before` (scenario "Revisions page backwards"); an edit that changes nothing appends no revision (scenario "A no-op save adds nothing"); the history sheet has "Load older".
- [x] [major] Hidden sessions are not addressed for session pages or citations. Resolved: allowed deliberately and specified ("A hidden session MAY have a session page and MAY be cited"), because hiding a session must not make pages that cite it unsaveable, and no existence oracle arises when the caller can already access every session of the show (D4); test 3.2 covers a citation to a hidden session.
- [x] [major] D8 doesn't permit edits that the tasks require: `apiResponseFixtures.int.test.ts`, `types.conformance.test.ts`, `queryKeyFactories.repo.test.ts`, `TopBar.test.tsx` and `SessionWorkspace*.test.tsx`. Resolved: D8 adds category 5 (registry and fixture inventories gain wiki entries) and category 6 (shell controls gain wiki entry-point assertions only); tasks reference them, and the 1.1 grep covers them.
- [x] [major] A `kind` change to or from `session` would surface as an unmapped `23514` (500), and no 422 was specified. Resolved: the spec scenario "A kind can't become session" gives 422; D3 checks it before any write; the contract's 422 list and tests 3.2 and 4.2 updated.
- [x] [major] `aliases` for merged and deleted pages was undefined, since alias rows exist only for live pages. Resolved: a page that isn't live reports its newest revision's aliases, and restore rebuilds the alias rows from them (spec, contract and D1); tests 3.2 and 4.2.
- [x] [major] Some frozen API surface can be cut: the revision-restore endpoint, the `q` list parameter, and optionally deleted/restore. Resolved: cut `POST …/revisions/:rev/restore` (restoring is a `PUT` with `restored_from`) and `q` (the client filters the full list); kept soft delete and restore, which are in the approved plan (D5 non-goals list nothing about them) and keep deletes reversible.
- [x] [major] The session-page `security definer` trigger is heavier than needed for a check that only ever fires on a bug. Resolved: replaced by a composite foreign key `(session_id, show_id)` that references a new `unique (id, show_id)` on `catalog.sessions`; there is no new function; the catalog-database delta, migration plan and tasks 2.1 and 2.2 were updated.
- [x] [major] Task 5.7 named no test file and targeted a workspace header that doesn't exist; the TopBar link had no test and risked the one-line rule at 390px. Resolved: the button sits at the end of the feed-tab row (D7), tested in `SessionWorkspace.wikiButton.test.tsx`; the TopBar link is icon-only below `md`, with a `TopBar.test.tsx` assertion and a 390px check in 5.8.
- [x] [major] RLS lets a `wiki_aliases` row (and `merged_into`) carry another accessible show's `show_id`, which leaks text across shows and blocks names there. Evidence: a rolled-back probe as `catalog_user` gave `INSERT 0 1`, `MISMATCH|t`. Resolved: `unique (id, show_id)` on `wiki_pages`, with composite FKs `(page_id, show_id)` and `(merged_into, show_id)`; scenario "Alias in the wrong show"; tests 2.1.
- [x] [major] `*_by_name` read through `catalog.users` RLS (self plus co-members) would lose or blank the names of people who left the team. Evidence: the `users_user_select` policy. Resolved: names are snapshotted at write time (`created_by_name`, `updated_by_name`, `author_name`); spec "Names"; tests 3.2.

# Panel: require-login
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-02

## Failure and abuse

- [x] [critical] The login gate is bypassed by a percent-encoded path, live on stage today and very likely on prod (same code on `main`). `authContext` decides on the raw `new URL(c.req.url).pathname` while Hono routes on the decoded path, so `/%61pi/...` reaches `/api/...` handlers with no login check; `docker/Caddyfile` forwards `%61pi` to the api by design. After this change the `/api/companion/*` routes (presence, log, transport, command POSTs) would stay open, since none checks `user`/`apiTokenAuth`. Evidence: `curl 127.0.0.1:8788/api/sessions` -> 401; `curl 127.0.0.1:8788/%61pi/sessions` -> 200 `{"active":[],"archived":[]}`; `/%61pi/companion/state` (no token) -> 200 with `last_command`; `grep -n pathname server/src/middleware/auth.ts` -> `30: const path = new URL(c.req.url).pathname;` (same on `main`). Resolved: fixed in the separate hotfix `gate-decoded-path` (PR #32 into `main`, PR #33 into `supabase-migration`; owner-approved freeze exception); the gate now decides on `c.req.path`. Prod was not deployed, so nothing was exposed. This change adds a repo test against regressions (D13) and builds on the fix (A12).
- [x] [major] `GET /api/studio` (`profile.ts:24-31`) is missing from D3's `requireUser` list; with D5's non-null signature a principal-less request would 500 instead of 401. Evidence: `grep -rn "getEffectiveStudioForUser(" server/src` -> `shows.ts:26, profile.ts:26, sessions.ts:116, sessions.ts:156`. Resolved: D3 lists `GET /api/studio`.
- [x] [major] The README endpoint table can't drive the 401 table test reliably (alternation rows, no methods); derive the list from Hono's registered routes and fail on any `/api` route with neither a 401 expectation nor a named exemption. Evidence: `sed -n 805,832p README.md` -> `| /api/companion/presence\|state\|log\|transport\|command\|categories\|commands/* |`; registered-route grep -> 62-78 distinct paths. Resolved: D7 and task 2.1 iterate `app.routes` with a named exemption list; a new route without an exemption fails.
- [x] [major] D7's default user in every studio changes what team and admin suites test (role, member counts, `/api/admin/users` list); pin its role and keep it out of team/admin suites. Evidence: `grep -n toHaveLength server/src/routers/teams.int.test.ts` -> `510: expect(adminView.members).toHaveLength(2);`; `grep -rln seedStudio --include=*.int.test.ts server/src | wc -l` -> 22. Resolved: (owner, narrowed default member) role `member`, built-in studios and `seededSession()` studios only, no auto-membership in `seedStudio`; team and admin suites use `anonApp` or explicit cookies.
- [x] [minor] "Blank" differs between the boot guard (`!env[k]`, no trim), `compose-run` (no trim) and `oauthConfigured` (trims, and also requires `PUBLIC_BASE_URL`). Evidence: `sed -n 30,45p server/src/env.ts` -> `.trim()` accessors; `grep -n "missing = " server/src/bootGuard.ts` -> `!env[k]`. Resolved: D1 trims and also requires `PUBLIC_BASE_URL`, the same rule as `oauthConfigured`; `compose-run` trims; whitespace cases are in 2.1.
- [x] [minor] Dev `API_TOKEN` is an owner step that nothing enforces; an empty token just 401s the Companion. Evidence: `grep -n "expected = " server/src/auth/identity.ts` -> `if (!expected) return false;`. Resolved: D10, the docs and 6.3 name the expected 401 without it.
- [x] [minor] Dev's bind-mounted `tsx watch` app will refuse to boot as soon as task 2.2 lands (it still has `REQUIRE_LOGIN=0` and no Google client); tasks should say dev is down from 2.2 until 6.2/6.3. Evidence: `docker exec autologger-dev-app printenv REQUIRE_LOGIN` -> `0`. Resolved: tasks.md header and design Risks say dev is down from 2.2 until 6.2/6.3.
- [x] [minor] Cutover/rollback: the new image with `main`'s compose (`REQUIRE_LOGIN: "1"`) crash-loops (fail closed); the old image with the new compose is safe (unset = required). Record both directions in the ADR cutover note. Evidence: `grep -n REQUIRE_LOGIN compose.yaml` -> `98`; `git show main:server/src/env.ts | grep -A4 requireLoginEnabled` -> `if (!v) return true;`. Resolved: both directions are in design Risks and task 5.2 (ADR cutover notes).
- [x] [minor] `teams.ts` already has a module-local `requireUser`; reuse one. Evidence: `sed -n 54,58p server/src/routers/teams.ts`. Resolved: D3 moves it to `_helpers.ts` and shares it.

## Scope and simplicity

- [x] [major] D3's `requireUser`/`requireSession` 401 contradicts the retained `core-ports-architecture` rule "The login-required check SHALL NOT be duplicated between middleware and per-route helpers"; amend the requirement or make the guard an internal assertion. Evidence: `sed -n 3,19p openspec/changes/require-login/specs/core-ports-architecture/spec.md`. Resolved: D3 makes a missing principal an internal error (500), not a 401; the core-ports delta adds that helpers MAY assert a principal.
- [x] [major] Over budget; split suggested: 5b-1 require login (gate, boot, harness, anonymous branches, web, compose), 5b-2 delete the now-unreachable open-network 503s (env exports, six routers, main.ts, five capability deltas). Evidence: measured about 380 non-test lines before the fixture; `size_budget: 400`. Declined by human: the owner chose one PR with `size-override`.
- [x] [major] D11's retitle-in-place leaves eight durable scenarios whose titles contradict their bodies; REMOVED + ADDED under a new name validates and is cleaner for small requirements. Evidence: scratch copy -> `REMOVED "Configuration-gated generation"` + `ADDED "Topic generation is configuration-gated"` -> `Change 'require-login' is valid`. Resolved: D11; small requirements use REMOVED + ADDED under accurate names (spec deltas reworked).
- [x] [minor] Three layers guard `REQUIRE_LOGIN` (boot refusal, check-envs absence, custom-env line); the check-envs absence check is redundant given the boot refusal and A3. Evidence: `grep -c REQUIRE_LOGIN docker/secrets-env.yaml` -> 0. Resolved: D9 drops the check-envs absence check.

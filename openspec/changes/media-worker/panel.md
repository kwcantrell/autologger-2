# Panel: media-worker
Tier: 2 · Reviewers: browser crash-safety (assumption tester), security and infrastructure (failure and abuse), merge data integrity (failure and abuse, scope and simplicity) · Date: 2026-10-11

Reviewers report only critical and major findings (ADR 0024). Each item names the design decision
that resolves it; the owner's answers of the same day are in proposal.md "Owner answers after the
panel".

## A. Browser crash-safety

- [x] [critical] Multi-tab recovery double-uploads: tab B's scan recovers a chunk tab A is still recording or uploading, and both post it. Evidence: design D10 (first draft) scanned storage on every page load with no ownership. Resolved: Web Locks, one per take held by the recorder and one per chunk held by the uploader; the scan skips any chunk whose chunk or take lock is held, with a 30 s heartbeat lease as the fallback where `navigator.locks` is missing (D10; live-recording-chunks "Finished chunks are persisted…", scenario "A second tab does not recover a live take"; tasks A.2, A.3, 0.3).
- [x] [major] A chunk the server accepted just before the crash (before `remove()`) is re-uploaded on recovery. Resolved: recovered chunks start `ambiguous` (segments-list check first) and the server's segment POST is idempotent per `(session, recording_ordinal, started_at_utc)`, seams of merged segments included (D10, D18; api-contract-freeze "Segment upload is idempotent per recording window"; tasks B.3, A.3).
- [x] [major] Shared-machine privacy: another user's unsent audio would be listed and uploadable. Resolved: the manifest carries `userId`, storage is per-user (`autologger-chunks/<userId>/`), the scan lists only the signed-in user's chunks, sign-out warns on unsent chunks and then wipes that user's directory (D10; scenario "Another user's chunks stay private"; tasks A.1, A.6).
- [x] [major] A new recording can reuse a recovered ordinal while the scan is still running. Resolved: the Record control is disabled until the recovery scan completes, then `deriveNextOrdinal` counts the recovered ordinals (D10; scenario "Record waits for the scan"; task A.5).
- [x] [major] Import resume keyed by `sessionStorage` and a whole-file `ArrayBuffer` hash: a new tab cannot resume, and a 1.4 GB file cannot be hashed in one buffer. Resolved: `upload_id` remembered in IndexedDB by file-group identity; per-part sha256 (WebCrypto over each ≤ 32 MiB slice) declared at create, checked by the server on every PUT, and the whole-file check rebuilt server-side by re-hashing the staged parts (D12; batch-audio-import "Large imports upload in parts", api-contract-freeze upload family; tasks D.3, B.4, S.4, S.6).
- [x] [major] Track ended (Bluetooth or device change, permission revocation, sleep) is the likeliest real loss and still ends the take. Resolved: D19 re-acquires the microphone (previous device, then default, on the chunk backoff for 60 s) and continues the same take with the next chunk index; finalize only on failure; `devicechange` with a live track only logs (live-recording-chunks "A lost microphone is re-acquired"; tasks A.4, A.5; root-cause path 6 now closed).
- [x] [minor] Grouped minors. Resolved: `requestData()` on `pagehide` is best effort, so the guarantee reads "at most one slice unpersisted" (D11, spec text); a live chunk answering `413` is re-sent through the parts upload in segment mode instead of parking (D11, D12 segment mode; scenario "An oversize chunk goes through parts"); a recovered partial chunk's window comes from its measured bytes, not the manifest (D10; scenario "A partial chunk's window comes from its bytes"); Safari's 7-day eviction and `persist()` heuristics are stated in the spec (D10).

## B. Security and infrastructure

- [x] [critical] The API cannot safely adopt worker files: a rename keeps a worker-owned inode under `audio/`, and a TOCTOU symlink swap between check and rename reaches any blob. Resolved: the API opens the result `O_RDONLY | O_NOFOLLOW`, `fstat`s the handle (regular file, size cap, worker uid), copies into its own `.tmp/put-*`, fsyncs and renames; it never renames the worker's inode; spike 0.1 proves the sequence and the symlink refusal (D3; media-processing "The API applies worker results", scenario "A swapped symlink cannot reach the audio directory"; tasks 0.1, S.6, B.5).
- [x] [critical] The worker's `UPDATE` grant on `media_jobs` is too broad (it could rewrite any job, any column, any status). Resolved: column-level `GRANT UPDATE` on eight columns, a `BEFORE UPDATE` guard trigger allowing only `queued → running` (lease free or expired) and `running → queued | done | failed` by the lease holder, `CHECK (octet_length(result_json) <= 262144)`, and the apply step trashes blobs named by re-read rows, never by the result (D2, D7; catalog-database role requirement; tasks S.2, S.3, B.5).
- [x] [major] ffmpeg demuxers can open other files (HLS playlists, ffconcat, external references). Resolved: the worker opens the input itself (`O_NOFOLLOW`, regular file under `audio/` or `.trash/`), sniffs the container, forces the demuxer from an allowlist and feeds `pipe:0` with `-protocol_whitelist pipe` and `-xerror`; the only `file:` read is a `moov`-last MP4 with `-f mov` forced and external references disabled (D4; media-processing scenario "ffmpeg cannot be steered to another file"; tasks W.1, 0.2).
- [x] [major] Upload abuse: unbounded open uploads and staging per user, and no disk floor. Resolved: 2 open uploads and 3 GiB staged per user (`429`), `statfs` floor `MEDIA_MIN_FREE_BYTES` checked at create and every part (`507`) (D12; api-contract-freeze upload family; tasks B.4, S.4).
- [x] [major] Trash pressure can fill the disk. Resolved: low-disk mode purges trash oldest-first down to the floor, refuses uploads with `507`, and pauses merges and oversize jobs on the worker side; transitions are logged once (D8; media-processing scenario "Low disk shortens the grace period"; tasks B.5, S.6, W.3).
- [x] [major] The worker login can `LISTEN` on the frame-bus channel and flood `pg_notify`; no grant restricts it. Resolved: accepted and monitored, since PostgreSQL has no `LISTEN`/`NOTIFY` privilege (A15): the frame bus's HMAC and replay guards hold, the role's connection limit and timeouts bound the rate, the API's sweep reads `pg_notification_queue_usage()` and warns above 0.5, and `docs/security.md` records the residual (D20; tasks B.5, W.7).
- [x] [minor] Grouped minors. Resolved: fair claim ordering: `run_after_ms` then creation, and two lanes keyed on `input_bytes` so a big import does not starve chunk waveforms (D2; scenario "A big import does not delay a chunk's waveform"; tasks S.3, W.4); the ffmpeg digest is pinned once in the Dockerfile with a review date, mirrored by a test, and bumped by Dependabot's docker ecosystem (D13; task W.5); the `media` network is internal so no external resolver is reachable, verified in the spike (D4; task 0.1); the spark-infra hand-off names `roles/autologger_images/defaults/main.yml:14-15`, `roles/autologger_env/defaults/main.yml:79-80`, `roles/autologger_env/tasks/up.yml:107-143` and that `MEDIA_DB_PASSWORD` must exist in KV before the migration ships (proposal Impact).

## C. Merge data integrity

- [x] [critical] Duplicate audio after a reload or two tabs, even when the chunk row was already merged away: the dedupe only looked at live rows. Resolved: `catalog.session_audio_seams` keeps every accepted window with the segment that holds it; the segment POST answers with the existing segment (chunk or merged) and stores nothing, the seam primary key turns a concurrent duplicate into the same answer, and Web Locks stop the two-tab race at the source (D7, D18, D10; api-contract-freeze "Segment upload is idempotent per recording window"; catalog-database seams table; tasks S.1, S.5, B.2, B.3).
- [x] [major] A late middle chunk would be appended at the end of the merged file. Resolved: the merge refuses to append an input whose window lies between existing seams and rebuilds from the originals (each seam records its `source_key`, originals live in `.trash/` for 7 days, the worker reads them there) or fails `interleaved-input`; finalize carries the client's window list and the server answers `waiting` until every window is held (D6, D7; media-processing scenarios "A straggler holds the merge", "A late middle chunk never lands at the end"; tasks B.3, W.3, A.3).
- [x] [major] Transcript generation during a swap silently loses a chunk (a missing blob is skipped). Resolved: `mediaApply` defers merges while a `transcript-generation` (or `youtube-import`) run lease is held; generation fails with `502` naming a listed segment whose blob is missing, while unparseable blobs are still skipped; the replace transaction re-checks the segment set (D7, D9; transcript-generation "Segment grouping and concatenation" MODIFIED; media-processing scenario "A merge waits for a transcript run"; tasks B.5, D.4).
- [x] [major] Safari AAC chunks fail the sample-count tolerance through priming ((n−1) × 2112), and a corrupt stream decoded as silence passes it. Resolved: exact expected counts computed per family from the inputs' headers (Opus pre-skip, AAC with `-ignore_editlist 1` on both sides, raw sums for FLAC/PCM), zero tolerance, and `-xerror` so any decode error fails the job (D7; media-processing scenarios "A verification mismatch keeps the chunks", "Safari AAC chunks verify exactly"; tasks W.3, W.2).
- [x] [major] The reconcile would re-enqueue a failed merge every tick. Resolved: recordings with a terminal (`failed`, `cancelled`) merge job younger than 24 h are skipped (D6; scenario "A failed merge is not retried every tick"; task B.5).
- [x] [major] Alignment regression: one linear clip accumulates the rollover gaps (0.34-1.1 s over 3 h), so feed-row seeks and playback drift. Resolved: in scope; a merged segment is laid out as one clip per seam (same URL, media offset `offset_ms`, position from the seam's `started_at_utc`), identical to the chunk layout, and `seams` is exposed on the segment dict (D16, D7; web-session-console MODIFIED requirement and scenarios "A merged recording lays out by its seams", "Seam clips do not drift over a long recording"; tasks D.1, D.2, B.1, B.3).
- [x] [minor] Grouped minors. Resolved: the merged row's id and key derive from the job id so a retried apply is idempotent (D3); an ingest whose target row is gone is `cancelled` (D3); the worker's finish and fail statements are fenced `WHERE locked_by = $me AND status = 'running'` (D2; tasks S.3, W.4); the merge fails when `skipped.length > 0 || groups.length !== 1` (D7; task W.3); the ADR's "undo" claim is dropped (no segment undo exists, A14).

## Implementation panel 2026-10-12
Reviewers: worker/apply security, merge/apply data integrity, browser recording reliability · Code: `supabase-11a-legacy-import...afac1f24`

- [x] [major] A compromised worker could add seams with future windows through `result_json`; later real chunk POSTs were answered `existing` (D18) and the client dropped its only copy. `source_key` and `offset_ms` were taken from the result. Resolved: `applyMerge` accepts only the exact held windows of the inputs plus seamless input starts, bounded and strictly increasing offsets, and DB-sourced `ended_at_utc`/`source_key`; else `invalid-result` (B.9).
- [x] [major] Parts-uploaded files reached `audio/` as 0600, so the worker could not read any import or 413-fallback chunk. Resolved: every blob write path leaves 0644 files and 0755 dirs; cross-uid docker test (S.7).
- [x] [major] `mediaApply` cancelled a job on any hub-open error (DB blip, shutdown), stalling merges 24 h and leaving ingest segments pending forever. Resolved: cancel only when the session is gone; shutdown awaits the in-flight pass (B.9).
- [x] [major] A worker that lost its lease deleted the shared `media/<job>/`, wiping the re-claimer's output. Resolved: per-attempt file and scratch names; cleanup touches only the attempt's files (W.8).
- [x] [major] A throw in the recorder's onstop (unknown store handle, failed append) lost the chunk and left Stop stuck. Resolved: the store never throws, slices fall back to memory, duplicate onstop ignored (A.8).
- [x] [major] A chunk waiting in backoff in one tab was recoverable by another, giving two owners. Resolved: the queue holds the chunk's Web Lock for as long as it owns it; vanished bytes are checked against the server (A.8).
- [x] [major] OPFS worker calls had no timeout, so a hung worker stalled recording and held Record in `scanning`. Resolved: 10 s per-call timeout, backend marked dead, memory fallback, bounded scan (A.8).
- [x] [major] Falling back to memory deleted the disk copy even when reading it failed. Resolved: persisted bytes stay on disk; only new slices go to memory (A.8).
- [x] [major] Unmounting during microphone re-acquisition could start a recorder with no UI. Resolved: unmount ends the take (A.8).
- [x] [minor] Guard trigger did not bound lease/schedule values or error text. Resolved: bounded on the DB clock, refunds only by the live holder, error limited to D2 codes (S.7).
- [x] [minor] Worker-written `job.error` copied into `media_error`. Resolved: mapped to fixed codes (B.9).
- [x] [minor] AAC seam offsets ignored per-input priming (~43 ms). Resolved: measured priming subtracted; D7 amended (W.8).
- [x] [minor] Legacy rows with NULL `started_at_utc` became window "null". Resolved: worker fails `interleaved-input`; `--merge` excludes them (W.8, B.9).
- [x] [minor] Deterministic merge failures were retried daily forever. Resolved: blocked until the recording's segments change (B.9).
- [x] [minor] Recorder minors: finalize missed a window after a late rollover, sign-out and banner were not per user, 401/403 on dedupe retried silently, Record waited on the profile forever, `PartsUploadError` retried endlessly and opened new uploads, the probe leaked its worker. Resolved: all fixed with tests (A.8).

# Panel: session-frame-bus
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-07

- [x] [critical] Building `PostgresFrameBus` in `createBindings` would give every route-level socket test on the harness env (49 `createBindings` callers) no frames, because the harness never runs `main.ts`, and fixing that would mean changing many existing tests. Raised by assumption tester. Resolved: D1 makes the bus opt-in (`createBindings({frameBus})`, default `'local'`); only `main.ts` passes `'postgres'`, and new multi-process tests build their own bindings.
- [x] [critical] An access-loss close lists every lost session id in one NOTIFY. Above about 190-200 sessions it exceeds the 8000-byte limit, and other processes keep the revoked user's sockets. Raised by scope; also by failure and abuse and assumption tester as major. Resolved: D5 splits closes at 150 ids per message, and the 300-session test is in tasks 4.2 and 5.1.
- [x] [major] Any database login role can `pg_notify` (executable by PUBLIC, even read-only), so it could forge frames, record commands or closes. Raised by failure and abuse. Resolved: owner decision 4: messages are HMAC-signed with `FRAME_BUS_SECRET`, and receivers verify the signature, version, frame type, command enum and close code (D2). There is a forged-message scenario and test, and `docs/security.md` records the threat.
- [x] [major] The `autologger_app` connection limit (20) counts all processes together, and two processes need 26. Raised by failure and abuse and assumption tester. Resolved: owner decision 5: a migration raises it to 60, the per-process budget is 14 (four processes), the catalog-database and Postgres-adapter specs are amended, and there is a pg test (D7, task 2.1).
- [x] [major] A close published after commit is not atomic with the revoke, and a failed publish leaves other processes' sockets open indefinitely. Raised by failure and abuse. Resolved: owner decision 6: the close is published inside the revoking transaction (D5), and a revoke whose close can't be published fails with nothing changed. Tested in 5.1.
- [x] [major] Relayed commands become root-slot `pg_notify` calls that a socket can flood with any string, starving the 3 shared root slots. Raised by failure and abuse. Resolved: D4 validates commands against the contract enum, rate-limits to 10 per second per socket, and publishes on the bus's own publisher connection. Tested in 3.1.
- [x] [major] The bus-loss test would terminate other parallel test files' listeners (found by `application_name`, cluster-wide). Raised by failure and abuse. Resolved: the bus exposes its listener's backend pid, and tests terminate only their own (D8, task 4.3).
- [x] [major] team-management "Owner-anchored team lifecycle and access revocation" says "in this process … the close is driven from the database" and was not amended. Raised by scope. Resolved: MODIFIED delta.
- [x] [major] core-ports "Session runtime…" says socket operations "stay synchronous", and "Every catalog and session call is bound to a caller" says fan-out sends "no statement". Both become false. Raised by scope. Resolved: MODIFIED deltas for both, plus "The Postgres session adapter" for the connection budget. The cross-process order is folded into the broadcast-order clause.
- [x] [major] The `1012` spec closed sockets when the connection drops, but the design closes them when it reconnects. Raised by scope. Resolved: the requirement and scenarios now close on re-establishment, once per loss, and state that sockets get no frames while the connection is down.
- [x] [major] The ADR changes were broader than task 5.2 said: ADR 0021's live-updates decision, step 9, Consequences, the 6a follow-up and the "until slice 9" notes, plus ADR 0023's recommendation. Raised by scope. Resolved: task 6.2 lists every one.

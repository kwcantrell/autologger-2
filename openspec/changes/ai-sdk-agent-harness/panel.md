# Panel: ai-sdk-agent-harness
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-11

This change was first proposed as `opencode-agent-harness`: an OpenCode process per AI turn. The
first panel and the re-panel below reviewed that design. After them, the owner switched the
harness to the Vercel AI SDK running in process (2026-10-11). Findings specific to running
OpenCode are resolved by that switch. Findings that still apply are resolved in the current
artifacts. The AI SDK design gets its own re-panel, appended below.

## Panel (OpenCode design)

### Failure and abuse

- [x] [critical] OpenCode would run as the API's own uid with no OS isolation. Any built-in tool that slipped past deny-all could read `/proc/<api pid>/environ` (`PROVIDER_KEYS_SECRET`, OAuth, frame-bus and DeepGram secrets), another turn's tokens, and the operator's `~/.claude`. Evidence: design D3 (deny-all the only control); `docker/Dockerfile:165` `USER node`; `docker/secrets-env.yaml`; namespaces unavailable in the container: `docker run --rm --user node node:22-bookworm-slim@… unshare -Urpf --mount-proc …` -> `unshare: unshare failed: Operation not permitted`. Resolved: (owner choice, 2026-10-11) first a sidecar container, then superseded by the in-process AI SDK harness. The model drives no process with shell, file or network tools; its only capabilities are the turn's tool functions; design D3, Goals.
- [x] [major] "The only egress is loopback" was inferred, not enforced, so a runtime fetch by OpenCode could reach the internet. Evidence: design D3 step 2 (OpenCode draft). Resolved: superseded. No agent process exists, and every model request goes through the guarded fetch, which allows only the credential's destination; design D4, task 5.1.
- [x] [major] Relay `429`/`502` answers would trigger OpenCode's ten retries over ~90 s. Evidence: `502` -> 11 requests, 85 s; `429` -> 11 requests, 90 s. Resolved: superseded. There is no relay, and AI SDK retries are capped by `maxRetries: 2` (measured: 3 requests); design D3, A8.
- [x] [major] No deployment-wide concurrency ceiling. Evidence: ai-topics-chat "Spend bounds…" ("deferred to the change that adds other providers"). Declined by human: owner chose "Defer" (2026-10-11). The deferral now points to a later change; design Risks; proposal owner decision 9.
- [x] [major] Input tokens were unbounded, because each step re-sends the whole context. Evidence: design D4 caps (OpenCode draft). Resolved: a per-turn token budget, plus request-body caps of 4 MB per request and 48 MB per turn in the guarded fetch; design D3 "Limits", D4, tasks 5.1, 6.3.
- [x] [major] `opencode serve` processes and scratch roots could be orphaned by a restart. Evidence: `server/src/main.ts:138-170`. Resolved: superseded. AI SDK turns spawn nothing, and abort or timeout ends the request (measured: upstream socket closed); design D3 "End", A6.

### Assumption tester

- [x] [major] Readiness deadlocked: `opencode serve` connects to MCP only when a client touches it. Evidence: `sleep 4; wc -l < mcp.log` -> `0`. Resolved: superseded. The AI SDK passes tools in each request (measured `REQ1 tools: [ 'get_words' ]`); design A3.
- [x] [major] The relay path allowlist ignored query strings (`?beta=true`, `?alt=sse`). Evidence: panel `l401.log`. Resolved: superseded. The provider factories build the URLs, and the guarded fetch checks the destination origin and base path, not exact paths; design D4.
- [x] [major] No per-turn `TMPDIR`, so OpenCode would use the shared `/tmp/opencode`. Evidence: `debug paths` -> `tmp /tmp/opencode`. Resolved: superseded. No OpenCode process exists.
- [x] [major] The check constraint allowed a keyed row with some key columns null once `not null` was dropped. Evidence: temp table in `autologger-dev-db-1`, `begin … rollback`: inserting `('anthropic','llm',null,'\x01',null,'\x01',1,'abcd')` -> `PARTIAL-NULL keyed row accepted`. Resolved: every non-`claude-cli` row requires each key column non-null, with a partial-null test case; design D2, task 2.1.

### Scope and simplicity

- [x] [major] Unmodified auto-event-generation requirements say only a "CLI turn" triggers the regenerate delete. Evidence: `openspec/specs/auto-event-generation/spec.md:134,168-169,228-279`. Resolved: the modified "Single orchestrator turn over all instructions" says "CLI turn" means the generation turn on either route; task 7.2 tests regenerate on the SDK route.
- [x] [major] Page sizes were proven only against the CLI's tool-output limit. Evidence: auto-event-generation spec:349-351. Resolved: superseded. On the AI SDK route the tool's result goes to the model whole, with no truncation layer, and the page cap still bounds it; design D3.
- [x] [major] The spend bounds (`steps`, output cap) were unverified. Evidence: design Risks (OpenCode draft). Resolved: verified on the AI SDK: `isStepCount(3)` -> 3 requests; requests carry `max_tokens: 4000`; design A3, A7.
- [x] [major] The relay's one-in-flight cap was unneeded. Evidence: design D4 (OpenCode draft). Resolved: superseded. No relay; the guarded fetch has no in-flight cap.
- [x] [major] The ceiling sentence deferred to "the change that adds other providers", which is this change. Evidence: ai-topics-chat delta, "Spend bounds and per-session single-flight". Resolved: it now defers to a later change by owner decision 9.
- [x] [major] The development-mode CLI fallback was not an owner decision, and it made the CLI tests skip the production path. Evidence: proposal owner decisions; design D9 category 1 (OpenCode draft). Resolved: (owner choice) dropped; tests save a `claude-cli` row through a helper; design D1, D9, tasks 4.1, 7.1.
- [x] [major] api-contract-freeze said `claude_session_id` was "unchanged" although the second route ignores it. Evidence: api-contract-freeze delta. Resolved: the chat requirement states the per-route handling; design D6.
- [x] [major] Two changed scenarios keep "unchanged" titles over new `503` bodies. Evidence: api-contract-freeze and topic-generation deltas. Resolved: task 9.5 retitles them in the main specs at archive (a MODIFIED block must keep its scenario names).
- [x] [major] The Purpose sections of ai-topics-chat and topic-generation will be false after archive. Evidence: `openspec/specs/ai-topics-chat/spec.md:4`, `openspec/specs/topic-generation/spec.md:4`. Resolved: task 9.5 rewrites both at archive.
- [x] [major] The README endpoint table check could not catch stale rows. Evidence: `README.md:947`, `:953`. Resolved: task 7.3 names each row and requires its excerpt in the evidence.

## Re-panel (OpenCode sidecar delta)

- [x] [critical] Joining `api` to the agent network exposed the whole API, which listens on `0.0.0.0`, to every turn. With `TRUST_PROXY`, a turn could also spoof `X-Forwarded-For`; in dev, the gate did not refuse the agent subnet. Evidence: a peer on an `--internal` network fetched `http://api-agent:8787/` -> `200 api-ok`; `compose.yaml` `HOST: 0.0.0.0`; `GATE_DENY_SUBNET: 172.28.34.0/24 172.28.36.0/24`. Resolved: superseded by the in-process AI SDK harness. No agent network or sidecar exists.
- [x] [critical] Reused per-turn uids let a `setsid` survivor read the next turn's tokens. Evidence: `setpriv --reuid 20001 sh -c "(setsid sleep 300 &)"` -> still alive after its parent exited. Resolved: superseded. No per-turn processes or uids exist.
- [x] [critical] The sidecar broke the unmodified dev gate requirement, which says the gate is the only external listener and the environment list is closed. Evidence: `openspec/specs/local-container-environments/spec.md:212-246`; `docker/dev-gate.Caddyfile:44`. Resolved: superseded. No new listener or app environment variable besides `CLAUDE_CLI_EMAILS`; design D7.
- [x] [critical] Compose invariant 16 fails once `api` joins another network. Evidence: `local-container-environments` spec:772-777; `docker/scripts/check-envs.sh:225-234`. Resolved: superseded. No compose change.
- [x] [major] The runner, as root holding only four capabilities, could not remove a turn's 0700 scratch root. Evidence: `rm scratch ERR EACCES`. Resolved: superseded.
- [x] [major] The runner's config check ("deny-all first") let unsafe configs through. Evidence: design D10 (OpenCode draft). Resolved: superseded. Tools are code-defined functions, with no config the model or user can influence.
- [x] [major] Byte caps were not derived against legitimate turns. Evidence: design D4, D5. Resolved: the re-panel's simulation shows legitimate turns reach the model's context window first (a 40-step turn at a full 200k-token context ≈ 30.5 MB); design A11.
- [x] [major] Losing the runner mid-turn was unspecified. Evidence: design D3 mapping (OpenCode draft). Resolved: superseded. With no runner, a dropped provider stream surfaces as an SDK `error` part, which maps to `upstream-failed`; design D3 mapping, task 6.3.
- [x] [major] The runner image had no release path, ran as root against the non-root rule, broke package-architecture rules, and its scratch path and ports were unstated. Evidence: local-container-environments spec:486-505, 599-650; container-deployment spec:16-18; package-architecture spec:91-117. Resolved: superseded. No new image, package or ports.
- [x] [major] The relay as a second listener and port was unneeded. Evidence: design D4 (OpenCode draft). Resolved: superseded. No relay listener.

## Re-panel 2026-10-11 (AI SDK design)

### Scope and simplicity

- [x] [critical] A generation turn stopped by the step cap or token budget was mapped to success (`finish` → result), though the specs make it a failure; a truncated event regenerate would answer `200` and delete prior auto rows. Evidence: design D3 mapping (`finish` "after any number of steps"); specs/auto-event-generation:116-121; specs/topic-generation:104,120-125. Resolved: D3 "How a turn ends" — a capped generation turn fails (topics `502` with prior topics unchanged, events `502` with no regenerate delete); a capped chat turn ends `done`; tasks 6.3, 7.2.
- [x] [major] No way for the guarded fetch and `PROVIDER_HOSTS` (in `server/src`) to reach `@autologger/ai-runtime`, which package-architecture forbids importing from `server/src`. Evidence: design D3; `server/src/auth/providerTester.ts:24`; package-architecture spec:267-270. Resolved: the route injects a required `SdkTurnDeps {provider, baseURL, model, apiKey, fetch}`, and construction throws when `fetch` or `apiKey` is missing; design D3, task 6.3.
- [x] [major] The four cap variables are missing from `docker/secrets-env.yaml`, so tuning them would break a stack's secret. Evidence: `docker/secrets-env.yaml:40-53`; design D7. Resolved: all five new variables are allowlisted; design D7, task 9.1; task 7.3 greps all five.
- [x] [major] "Egress and spend disclosure" still said the ceiling waits for "the providers change". Evidence: specs/ai-topics-chat:579. Resolved: it now defers to a later change by owner decision 9 (spec delta).
- [x] [major] api-contract-freeze "events/generate optional body and deleted count" still froze the delete on "the CLI turn". Evidence: openspec/specs/api-contract-freeze/spec.md:897-926. Resolved: modified to mean the generation turn on either route, with a capped run a failure (spec delta).
- [x] [major] A provider that omits usage silently disables the token budget. Evidence: design D3 (usage-only budget). Resolved: a step with no reported usage counts an estimate from its request and response bytes ÷ 4; design D3, task 6.3.
- [x] [major] The 16 MB response cap was never derived and could stop legitimate generation. Evidence: design A11 (requests only). Resolved: raised to 64 MB from 40 steps × 4000 tokens × ~200 bytes of SSE per token ≈ 32 MB, doubled; design D4.
- [x] [major] The "existing 10 s header timeout" would cut long-context prefills. Evidence: specs/provider-credentials:148 (whole-test timeout). Resolved: a new 120 s timeout covers only the wait for headers; the route timeout bounds the turn; design D4, task 5.1.
- [x] [major] There is a smaller way to share the tool bodies than refactoring `TOOL_BUILDERS`. Evidence: `packages/ai-runtime/src/aiMcpServer.ts:714,729-787,956`. Resolved: a `ToolSink` interface for the builders' `server.tool` parameter, with an AI SDK collector; the MCP tests stay unchanged; design D3, D9, task 6.2.

### Failure and abuse

- [x] [critical] Nothing bounded tool calls per step, and the SDK runs them concurrently, so a hostile OpenAI-compatible server could request ~100k transcript renders or topic inserts in one streamed step inside the shared process. Evidence: `ai/dist/index.js:3229` (per-call `executeTool`); `aiMcpServer.ts:765-820`. Resolved: the tool wrapper caps 16 calls per step and 32 (chat) or 300 (generation) per turn, aborting the turn past a cap, and runs one body at a time; design D3, Risks, task 6.3.
- [x] [major] Tool bodies already running keep writing after the turn ends. Evidence: re-panel `node latetool.mjs` -> `525 execute END (side effect would land), signal aborted: true`; `aiTurn.ts:154-157`. Resolved: the wrapper refuses calls once the turn is not live, and the turn awaits in-flight bodies (bounded 30 s) before reporting or releasing the slot; design D3, task 6.3.
- [x] [major] No process-level backstop: Node's default unhandled-rejection output would print `APICallError.requestBodyValues`. Evidence: `grep -rn "unhandledRejection|uncaughtException" server/src packages/*/src` -> nothing. Resolved: handlers print one fixed line naming the class and exit non-zero; design D5, task 5.3.
- [x] [major] Echoing `done.claude_session_id: null` verbatim would `422` the next turn. Evidence: `packages/contract/src/schemas.ts:208,221`. Resolved: the request accepts `null` as absent; design D6, task 3.1.
- [x] [major] Unfrozen strings could reach the SSE: an `OutboundFailure` kind (`unreachable`), and the model's invented tool names on `invalid` tool calls. Evidence: `providerOutbound.ts:101`; `ai/dist/index.js:4140-4150`. Resolved: every model-side error maps to `upstream-failed`; only valid tool names in the turn's set are relayed; design D3, D5, task 6.3.

### Assumption tester

- [x] [major] A provider stream dropped mid-response throws from `fullStream` instead of emitting an `error` part, which would surface as `internal-error`. Evidence: re-panel `node beh.mjs drop` -> `THROWN APICallError status 200`. Resolved: the relay wraps iteration and classifies a throw as `upstream-failed`; design D3, A27, task 6.3.
- [x] [major] Calls to tools outside the set still produce `tool-call` parts carrying the model's name. Evidence: re-panel `node guard.mjs unknowntool` -> `tool-call bash invalid true`. Resolved: not relayed; design D3, A28.
- [x] [major] `execute` keeps running after abort. Evidence: re-panel `node latetool.mjs`. Resolved: as the late-write finding above; design D3.
- [x] [major] The token budget does nothing without usage. Evidence: re-panel `node beh_nousage.mjs budget` -> `seenSteps [[null],…]`. Resolved: the byte estimate; design D3, A26.
- [x] [major] The guarded fetch can't be imported into `ai-runtime`, and an undefined fetch silently falls back to `globalThis.fetch`. Evidence: package-architecture `SHALL NOT import … any module under server/src/`; `provider-utils/dist/index.js:650-660`. Resolved: required injected deps, with a construction-time check; design D3, A17, A18.
- [x] [major] OpenAI's Responses API stores the conversation by default. Evidence: re-panel `node urls2.mjs` -> `store= None`. Resolved: `providerOptions.openai.store = false`, disclosed in the README; design D3, A19, task 6.3.
- [x] [major] The existing 10 s timeout covers the whole request and would kill streaming turns. Evidence: `providerTester.ts` `TEST_TIMEOUT_MS = 10_000` "Bounds the whole request". Resolved: a new streaming function with a 120 s headers-only timeout; `providerRequest` unchanged; design D4.
- [x] [major] Inline `<think>` reasoning from OpenAI-compatible servers arrives as `text-delta`. Evidence: re-panel `node think.mjs` -> `text-delta "<think>INLINE-REASONING</think>"`. Resolved: `extractReasoningMiddleware({tagName:"think"})` on that provider, verified across chunk splits (`node think2.mjs` -> `reasoning-delta:"SECRET-REASON" | text-delta:"Answer"`); design D3, A20.
- [x] [major] The cap variables can't be set in deployed stacks. Evidence: `grep -n "AI_CHAT\|GENERATE" docker/secrets-env.yaml`. Resolved: as the scope finding above; design D7.

## Re-panel 2026-10-11 (fresh reviewer, on the AI SDK re-panel fixes)

- [x] [critical] The planned process-level backstop rested on a false premise: the API embeds Next.js, whose own `unhandledRejection`/`uncaughtException` handlers print the whole error and keep the process alive, so ours would either crash the shared API on routine RSC rejections or run after Next had already printed the prompt. Evidence: `node_modules/next/dist/server/lib/router-server.js:554-567`; `next-server.js:193-221` ("we definitely shouldn't crash the entire process"); `node fresh-review/tla.mjs`. Resolved: no process handler; every SDK result promise gets a no-op catch, no `AISDKError` leaves `sdkTurn` (property-free `SdkTurnFailure`), and the global error log redacts SDK errors to their class; design D5, A35, tasks 5.3, 6.3.
- [x] [major] Hono's global `onError` logs any non-database error in full, so an escaped SDK error would print `requestBodyValues`. Evidence: `server/src/app.ts:237`, `:142-151`. Resolved: `redactDatabaseError` gains the SDK-error rule; design D5, A36, task 5.3.
- [x] [major] "Capped vs natural" from the last `finishReason` is unreliable (tool calls reported with `stop`, `length` with an unexecuted call, `tool_calls` with none), so a truncated regenerate could still delete. Evidence: `node fresh-review/ends.mjs stopfr|lenfr|tcnotool`. Resolved: endings decided from the turn's own step records (step count, budget, last-step tool calls), with `length`/`content-filter`/`error`/`other` failing generation; design D3 ending table, A33, task 6.3.
- [x] [major] A cap breach from inside `execute` ends as an `abort` part, which the mapping table treated as a client cancel (no terminal event); the result promises then reject. Evidence: `node fresh-review/ends.mjs capabort` -> `…,abort`, `steps rejected DOMException`. Resolved: a `breach` flag checked before the abort row, result promises never awaited; design D3, A34, task 6.3.
- [x] [major] A hard fail at the 17th call in one step would break legitimate generation ("call create_event once per hit"). Evidence: `packages/ai-runtime/src/eventGeneratePrompt.ts:43-46`. Resolved: the per-step cap is soft (a tool error, the turn continues); only the per-turn cap ends the turn; design D3, task 6.3.
- [x] [major] Waiting for in-flight bodies "≤ 30 s" conflicted with the unchanged `runOuterAiTurn` (terminal `timeout` emitted before terminate), and that 30 s timeout does not exist for these routes. Evidence: `aiTurnOrchestrator.ts:164-176`; `grep -rn MCP_TOOL_TIMEOUT packages/ai-runtime/src` -> only AI v2. Resolved: the route awaits the drain set before acting on results or releasing the slot and lease; bodies are bounded by the app role's `statement_timeout = '30s'`; design D3 "Draining tool bodies", A40, task 7.2.
- [x] [major] "Reasoning is never relayed" is false for servers whose template opens `<think>` in the prompt (only `</think>` appears). Evidence: `node fresh-review/think3.mjs noopen` -> `t:"REASON-NO-OPEN-TAG" | t:"</think>Answer1 "`. Resolved: the guarantee is scoped to reasoning fields and `<think>…</think>`, and the README says to enable the server's reasoning parser; design D3, A39, task 7.3.
- [x] [major] The scenario "Nothing of an AI SDK turn survives it" had no task naming a test. Evidence: specs/ai-topics-chat:433-435. Resolved: task 7.1 "Nothing survives" queries the catalog and `DATA_DIR` for a planted marker after each ending.

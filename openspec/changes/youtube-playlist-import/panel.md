# Panel: youtube-playlist-import
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-11-09

- [x] [major] Session names are cut to 80 Unicode code points, but `episode: z.string().max(80)` counts UTF-16 code units. A title full of emoji cut to 80 code points is up to 160 units, so `POST /api/sessions` answers 422 and that video can never be imported. The ` (k)` suffix rule has the same problem, and the create-failure log line is unspecified (a 422 `detail` is an array). Evidence: `node --input-type=module -e "import {z} from 'zod/v4'; …max(80)… '😀'.repeat(41)"` (server/) -> `false`; `'😀'.repeat(40)` -> `true`; `packages/contract/src/schemas.ts:51 episode: z.string().max(80).nullish()`. (Assumption tester and scope reviewer; the failure reviewer's opposite reading was re-checked and is wrong.) Resolved: names are cut at 80 UTF-16 code units without splitting a surrogate pair, the duplicate suffix included (batch-audio-import "YouTube playlist session naming" steps 3-4, new scenario "Emoji titles fit the episode limit in UTF-16 units"); the create-failure line renders a zod-issue array as `<path>: <message>` joined with `; ` ("YouTube playlist import run", Create failure bullet and scenario); design D6 and A16; tasks 8.1 (80 emoji, half-pair cut) and 8.2 (422 line).
- [x] [major] Behind Cloudflare's 100 s limit the browser loop stops being sequential. After a non-JSON 524, D7 moves on while the server keeps downloading (up to 15 min, then `readFile` buffers up to 2 GB). `youtubeImportGuard` is per session, with no global cap. On prod (g6-standard-2, 4 GB, api has no mem_limit) about 9 downloads can run at once, and closing and reopening the modal adds more. Evidence: `grep -n "readFile(fetched" server/src/routers/sessions.ts` -> `556`; `packages/media-import/src/ytdlp.ts` -> `DEFAULT_MAX_FILESIZE_BYTES = 2_000_000_000`, `DEFAULT_HANG_TIMEOUT_MS = 15*60*1000`; `YoutubeImportGuard` holds only `inflightSessions: Set<string>`. Resolved: after a non-JSON answer the runner keeps the session and does not start the next entry, polling `…/audio/segments` every 15 s for at most 32 minutes (two 15-minute spawn bounds plus margin) and never re-sending `youtube-import` (a re-send racing the first import's finish would attach audio twice); abort keeps the in-flight session (batch-audio-import "YouTube playlist import run", Unknown outcome bullet and scenarios; design D7; task 8.2). A process-wide cap on `youtube-import` downloads would add a refusal that "No global import ceiling on claude_cli" rules out, so it is design Open question 2 (old Open question 2 on abort is superseded).
- [x] [major] An empty session left behind by an unknown outcome (a 524 or network drop followed by a server-side failure, a restart, or a lost create response) is skipped as "already in system" on every re-run, so "failed ones retry" never happens. Folder import already handles this with `resumableSessionFor`, which retries into a session that has zero segments. The playlist runner (task 7.2) has no equivalent. Evidence: `grep -n "segments.length === 0" web/src/pages/index/batchImport/runner.ts` -> `return segments.length === 0 ? sessionId : null;`; design.md "keeping it means a re-run skips it". Resolved: a name match that this import created for the same show and video id (IndexedDB memory, key `youtube:<showId>:<video_id>`, 30 days, as folder import) with zero segments is retried into; a `409` logs "still importing" and moves on; hand-made sessions are never imported into (batch-audio-import "Retry into an unfinished session" and scenarios; design D5 Created-session memory, A19; task 8.2).
- [x] [major] Duplicate-title suffixes ` (k)` depend on position. A video added at the top of the list, or an earlier same-titled video deleted (untitled entries get no name), shifts every suffix. A re-run then matches the wrong video's session and silently skips videos that were never imported. Evidence: spec naming rule 4 plus "Each playlist entry with a title SHALL get one session name"; design.md:238 "Rare (needs duplicate titles and a reorder)". Resolved: every entry sharing a plain name gets ` [<video_id>]` with the title part cut to 66 UTF-16 units (14-unit suffix, total ≤ 80); names no longer depend on positions or selection (batch-audio-import naming step 4 and scenario; design D6 with the residual newly-duplicated-title case; Open question 3 closed; proposal owner decision 2 note; task 8.1 reversed-order case).
- [x] [major] The skip check reads `GET /api/sessions`, which lists the profile's current active show, not the run's `showId`. `alignActiveShow` runs once, but a run lasts hours. Switching show in any tab or device mid-run makes skips compare against the wrong show, giving false skips and duplicates. The list is also not refetched before each create, so two tabs or members importing the same playlist create duplicate sessions. Evidence: `sed -n 147,175p server/src/routers/sessions.ts` -> `listSessionsForShow(activeShowId)`; `runner.ts:250-252` aligns once and then fetches; `show_id` is serialized (`sessions.ts:113`). Resolved: before each entry the runner reads the profile and switches the active show back if another tab changed it, then reads a fresh session list and matches only sessions with `show_id === showId` (batch-audio-import "Fresh session list" bullet and scenario; design D5, A17; task 8.2). The two-tab same-second race is an accepted risk in design Risks.

- [x] [major] A bad body gets `400 "Invalid playlist request body."`. That conflicts with the frozen "Validation error bodies carry zod 4 issues" (422 `{detail:[...]}`), and the delta doesn't declare an exception. `youtube-import` has the same deviation. Either declare the exception explicitly or answer 422. Evidence: `openspec/specs/api-contract-freeze/spec.md:1901-1905`; `sessions.ts:324 YOUTUBE_IMPORT_BAD_BODY_DETAIL`. Resolved: a body that is not JSON or fails `{url: string 1–2048}` is answered `422 {"detail": [zod issues]}` per the frozen convention; only URL rules give `400`; `youtube-import` keeps its own `400` (api-contract-freeze delta table, body paragraph and new scenario "A malformed body is a zod 4 validation error"; Run-features delta now says before the body `422`; design D2; tasks 5.1, 5.2, 5.3, 6.1 statuses include 422; proposal contract impact).

# Panel: catalog-pg-schema
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-01

All three reviewers found the first item independently; it is listed once.

- [x] [critical] Joining the dev `app` to the shared `db` network also puts `app-gate` on it, because the gate shares the app's namespace. Any Supabase service (or `db` through pg_net) would get anonymous access to the dev app and the operator's Claude login. This breaks the containerized-dev-env rule and invariant 3. Evidence: `docker/compose.dev.yaml:16-19,61`; `check-envs.sh:249-251` `(.services.app.networks//{})|keys)==["dev"]`; `dev-gate.Caddyfile:39,45`. Resolved: owner chose a two-member `catalog` network (`db` + app only) in 4a. The dev gate also refuses the `catalog` subnet. Invariants 3 and 16 are amended explicitly, and a `network_mode` sidecar counts as a member (design D5).
- [x] [major] With prod/stage `api` on `db`, the Supabase services reach `api` past the router and can forge `X-Forwarded-For` (`TRUST_PROXY=1`) to get past `IP_ALLOWLIST`. In the other direction, `api` reaches rest, auth, realtime and storage directly, past every gateway rule. Evidence: `compose.yaml:94,99`; `server/src/middleware/ipAllowlist.ts:3,176`; `docker/supabase-gw.Caddyfile` `@badhost`/`@nokey`/`@restroot`. Resolved: same two-member `catalog` network. The app's only new peer is `db` (D5).
- [x] [major] The MODIFIED container-deployment requirement and the dev-isolation requirement still say the app gets secrets only through the shared allowlist. `PGPASSWORD` contradicts that. Evidence: container-deployment "Secrets" bullet; local-container-environments "Dev isolates data and secrets" and the "Unnamed Infisical secrets" scenario. Resolved: both now carve out the five `PG*` literals, and the dev-isolation requirement is added as MODIFIED.
- [x] [major] The password step breaks the existing `test_migrate.sh` fixtures: they pass no `APP_DB_PASSWORD` and create no `autologger_app`. Evidence: `test_migrate.sh:37,51`; `alter role no_such_role …` → `role "no_such_role" does not exist`. Resolved: the step reports "app role absent" and succeeds when the role is missing. `runner()` passes the key (D4, task 3.1).
- [x] [major] The harness sat in `server/src/test/pg/`, but 4b's adapter in `packages/storage` may not import `server/src`. Evidence: `package-architecture/spec.md:28`. Resolved: the harness moves to the repo-root `test/pg/` (D6).
- [x] [major] The `globalSetup` on the existing integration project would make every SQLite integration test need docker. Evidence: `server/vitest.config.ts:19-24`. Resolved: a separate `pg` vitest project (`*.pg.test.ts`). `unit` and `integration` are unchanged until 4c (D6).
- [x] [major] Waiting only for `pg_isready` over the socket succeeds about 1 s before the image's initdb restart. The harness also didn't use the stack's command. Evidence: socket-ready 12:03:20.177 vs tcp-ready 12:03:21.274; `test_migrate.sh:29-31`. Resolved: the stack's exact `db` command, and a TCP query that must succeed twice (D6, A17).
- [x] [major] `log_statement` is `ddl` for `postgres` on this image, so `ALTER ROLE … PASSWORD` reaches the log unless `log_min_messages=fatal` is set. The design wrongly claimed `none`. Evidence: `show log_statement` → `ddl`; `postgresql.conf:542`; `docker logs … | grep -c <pw>` → 2 without the flag. Resolved: the step sets `log_statement = 'none'` itself, and a test checks `docker logs` (D4, D7, A16).
- [x] [major] The role inherits PUBLIC `TEMP` and `CONNECT`, so "no CREATE anywhere" and "nothing else" overstated it. If pg_net were ever created, PUBLIC would get `net.http_*`. Evidence: `create temp table tt(i int)` → `CREATE TABLE` as the role; `20250220051611_pg_net_perms_fix.sql:59-60`. Resolved: the wording is corrected, the attributes are always reset, and memberships are refused. PUBLIC `TEMP`/`CONNECT` is a recorded residual in `docs/security.md`, because revoking it would change what the Supabase services get. The dev gate refuses the `catalog` subnet, against a future pg_net SSRF (D3, D5).
- [x] [major] There was no connection limit and no timeout: a leaking pool could take all 100 slots from the Supabase services and `migrate`, or hold the migrate advisory lock. Evidence: `max_connections 100`, `rolconnlimit -1`. Resolved: `CONNECTION LIMIT 20`, `statement_timeout 30s` and `idle_in_transaction_session_timeout 15s` on the role, and the test harness uses `max_connections=300` (D3, D6).
- [x] [major] int4 columns would turn values SQLite accepts today into 500s. `start_offset_frames` has no maximum in the contract. Evidence: `packages/contract/src/schemas.ts` `z.number().int().min(0)`; `select 3000000000::integer` → `integer out of range`. Resolved: every SQLite INTEGER maps to `bigint`, with a 3e9 round-trip test. 4b parses int8 into a number (D1, A15, A23).
- [x] [major] NUL bytes in text are stored by SQLite but refused by Postgres, a frozen-contract change. Evidence: as above. Resolved: recorded for 4c, with a contract test and a 400-or-strip decision (D1, non-goals). 4a has no write path.
- [x] [major] A `DO` block with `begin`/`end` at the start of a line is refused by `migrate.sh`'s transaction-control check. Evidence: `refusing: … transaction control … is not allowed`. Resolved: the blocks are indented (D3, task 2.2).
- [x] [major] The password test could pass with a wrong password: pg_hba trusts loopback inside the container. Evidence: `host all all 127.0.0.1/32 trust`. Resolved: the login is tested from the host through the published port, and a wrong password must be refused (D7, A18).
- [x] [major] The `pg_stat_statements` check would error on a template clone, which lacks the extension, and would read `<insufficient privilege>` as the app role. Evidence: probe as a DML-only role → `<insufficient privilege>`. Resolved: queried as `postgres` on the `postgres` database (D7).
- [x] [minor] The `DO` guard trusts a pre-existing role's attributes and memberships. Resolved: the migration always runs `ALTER ROLE … NOSUPERUSER … NOBYPASSRLS`, fails on any membership, and the test checks this (D3, D7).
- [x] [minor] Membership was checked by service name. A `network_mode: service:app` sidecar was invisible to it, and one merged scope admitted dev `api` and prod `app`. Resolved: namespace sharing counts as membership, only `app-gate` may share `app`'s namespace, and `SECRET_SCOPE` is per stack (D5).
- [x] [minor] A12 overstated the protection: a same-uid child can read `/proc/<pid>/environ`. Evidence: the `/proc` probe → `PGPASSWORD=s3cret`. Resolved: recorded as a residual in `docs/security.md`, bounded by the role limits and the two-member network (D5).
- [x] [minor] `postgres` is a member of `pg_read_all_data`, so `realtime` (which holds `POSTGRES_PASSWORD`) can read the catalog. Resolved: stated in the spec and docs, and left to slice 6 (D2).
- [x] [minor] Rotation order, and the prod `:?` behaviour. Resolved: the order (migrate, then recreate the app) is documented. 4c records the boot order. Prod resolves need the key like the other Supabase keys, and `make check` uses sentinels (D4).
- [x] [minor] Harness leaks and flakes: Ctrl-C leftovers, clones never dropped, connection exhaustion, cold CI pulls. Resolved: pid-labelled reaping, `max_connections=300`, `max: 1` pools ended per test, and an explicit pull with a timeout (D6).
- [x] [minor] Check the password format with `case`, not `grep`, which matches per line. Resolved: `case` plus a length check (D4).
- [x] [minor] The collation test doesn't cover `COLLATE NOCASE` in `showsStore.ts:178`. Resolved: recorded for 4c (D1).
- [x] [minor] The runner's `N applied` summary is always 0 (an existing bug), so the rerun assertion was trivial. Evidence: two fresh files → `0 applied`. Resolved: fixed in this change with a test (D4, A24).
- [x] [minor] Parity of nullability and index names can't hold as written (SQLite text PKs are nullable, and its autoindexes are unnamed). Comparing rendered defaults is brittle. Resolved: PK columns are an explicit exception, only the named indexes are compared, and types and defaults are checked against a fixed table. The test is deleted in 4e (D7).
- [x] [minor] postgres.js returns int8 as a string, so a strict range test would fail. Resolved: the test compares through `Number()`, and 4b owns the parser (D7).
- [x] [minor] The ADR's "rollback per test" changes, and the task recorded none of it. Resolved: added to task 5.1.
- [x] [minor] Stale header comments: `supabase-db.yaml`, `compose.dev.yaml` and `secrets-env.yaml`. Resolved: added to task 4.3.
- [x] [minor] The no-docker test sat in an integration file whose setup already fails without docker. Resolved: it is a unit test with an injected `docker` stub (task 1.1).
- [x] [minor] There were no tests for "published only on 127.0.0.1" and "no password on argv". Resolved: a spec scenario and a unit test (task 1.1).
- [x] [minor] A cold CI pull of the image is about 367 MB, with no explicit pull or timeout. Resolved: an explicit `docker pull` with a 10-minute timeout (D6).
- [ ] [minor] Running 4d before 4c would keep the branch from ever running live Postgres with known races. Open for the owner: the approved plan orders 4a-4e and allows this swap at approval.
- [x] [minor] Keep the `pg_stat_statements` step and running migrate twice. These are confirmations, not defects: A7, A8 and A1 show why. No change needed.

# Panel: session-leases
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-06

- [x] [major] A2's mechanism was wrong: Postgres evaluates the `DO UPDATE … WHERE` before the UPDATE policy's USING, so with a holder-scoped USING a refused claim gives `INSERT 0 0` and the expired-takeover claim raises 42501 (assumption tester, rolled-back txn). Resolved: design A2 and Risks rewritten with the observed outputs; the chosen policy (USING = access rule alone) is unchanged; task 2.1 pins the takeover case.
- [x] [major] RLS does not bind a live lease to its holder: with USING = the access rule, a user with show access can rewrite a live lease to itself with a direct UPDATE (assumption tester). Resolved: stated in design D1, the catalog-database delta (requirement text and scenario "RLS alone does not protect a live lease") and the proposal's approver section as an accepted trade-off (no Clock time in the policy; the server statements are the only writers, as for every 7b-2 table); task 2.1 pins it.
- [x] [major] Status-read alarm arming treated a running alarm as idle (the timer slot is cleared before `runAlarm` takes the lock), which would flake `callers.int.test.ts`'s exact system-transaction list (assumption tester); and it changes no outcome under the owner decisions (scope and simplicity). Resolved: status-read arming is cut from the design (D5), spec, proposal and tasks; race case (c) is now "B's status reads not alive; B's claim takes over".
- [x] [major] The session-isolation guard (`isolation.int.test.ts`) would lose lease coverage because its `TABLES` map omits `session_leases` (assumption tester). Resolved: D6 category 6 and task 3.2 add the table to the guard.
- [x] [major] D3 dropped today's empty client-id guard, so a whitespace id would hit the check constraint (23514 → 500); a NUL id bound into heartbeat/release would raise 22021 → 500 (assumption tester; failure and abuse). Resolved: D3 keeps the guard and extends it to NUL; the api-contract-freeze delta adds the client-id rule and scenario "A blank or NUL client id is refused, never a server error"; tasks 3.1 and 5.1 test it at store and route level.
- [x] [major] The tab id shown to every viewer let a user with access squat on another user's client id after release, mislabelling the victim's UI and making the lease unbreakable (failure and abuse). Resolved by owner decision 7: only the holding user sees the real id, every other caller gets `"another-client"` (design D4, api-contract-freeze delta and scenario, tasks 3.1 and 5.1).
- [x] [major] "At most a 40 s gap" was false: a lapse mid-take (deploy, restart, sleep, network) loses the lease for the rest of the take while the web keeps recording with no lease (failure and abuse). Resolved by owner decision 8: the recorder re-claims after a refused heartbeat and warns on a 409 (design D7, live-recording-chunks MODIFIED, task 6.1); the migration and rollback text is corrected (deploy and roll back between takes).
- [x] [major] `runUncounted` was a generic escape hatch needing its own repo guard (scope and simplicity). Resolved: replaced by a purpose-specific `SessionCore.heartbeatLeaseUncounted`, following the `metaSetUncounted` precedent; the repo-guard task is removed.
- [x] [major] `claimed_at_ms` had no reader in 8a (scope and simplicity). Resolved: the column and the claim's CASE are dropped; D1 notes that 8b adds a claim time if it needs one.
- [x] [major] Assumptions listed no command or observed output, as `openspec/config.yaml` requires (scope and simplicity). Resolved: design A1-A8 now each give the test and the observed output (from the assumption tester's rolled-back runs and greps).
- [x] [major] Task 7.4 pre-waived `scripts/check-change.sh` (scope and simplicity). Resolved: 7.4 runs `--stage hook` and `--stage pr` unless the owner waives it during this change.

## Re-panel (2026-10-06, fresh reviewer, on the revised design)

- [x] [major] A re-claim could land after the final release (heartbeats are fire-and-forget, and `finalizeStop`/`pagehide` release separately), leaving a 40 s phantom lease that blocks others and shows this tab as recording. Resolved: D7 binds every response to its take, `finalizeStop` waits for an in-flight claim before releasing, and a claim that succeeds after stop is released at once; `pagehide` stays best-effort and is documented; live-recording-chunks scenario "Stopping during a re-claim leaves no lease behind"; task 6.1 tests.
- [x] [major] The 409 retry loop was under-specified, gave a toast every 8 s, and contradicted itself on whether heartbeats resume. Resolved: D7 is now a two-mode state machine (holding/lost); in lost mode each tick sends a claim instead of a heartbeat; one warning per loss; heartbeats resume after a successful claim; spec text and scenario rewritten; task 6.1 tests no second toast and the resume.
- [x] [major] The masking scenario had the Companion reading a field it can't reach, and D4's "both null" exception contradicted decision 7's "including Companion". Resolved: the scenario now checks B's status and the Companion's `is_recording`; D4 states that Companion never receives the field and that no system task holds a recording lease in 8a.

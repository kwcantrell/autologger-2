# Panel: shared-request-state
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-07

- [x] [major] Whole-record re-puts of a log-import job were unordered (floating `onProgress` appends, a 10 s heartbeat timer, 3 root connections), so an earlier `running` snapshot could overwrite a terminal status; simulated in 127 of 200 runs. Raised by assumption tester and failure and abuse. Resolved: D1 puts every write on a per-job promise chain, each an atomic `replaceIf(…, {expirationTtl})` against the last value written (a new optional parameter on `KvStore.replaceIf`). `finally` drains the chain before stopping the heartbeat. A delayed-put test is in task 2.1.
- [x] [major] A kv write failing in the detached job, the heartbeat, the poller or abandon would be an unhandled rejection, which would crash the process (no handler). Raised by failure and abuse. Resolved: D1 and D2 require every kv call on these paths to be awaited inside a chain or tick that catches and logs. A poll whose read throws retries rather than denying. A failed `register` put denies without emitting. Abandon deletes fire-and-forget with a catch. Throwing-kv tests are in tasks 2.1 and 3.1.
- [x] [major] The AI v2 row could be missing when the question goes out: a fast or cross-process answer would get 404, and the first poll would deny it as vanished. Raised by failure and abuse and assumption tester. Resolved: D2 awaits the `put` before arming the local entry, the poller and `emitQuestion`, and denies without emitting if it fails. Tested in 3.1.
- [x] [major] The crash path (a `200` to a dead turn until the row expires) contradicted the retained late-answer rule, and the expiry was stated three ways. Raised by scope and assumption tester. Resolved: the expiry is now the turn's deadline (start plus timeout) plus 5 s everywhere. The ai-v2-dashboards delta names the one exception: a turn whose process stopped, until its deadline.
- [x] [major] Wiring the AI v2 registry as a module singleton at the composition root would make the two-app test share one registry and never exercise kv. Raised by scope. Resolved: D2 makes it a per-binding port (`c.env.ports.aiV2Questions`) and removes the module singleton. Test 3.2 asserts that B's registry never held a local entry.
- [x] [major] The stale-job "recovery" made a reported `failed` non-terminal while the web stops polling on `failed`. Raised by scope. Resolved: D1 makes stale failure final. A poll switches the record to `failed` with a compare-and-swap, a runner that finds its record changed stops importing, and the sheets-log-import delta says the report is final.
- [x] [major] The D3 file check scanned every project directory (one per historical session) and could pass while the CLI's own lookup fails, for example with a shared home and a different `TMPDIR`. Raised by failure and abuse. Resolved: D3 stats exactly `projects/<encodeCwd(stableSessionCwd(sessionId))>/<id>.jsonl`. The encoding is pinned by a unit test against an observed CLI path and confirmed by the live check with the image's CLI. A test with a file under a different directory expects 422.
- [x] [major] There is no kv test double, and the packages may not import `@autologger/storage`. Raised by assumption tester. Resolved: D4 adds an in-package `MemoryKv` to each of `log-import` and `ai-runtime`, copying the exact semantics, and repeats the key cases on the real Postgres kv in the server integration tests.
- [x] [major] D3's file check breaks the existing accepted-resume test (`ai.int.test.ts:492`), whose fake CLI writes no conversation file, and D4 forbade the fix. Raised by assumption tester. Resolved: D4 category 2 now covers seeding a conversation file and overriding the CLI home in tests that expect a resume to be accepted.
- [x] [major] core-ports-architecture "Wall-clock time is read through a single Clock port" kept a size-cap eviction scenario and didn't list the new clock reads. Raised by scope. Resolved: a MODIFIED delta restates that scenario (no eviction by count), lists heartbeat staleness, the question deadline and the resume expiry, and adds a stale-job clock scenario.
- [x] [major] package-architecture "Every process-wide singleton has exactly one package home" still named the log-import job store as a `globalThis` singleton. Raised by scope and assumption tester. Resolved: a MODIFIED delta removes it from the singleton list, says the three kinds of shared request state live in kv behind the port (with the AI v2 registry built per binding), and adds a scenario.
- [x] [major] The sheets-log-import scenario "Running jobs survive the size cap" contradicted itself once the cap was removed, and mapped to no task. Raised by scope. Resolved: restated as a job that keeps heartbeating past its 2 h initial expiry and is still readable (the title is kept because a MODIFIED requirement can't drop scenarios), mapped to task 2.1.

# Panel: session-content-policies
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-03

- [x] [critical] A `GET /api/companion/state` raced by a revoke must answer its frozen no-access `200` shape (`active_session_id: null`, `session: null`, `last_command` re-masked), not `409` or `404`. Evidence: api-contract-freeze `spec.md:1604-1613`; `companion.ts:146-160` calls `getSessionHub(c, activeSid).statusLive(…)` after `callerMaySee`. Resolved: design D8 maps the refusal in `state` to "cannot see the active session"; the core-ports delta ("Session hub calls refused in a race") lists `state` apart from `categories`/`log`/`transport`/`command`, and its Companion scenario covers both; task 5.1 adds the `/state` race case and 5.2 the mapping.
- [x] [major] Group 3 as one commit was too large for tier-2 review. Resolved: tasks.md splits it into commit 3a (group 3: `SessionCaller`, the caller per call on `SessionStorage`, the per-call adapter, the probe, `session_exists` use and `SessionAccessDeniedError`; the hub passes one internal `session-hub` caller, so behaviour is unchanged and the allowlist entry only moves to `SessionHub.ts`) and commit 3b (group 4: `as()`, `SessionHubEntry`, the callers, undo steps, retiring `session-hub`, the scan rules), each ending with the full suites green.
- [x] [major] Compensating undo steps ran as the user and would be refused after a revoke, leaving an orphan segment and blob or a doubled set of generated events. Resolved: owner decision P1 (proposal, design "Owner decisions"): the seven undo sites run as the reviewed system task `session-undo` through a per-file `undoHub` (design D7, D9; task 4.5), each removing only what the same request wrote or, for the regenerate, the snapshot it replaces; the spec's "leave the session unchanged" became "leave none of its own writes", with the undo stated; race tests per site in task 5.1.
- [x] [major] The first draft's policy cost grew with the user's accessible sessions (0.060 ms system vs 9.26 ms at 20,000 sessions for a one-row insert; a `session_events` count 0.30 ms at 300 vs 1.49 ms at 3,000). Resolved: `spike/scale7b2.sql` measured three forms at 300 / 3,000 / 20,000 sessions (design A6): the correlated `exists` on `sessions` against `accessible_shows` is flat (one-row insert 0.45 / 0.45 / 0.46 ms; 200-row read 0.65 / 2.03 / 1.18 ms; 31,621-row insert 238 / 251 / 241 ms), the set form linear (0.54 / 1.70 / 9.27 ms; 1.00 / 3.31 / 18.27 ms), a per-row definer boolean flat but slow (28 ms read, 1.95 s insert). D1 and the draft use `exists`; `accessible_sessions` is dropped; D11's bench seeds 300 and 3,000 sessions before the stop rule applies (task 7.2).
- [x] [major] The YouTube import's catch-all (`sessions.ts:586-594`) turned any non-`ApiError` into `502`, so a refusal there would not answer the serial `404`. Resolved: design A14 audits every router catch block (only the YouTube import wraps; `mapGenerateError` and the rest rethrow); D8 has the YouTube catch-all rethrow `SessionAccessDeniedError` after its undo; the spec bullet names the wrapped case; task 5.1 adds the YouTube and local-import races, 5.2 the rethrow.
- [x] [minor] The churn was overstated as ~70 call sites. Resolved: design D3 and proposal Impact say about 13 production edits; the router `getSessionHub` call sites are unchanged.
- [x] [minor] The brand can be bypassed at the storage seam with an object literal. Resolved: D9 adds scan rules (`new PostgresSessionDb(` only in `node/config.ts` and the merge script; `kind: 'system'|'user'` literals only in `IMPLEMENTING`, A15) and states the remaining limit (a caller built without a `kind` literal) beside LIMITS; spec scenario and task 4.1 cover them.
- [x] [minor] The old requirement name "Every catalog call is bound to a caller" is still cited. Resolved: re-checked that OpenSpec refuses a MODIFIED block dropping a scenario (`openspec validate` on a scratch change: "omits scenario(s) the current spec still has"), so REMOVED+ADDED stays; task 4.6 updates the two code comments, task 7.4 hand-edits `core-ports-architecture/spec.md:85` at archive and greps for the old name.
- [x] [minor] The kept scenario "A user binding is refused on the session tables" contradicted its body. Resolved: its THEN now leads with "a user without access is refused".
- [x] [minor] Three scenarios had no direct test. Resolved: D12/task 4.2 add a binding recorder (`current_user`, `app.user_id` per body) for two users on one hub, the open, the alarm, an AI tool and a log-import job; task 2.1 adds the grant-then-repeat case.
- [x] [minor] The snapshot probe and `session_exists` were two steps. Resolved: one pipelined statement returns `ok` and `session_exists` (design D4).
- [x] [minor] Task 1.2 wrote `bench7b2.mts` against an API that did not exist yet. Resolved: 1.2 runs only 7b-1's baseline; the bench is written in 7.2 against the implemented API.
- [x] [minor] D5 overstated the guarantee after a mid-body revoke. Resolved: D5 and Risks state that later reads return no rows silently, a read-then-decide body commits a no-op and answers its own `404 Event not found`, a later write fails with `500`, and EvalPlanQual can widen the window; task 4.2 adds the no-op-commit case.
- [x] [minor] `accessible_sessions(uid)` accepted any uid. Resolved: the helper is gone with the `exists` form (finding 4); the policy reads `catalog.app_user_id()` inside, the 6b-2 precedent (D1).
- [x] [minor] Token-only Companion calls run as system for any session id, and presence stores any id (pre-existing, slice 9). Resolved: named as the exception in Goals, proposal "For the approver" and Non-goals, the spec's system-caller list, and the README bullet (task 6.1).
- [x] [minor] D6 said a hub opens "always after that route's gate", false for AI tool bodies and the log-import job. Resolved: D6 and the spec's `session-open` reason say "after a gate or in work a gated request started".
- [x] [minor] Only `create_event` catches hub errors; the other tools surface the error message through the MCP SDK's `createToolError`. Resolved: `SessionAccessDeniedError` has the neutral message `access to the session was refused`, with the id only as a property (D4); A11 and D8 state each tool's path; tasks 3.1 and 5.1 pin the text.
- [x] [minor] `packageBoundaries.repo.test.ts` scans only `SessionHubFacade`. Resolved: A16; task 4.1 adds the `SessionHubEntry` check.
- [x] [minor] The log-import failure line prints a non-catalog error's message. Resolved: with the neutral message the line is `Failed “<title>”: access to the session was refused`, pinned in task 5.1.
- [x] [minor] `spike7b2.sql` pinned only the owner and an outsider. Resolved: it now creates a granted member, a `can_write = 0` grantee and a member without a grant; results in design A2 (the no-grant member sees the row, locks 0 rows, sees 0 events).

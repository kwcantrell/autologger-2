# Panel: shared-blob-volume
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-08

- [x] [major] (scope) The new `copyBlobs` script and `copyBlobTree` repeat the README's existing blob tooling (`BLOBSYNC`, rsync), and dev's 15-file move needs one copy command. Evidence: README.md:1396-1403, 1463-1464; `server/scripts/copyDataDir.ts:30`. Resolved: dropped the script, its package function, its tests, and the spec's "Copying" bullet and scenario. Existing audio is moved with an additive `cp -a` (dev, as `node`) or `rsync -a --chown=1000:1000` (stage and prod), never with `--delete`, documented in a new README section (design D5).
- [x] [major] (failure) The api image ships no `server/scripts`, so prod would run `copyBlobs` from the host as root. That leaves root-owned `audio/<sid>/` directories the server (uid 1000) can't rename into, so later uploads fail with EACCES. Evidence: `docker/Dockerfile:88-96`, `:162 USER node`; `blobStore.ts:57-66`. Resolved: no script. The stage and prod move uses `rsync --chown=1000:1000`, and the dev move runs as `node` inside the container (design D5).
- [x] [major] (assumption) The same image gap means `copyBlobs` can't run in a stage or prod container, as the README step, the slice 11 reuse and the rollback each assumed. Evidence: `grep -n scripts docker/Dockerfile` -> only the dev stage's `mkdir`. Resolved: as above, the commands are host rsync and in-container `cp`.
- [x] [major] (failure) Rollback lost audio: no write stop, a destination (`DATA_DIR/blobs`) that may no longer exist, and no copy possible after the revert. Evidence: design "Rollback"; D2; proposal Out of scope. Resolved: rollback is now ordered steps (stop, then an additive copy with `mkdir -p` and `--chown`, excluding `.tmp`, before the revert, then count and byte checks, then revert, keeping the blob volume until playback is confirmed). It is in design "Rollback", README task 7.1.
- [x] [major] (scope, assumption) `server/scripts/copyDataDir.ts` still prints `rsync -a --delete ${src}/blobs/ ${dst}/blobs/`, its test asserts it, and the README runbooks target `$VOL/blobs`. Neither was in Impact or the tasks. Evidence: `copyDataDir.ts:287-288`; `copyDataDir.test.ts:256`; README.md:1287, 1421, 1464, 1516. Resolved: design D5 changes the hint to point at the README sections, D8 category 5 covers the test, task 3.1 was added, and task 7.1 retargets every `$VOL/blobs` and the volume table to `$BVOL`.
- [x] [major] (assumption) `bootOrder.int.test.ts` and `bootFrameBus.int.test.ts` start `main.ts` with hand-built envs without `BLOB_DIR`. Under D1's check order they'd be refused early, and the unamended scenario "Missing catalog connection settings refuse boot" would contradict that order. Evidence: `sed -n 44,55p server/src/bootOrder.int.test.ts`; `sed -n 38,62p server/src/bootFrameBus.int.test.ts`. Resolved: both files were added to D8 category 1 and task 4.3. The scenario's WHEN now includes a valid `BLOB_DIR` (web-frontend-platform delta).

# Proposal: web-docs-architecture-viz

## Why

The system's architecture — how the web SPA, Companion module, server routers, SessionHub,
catalog DB, session DBs, and blob store actually interact — lives only in prose (README,
CLAUDE.md, spec Purposes) and in contributors' heads. There is no visual map, and prose maps
drift silently. Meanwhile the repo has unusually strong raw material for a *verified* map:
the code itself is the source of truth for topology, non-trivial changes are gated through
OpenSpec, migrations are plain DDL, and the README endpoint table is the normative route
inventory. A docs site can derive its diagrams from those sources and **fail its checks
when the diagrams stop matching the code**, so the map can never quietly lie.

## What Changes

- New npm workspace **`web-docs/`**: a fully static documentation site that renders
  interactive, drill-down mermaid diagrams of the system architecture. No server involvement
  — built and served as static files, with a loopback-bound local dev server.
- **Authored grouping, derived edges, reviewed snapshot**: a small checked-in component
  model assigns every git-tracked source file to exactly one named component (or a visible,
  reasoned exclusion list); cross-component edges are **extracted from real TypeScript
  imports** at build time and classified `production`/`test`; the derived edge set is
  diffed against a **committed, reviewed snapshot**, so a new or vanished architectural
  dependency fails the check until the snapshot is regenerated and reviewed in the same
  diff. Non-import relationships (web→server HTTP/WS, companion→server HTTP, server→web
  static-serve, e2e process-spawn, datastores, config-gated external services) are declared
  in the model with mechanical evidence checks.
- **Drift fails the check**: an orphan or double-mapped tracked file, a snapshot mismatch,
  an unevidenced declared relationship, an unaccounted baseline OpenSpec capability, an
  invalid/empty/oversized diagram, or a dangling navigation id is a hard error — never a
  warning. The gates run in `npm run build -w web-docs` and a root **`npm run docs:check`**
  invoked at branch completion and before archive (root `npm test` carries the workspace's
  unit tests only).
- **Three drill-down levels** (navigation between pages, mermaid rendered client-side in
  strict mode):
  - **L0** — system architecture: components typed by kind (`runtime`/`datastore`/
    `external`, with `tooling`/`test-harness` behind a toggle), production import edges
    from the snapshot, declared relationships rendered distinctly; each node links to its
    component page.
  - **L1** — per-component page: the component's internal module graph from real imports
    (every mapped file visible or in a named group, elided test counts shown), its
    governing OpenSpec capabilities with requirement counts, and in-flight changes.
  - **L2** — detail: ER diagrams generated by schema introspection (catalog migrations +
    session `initSchema`); two authored, code-derived state diagrams (recording lease,
    SessionHub registry lifecycle — the transcript flow is deferred until
    `transcript-gen-lock-status` lands); and an in-site requirement/scenario browser
    parsed from the spec markdown with a count-equality gate.
- **OpenSpec as annotation layer**: baseline capabilities attach to components (or are
  declared cross-cutting/process); active tracked changes overlay the diagrams —
  component-scoped delta capabilities tint their components, cross-cutting ones are listed
  without flooding the map, and **new** capabilities (which exist only on archive) render
  as pending rather than failing the build.
- **No LLM in the loop**: every diagram is mechanically derived or hand-authored and
  mechanically validated. Builds are deterministic and offline (sorted iteration,
  repo-relative paths, no network, no reads of git-ignored artifacts, no
  browser-downloading dependencies).
- Root `package.json` gains the workspace, `typecheck`/`lint`/`test` legs (test =
  unit tests), and the `docs:check` script; CLAUDE.md and the archive skill gain the
  branch-final `docs:check` + attach-new-capability-on-archive steps (see Impact).

## Capabilities

### New Capabilities

- `web-docs-site`: the web-docs workspace — the component model (node kinds, capability
  scopes, exclusions), edge derivation/classification and the reviewed snapshot gate,
  relationship evidence checks, capability accounting with pending-grace, diagram
  validity/budget/injection-safety requirements, the three-level drill-down site, the
  active-changes overlay, ER/spec-browser generation, authored state diagrams, and the
  build/dev/docs:check commands.

### Modified Capabilities

_None._ No existing capability's requirements change: the server, web app, and Companion
module are untouched. The two process obligations this change creates (run `docs:check` at
branch completion/archive; attach a newly archived capability in the web-docs model in the
same archive commit) land in the operational SDLC encodings — CLAUDE.md and the archive
skill — exactly as the `sdlc-process` capability requires (process rules live in the
encodings, never a parallel spec restatement; this change's panel + gate satisfies its
"process-rule changes are design-bearing" scenario, so `sdlc-process` itself needs no
delta).

## Impact

- **Contract impact: none.** No HTTP/WS route, JSON shape, status code, export body, or WS
  message changes. The server is not modified and serves nothing new; the site is static
  files built offline. `api-contract-freeze` is not touched. A post-install lockfile diff
  asserts no dependency outside `web-docs`' own subtree changed resolution (the frozen
  contract's consumers keep their exact resolved versions).
- **New code**: `web-docs/` workspace (extraction pipeline + gates, component model, edge
  snapshot, static site, two authored state diagrams, tests).
- **Modified code/docs**: root `package.json` (workspaces array + script chains +
  `docs:check`); CLAUDE.md (SDLC final-gates line + layout pointer); README (web-docs
  section); `.claude/skills/openspec-archive-change/SKILL.md` (archive checklist step — a
  machine-parsed governance file, so the change includes a parse/load verification step).
  No changes under `server/`, `web/`, `companion/`, or `e2e/`.
- **Dependencies**: web-docs-local only — `typescript` and `mermaid` exact-pinned, `tsx`,
  `jsdom`, vite/react/vitest, and `better-sqlite3` at `server/`'s exact specifier (one
  hoisted copy, one native build). Nothing added to server/web/companion dependency trees.
- **Systems**: the branch-completion and archive workflows gain the `docs:check` gate; a
  green `docs:check` now attests the architecture diagrams match the code.

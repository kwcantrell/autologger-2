# Panel: shadcn-foundation
Tier: 1 · Reviewers: assumption tester · Date: 2026-10-06

- [x] [critical] The `chart` primitive's `ChartStyle` uses `<style dangerouslySetInnerHTML>`, which breaks `noAgentAuthoredMarkup.repo.test.ts` and Biome `noDangerouslySetInnerHtml`. Evidence: scratch `vitest run src/noAgentAuthoredMarkup.repo.test.ts` -> `"file": "web/src/shared/components/ui/chart.tsx" … 1 failed`. Resolved: chart and recharts removed from this change and deferred to change 3d, which must replace ChartStyle with inline CSS custom properties (proposal Non-goals). Task 3.2 runs `noAgentAuthoredMarkup` as part of verification.
- [x] [critical] The D4 shadcn token names collide with the legacy `--border`, `--muted` and `--accent` tokens and their `--color-*` twins, and the full shadcn token set wasn't mapped, so legacy surfaces or primitives would silently repaint. Evidence: `grep -n "^\s*--color-\(muted\|accent\|border\)" tailwind.css` -> `184/213/214`; `var(--muted)` ×11, `var(--border)` ×9. Resolved: new design D3 renames the legacy tokens to `--legacy-*` and updates every consumer, with a zero-pixel-change QA step (task 2.1). D5 maps the full shadcn set, and the `shadcnHygiene.repo.test.ts` guard (task 1.3) prevents legacy code from reattaching to the shadcn names.
- [x] [major] `shadcn add` emits `import { cn } from "cn"` and installs the brand-new npm `cn` package, which would orphan the local utils and add an unlisted supply-chain dependency. `recharts` is pinned by the registry. Evidence: `add button chart sonner field --dry-run` -> `+ cn + radix-ui + sonner + next-themes + recharts@3.8.0`. Resolved: D2 rewrites generated imports to `@/shared/lib/utils` and never installs `cn`. The hygiene guard fails on any `"cn"` import, and task 3.2 checks `package.json`. recharts is deferred with chart.
- [x] [major] sonner depends on `next-themes`, has no provider, and falls back to `"system"`, so it would render light toasts on light-mode operating systems. Evidence: registry `sonner.json` deps -> `['sonner','next-themes']`. Resolved: D2 rewrites `sonner.tsx` to a fixed `theme="dark"` and doesn't install `next-themes`. The guard checks this, and the smoke test asserts `data-sonner-theme="dark"`.
- [x] [major] The `.btn.primary` sky label comes from `text-v5-primary` in `BTN_PRIMARY_SKY` (`classnames.ts`), not a tailwind.css rule. The unlayered injection didn't prove the planned edit works. Evidence: `cat src/shared/theme/classnames.ts` -> `… text-v5-primary …`. Resolved: D7 targets `BTN_PRIMARY_SKY` (`text-[#e0f2fe]`), and `classnames.ts` is in Impact. It was re-measured by overriding the winning rule's value with the corrected probe: 6.47 / 8.36.
- [x] [major] The `contrastTokens.test.ts` design compared colors against the darkest surface, so it couldn't fail first and passes today. Evidence: python WCAG calc -> `v5-bg #070b14 0.55 5.5`. Resolved: D8 now composites over the lightest effective surface the probe measured for each token. These are fixtures from the baseline JSON `bg` field (`(35,57,76)` rows, `(46,54,74)` login link), on which today's values fail. Task 2.2 is test-first.
- [x] [major] The probe wasn't conservative: it took only the first `rgba(` of `background-image` and dropped stacked gradients, inflating ratios by about 0.5–0.7. Evidence: `contrast.js` -> `const c = parse(img)` (first match). Resolved: `contrast.js` now parses every gradient layer and, for each, picks the stop giving the lowest contrast. The baseline was recaptured with it, and the D7 values were re-measured: primary 3.46 (was 4.21), plus three more failures found (placeholders, close `×`, login link), which the owner chose to fix in this change. `cap.sh` also moves the mouse away before measuring, so hover can't skew results.
- [x] [major] The spec delta silently added a disabled-controls exemption and a new SHALL sentence that the proposal didn't disclose. Evidence: `awk '/### Requirement: AA contrast floor/,0' openspec/specs/web-ui-system/spec.md` -> no exemption. Resolved: the proposal's Modified Capabilities now names both additions explicitly and flags the exemption as a decision for the approver, with the consequence of rejecting it.
- [x] [major] The baseline PNGs (19 MB) would land in the artifacts-first commit, because the root `.gitignore` edit can only come later. Evidence: `git check-ignore -v …/home.1440.png; echo rc=$?` -> `rc=1`. Resolved: `qa/.gitignore` (`*.png`) sits inside the change directory, so it ships with the artifacts. `git check-ignore` now prints `openspec/changes/shadcn-foundation/qa/baseline/home.1440.png`.
- [x] [major] D5's disabled Button lacked the "muted text" the spec scenario requires. Evidence: `sed -n 1395,1400p tailwind.css` -> `.btn:disabled … color: var(--v5-muted)`. Resolved: D6 adds `disabled:text-muted-foreground`, and the shared-layer scenario in the spec delta includes the disabled state.
- [x] [major] "Remove `dark:` variants" would ship shadcn's light-mode treatments, because `dark:` is a `prefers-color-scheme` media query here. Evidence: `grep -n custom-variant tailwind.css` -> only `hover-always`; 29 `dark:` uses in the registry files. Resolved: D2 folds each `dark:X` into the base class in place of its light counterpart. Task 3.2 does this, and the hygiene guard forbids leftover `dark:`.
- [x] [major] The QA walk couldn't see Preflight drift on dialogs and modals. The baseline was 19 screens with no modals, and was mis-described as "38 screens". Evidence: `ls qa/baseline/*.png | wc -l` -> `38`. Resolved: the new `qa/screens.sh` walks 26 screens, adding event-instruction, event-options, the color popover, the session menu, time display, filter and shortcuts. Surfaces the walk still can't reach are listed in `qa/README.md`, and task 4.1 reviews their bare elements in code, followed by a human dev-stack pass.

# Panel: async-session-callers
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-01

- [x] [critical] The new requirement "Server code SHALL await every catalog, key/value and presence call" is false once 3a archives, because the 3b routers (teams, admin, profile, shows, auth, identity) are still un-awaited. Resolved: the requirement is replaced by "Server code never drops or misuses a promise". It holds across `server/src` today, and the type-checked test enforces it (design D3, spec delta).
- [x] [critical] `guardAiV2Route` (aiV2.ts:207) calls `requireSession` and must become async. Four call sites drop its result, and neither tsc nor the planned regex would catch a missed await, so a non-member could pass the gate or the process could crash on an unhandled rejection. Resolved: it is listed in the helper set (proposal, task 3.1). The regex test is replaced by a TypeScript-checker test that flags any dropped Promise-typed call, with a fixture for a dropped gate call (design D3, task 1.1).
- [x] [major] The regex repo test misses aliased calls (`presence.list()` via a parameter at companion.ts:77), calls split across lines, misused promises (`!requesterCanViewSession(...)` at transcribe.ts:184 would leak holder titles), and every catalog call. Resolved: the type-checked test (design D3) flags dropped and misused promises, including through port interfaces and aliases, with fixtures for each. Biome `noFloatingPromises` was evaluated and rejected; the evidence is in D3.
- [x] [major] `exportRows` (exports.ts:18) is an unlisted sync helper with a catalog call. Resolved: added to the helper list (proposal, task 3.1).
- [x] [major] Nothing detects a missed await on a catalog call: tsc can't while the catalog is sync, and the ten void-returning writes (`projectSessionLive`, `setSessionEpisodeDate`) would float in 3d. Resolved: the D3 test scans all of `server/src` and covers these automatically once 3d makes the catalog return Promises. 3a awaits them now.
- [x] [major] `takeOauthState`/`take` is scope creep into auth (human-led), and the race predates this change. Resolved: cut from 3a. It's on the slice 4 hazard list (design D6.1) for the owner to decide.
- [x] [major] `update` is under-specified: an absent or expired row isn't locked by `SELECT … FOR UPDATE` on Postgres, expiry semantics are unclear, and a re-entrant or slow `fn` is unsafe. Resolved: `update` is cut. The ack race isn't reachable while storage is synchronous (D1), and slice 4 fixes it with one conditional `UPDATE … WHERE id` (D6.2).
- [x] [major] `/api/companion/command` broadcasts before it stores `last_command`, so on async KV a fast ack misses it and the delivery is lost. Resolved: it stores, then broadcasts (design D5, spec scenario, task 3.3).
- [x] [major] The transcribe in-flight 409 builds its detail from holder A, then re-reads the lock and checks membership against holder B after a new await, which is a cross-tenant leak once storage does I/O. Resolved: the error carries `holderSessionId`, and the route checks that id (design D5, spec scenario, task 3.4).
- [x] [major] `logImport.ts` `projectLive` is block-bodied, so awaiting it waits on nothing, and its rejection would escape the detached job once the catalog is async. Resolved: it becomes an expression body returning the call (design D5, task 3.5).
- [x] [major] Projection mirror writes after hub writes can commit out of order on an async catalog. Resolved: recorded on the slice 4 hazard list with the revision-guard remedy (design D6.3, ADR 0021 via task 4.1).
- [x] [minor] D1 overstated: a microtask yield admits no new request while storage is synchronous, so the races are slice-4 hazards and race tests against the real adapter prove nothing. Resolved: D1 rewritten with the tester's evidence. Race-only tests are dropped with `take`/`update`.
- [x] [minor] The size estimate was optimistic (simulation: 196 lines for the edits alone; total about 380-420). Resolved: `take` and `update` were cut, the estimate is 330-390, and if it's over 400 the plan is to split by file (design D7).
- [x] [minor] D4 missed windows: topic-generation's word list, youtube-import's hub RPCs, `create_event`, the `/state` double presence read, the sessions active-show read-then-write, and show-check-then-create. Resolved: all are in the D4 table. `/state` reads presence once (task 3.3). The rest are recorded or deferred to D6.
- [x] [minor] The finally-block note ("the call runs before the yield") stops being true at 3d. Resolved: marked for re-audit (design D6.4).
- [x] [minor] Purge failure at boot was undecided. Resolved: a failed purge logs and boot continues; a test covers it (design D2, spec scenario, task 2.3).
- [x] [minor] The adapter's lazy-expiry `delete` floats once async. Resolved: awaited (design D2, task 2.1).
- [x] [minor] Spec text named a test ("un-awaited calls are detected") and the proposal's requirement title differed from the delta. Resolved: the requirement is restated as a system invariant and the titles match.
- [x] [minor] The Purpose paragraph's "no async-costume APIs" conflicts with async adapters over SQLite. Resolved: concrete replacement wording is in task 4.2, applied at archive.
- [x] [minor] `logImport.ts` uses the request-scoped catalog inside a detached job. Resolved: recorded (design D6.6).
- [x] [minor] Hubs held across awaits must be re-checked once catalog calls yield. Resolved: 3a adds none, and the rule is recorded for 3d (design D6.7).
- [x] [minor] No WebSocket test covers a non-member upgrade. Resolved: a test is added in task 3.1.
- [x] [minor] The boot-order source-inspection test is optional. Resolved: replaced by a boot-helper test (task 2.3).
- [x] [minor] `update`'s return value was unspecified. Resolved: moot, since `update` is cut.

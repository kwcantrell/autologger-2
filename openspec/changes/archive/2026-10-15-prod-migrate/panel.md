# Panel: prod-migrate
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-07

- [x] [major] A hand-written wrapper call with only `compose run --rm migrate` would migrate prod without `prod-tags`, `resolved` or `prod-git` (the last runs only in the Makefile), so the proposal's "migrations run only as part of `prod-up`" did not hold. Raised by the scope reviewer and the failure-and-abuse reviewer. Evidence: Makefile:129-131 -> `@$(G) prod-git` is a separate `$(G)` line; compose-run.mjs `main()` has no git check. Resolved: D2 refuses the migrate step unless `prod-tags` and `resolved` come before it, and D5 adds `checkProdTree` (clean tree on `main`) in the wrapper immediately before the step; proposal Non-goals reworded; tasks 3.1 and 3.2 test both.
- [x] [major] The spec claimed nothing but the unmodified runner could run against prod, yet a run/exec deny-list lets other steps through with the prod secrets, e.g. `compose -f /tmp/o.yaml up -d migrate` (an extra compose file merged after compose_prod's list) or `compose cp`. Evidence: `splitStep('compose -f /tmp/o.yaml up -d migrate')` -> `["-f","/tmp/o.yaml","up","-d","migrate"]`, no `run`/`exec`; compose-run.mjs:759 -> `p.args.some((w) => w === 'run' || w === 'exec')`. Resolved: D2 is now an exact allowlist of the six prod compose steps the Makefile uses; the spec delta says so and task 3.1 tests `-f`, `up -d migrate` and `cp`.
- [x] [major] Rollback relied on "restore a backup taken before the upgrade", but nothing takes one before `prod-up` migrates; the only prod Postgres backup is the deploy host's nightly dump, and nine migrations contain `delete`/`drop`/`truncate`. Raised by the scope reviewer and the failure-and-abuse reviewer. Evidence: spark-infra `roles/stage_db_backup/defaults/main.yml:17` -> `"*-*-* 03:30:00"`; README:1618-1622. Resolved: D6 and task 5.1 state plainly that no backup is taken first and rollback means the last nightly dump; a pre-deploy dump in the deploy host's Ansible is left to the owner as a follow-up there.
- [x] [major] Task 3.1 would call the wrapper with the allowed `prod 'compose run --rm migrate'` step and test hooks off; in the prod deploy checkout, which has a real `.env.openbao.prod`, running the suite would log in and migrate prod. Evidence: compose-run.test.mjs:465-470 -> "falls through to the repo-root credentials file, which never exists for prod on a dev host or in CI"; spark-infra sync_prod.yml:3 -> `.env.openbao.prod` sits in the prod checkout. Resolved: task 3.1 tests the allowed plan through `checkProdPlan` only, and no test calls the wrapper with an allowed prod step.
- [ ] [major] Two migrations seed demo rows that will now land on prod: teams `test-studios` ("Test Studio") and `test-studio-2`, and the show `show-autolog-test`; the bootstrap owner's first sign-in then claims those ownerless teams. Evidence: `grep -n -i "insert into" supabase/migrations/*` -> `20261001000000_catalog_schema.sql:103`, `20261004000000_team_owner.sql:16`. Recorded as design A8 and a Risk; whether to remove them (a later migration, or deleting them in the app) is for the owner to decide.

# Panel: async-session-hub
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-03

Reviewers report only critical and major findings (ADR 0024).

- [x] [critical] The proposal and D1/D7 claimed multi-call read-then-write sequences "cannot interleave on the SQLite adapter". Under a per-call lock, two handlers that resume in the same tick alternate between hub calls, so the PUT event metadata merge (S3), the local-import ordinal (S4), the Companion transport toggle (S6), the transcript remap (S9) and the log-import dedupe (S10) become reachable races. That breaks "zero observable change". Evidence: proposal.md:44-45; companion.ts:221-232; scratch `node toggle.mjs` -> `async-hub same-tick toggles: starts 2 rolling true` vs `sync-hub … starts 1 rolling false`; the 1.2 interleave test used only non-conflicting pairs. Resolved: (owner, 2026-10-03) all five are fixed in 7a as single hub methods, each one transaction: `updateEvent` with the metadata merge, `addImportedAudioSegment`, `toggleTake`, `replaceTranscriptWordsRemapped`, and `addEventAtTotalFramesIfAbsent`. The premise is corrected in the proposal and in D1, D7 and D10 (spike A9). Conflicting-pair tests run at session-core level (5.1) and over HTTP (5.8), with a serial-order scenario per pair. S1, S2, S5, S7, S8 and S11 are documented with their real 7a window and listed as 7b hazards.
- [x] [major] The ADDED core-ports requirement wrote 7a's in-process mechanism into the durable spec: FIFO per call, reads in call order, flush before the next operation, single-flight open and eviction. OQ4 left that mechanism for 7b to decide, so 7b would have needed a re-delta. Evidence: specs/core-ports-architecture/spec.md:19-34; design.md OQ4. Resolved: the requirement now states observables only (no dirty or lost read, atomic read-then-write as one hub method, broadcasts only after commit and in commit order, no self-deadlock, a named error on a closed hub). FIFO, single-flight open and eviction are 7a design facts (D3, D5, D6), and 7b chooses its mechanism.
- [x] [major] The spec delta's "A failed rollback SHALL stop the server" and its onFatal/exit-1 machinery covered a condition session-core cannot trigger, and conflicted with the Postgres catalog contract, where an unconfirmed rollback retires the connection. Evidence: design A8; openspec/specs/core-ports-architecture/spec.md:815-817. Resolved: the sentence and `onFatal`, exit 1 and `SessionHubBrokenError` are removed. A failed ROLLBACK rejects the call (cause attached), and the hub closes and leaves the registry. Queued calls get `SessionHubClosedError`, and the next `get` reopens. The fatal or retire policy goes to 7b's adapter.
- [x] [major] The spike and benchmark that A1-A9 and tasks 1.1, 1.3 and 6.1 depend on lived only in a session-scoped scratchpad, so they couldn't be reproduced after approval. Evidence: tasks.md "copy `spike7a.mjs` from the session scratchpad". Resolved: both are pinned in the change as `spike/spike7a.mjs` and `spike/bench7a.mts`, and the references point there. The bench runs the identical sequence before and after, with a fresh directory per run (this removes the growing-`COUNT(*)` artifact). Baseline: addEvent median 180 µs, listEvents median 430.7 µs.
- [x] [major] The nested-transaction tests (SessionHub.test.ts:338-372) call the public `hub.addEvent` inside `inTxn`. D4's misuse rule rejects that, yet D12 said their assertions stay unchanged. Evidence: SessionHub.test.ts:338-353 vs design D4/D3. Resolved: D12 and task 5.3 rewrite those tests so the inner write goes through the transaction-bound stores or a joined `t.tx`, keeping their assertions. A new test checks that a hub delegate inside `inTxn` rejects promptly with `SessionTxMisuseError` and does not deadlock.
- [x] [major] The lease alarm is armed inside a transaction body, so its timer inherits that AsyncLocalStorage context. Fake timers don't propagate the context, so no test could catch a misfire, and "log, don't re-arm" would make the failure permanent and silent. Evidence: scratch `als.test.ts` -> `fake undefined real {"open":true}`; leaseStore.ts:37,50,88. Resolved: the timer is armed through `als.exit`, so the callback has no transaction context (spike A10). `SessionHub.alarm.test.ts` adds a real-timer case: expiry clears the holder, sends `lease.changed`, and runs with no transaction context. On failure the alarm re-arms with backoff (owner OQ3, below).
- [x] [major] Promise hygiene treated `return promise` inside `try/finally` as consumed. `generateTranscript` would release `transcriptGenerationLock` and delete its scratch directory before the replace commits, a real race in 7b. Evidence: generateTranscript.ts:182-186. Resolved: the scan gains the typescript-eslint `return-await` "in-try-catch" rule, with reported and not-reported fixtures (3.1) and a spec scenario. The S9 call uses `return await` (5.6).
- [x] [major] Widening the hygiene scan to the package roots finds 3 existing violations that the design didn't mention: aiMcpServer.ts:950, :1112 and :1127, all memoized-promise idioms. Evidence: scratch `node hyg.ts` -> `findings 3`. Resolved: D9 and 3.2 reshape that code with wrapper objects instead of relaxing the checker. Behaviour is unchanged: one start for concurrent first callers, and a retry after a failed start.
- [x] [major] A delta was missing: `ai-topics-chat` still said the hub is "never held across an `await`", which would contradict the new core-ports wording in the durable specs. Evidence: `grep -rn "held across" openspec/specs` -> ai-topics-chat/spec.md:177. Resolved: added a MODIFIED "Session-scoped MCP toolset" delta with the same wording as core-ports.

## Owner decisions on the design's open questions (owner, 2026-10-03)
- OQ1: fix all five interleaving sequences in 7a (critical finding above).
- OQ2: no transaction deadline. Revisit item recorded in ADR 0021 (D11, task 5.9): a hub transaction that hangs and never resolves holds the session's lock and soft-locks that session.
- OQ3: on a lease-alarm failure, log and re-arm with backoff (1 s, doubling, capped at the 40 s stale threshold, reset on success).
- OQ4: decided by the second major finding. The spec states observables only, and 7b picks the mechanism.

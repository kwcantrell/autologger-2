# persistence-package-extraction — Proposal

## Why

Step 2 of the ~5-change modular-monolith campaign (foundation → **persistence packages**
→ router surgery → feature packages → web split). Step 1 (`package-split-foundation`,
archived 2026-08-07) established the L0 packages and deliberately left two named
residuals: the `SessionHub` (51-method) and `Catalog` (~67-method) facades stayed
concretely typed, with `server/src/appEnv.ts` holding a one-module allowance to name
those two concrete classes. This change extracts the persistence layer into L1 workspace
packages and retires that allowance — routers and middleware stop type-depending on
concrete persistence classes entirely, and the boundary becomes test-enforced instead of
convention.

## What Changes

- **Three new L1 source-only workspace packages** (siblings; no cross edges):
  - `@autologger/session-core` — everything under `server/src/session/` (SessionHub +
    registry, SessionCore + the `SessionRuntime` seam, the seven domain stores,
    eventAnchors, audioSeamParts, storeHelpers) plus its unit tests and the
    `fakeRuntime` test helper. Depends on `domain`, `contract`, `ports`;
    `better-sqlite3` as **peerDependency**.
  - `@autologger/catalog` — everything under `server/src/db/` (Catalog facade, the five
    stores, profileAssembler, sessionTitleDerivation) plus the catalog **migrations
    `.sql` files**, whose directory path the package exports. Depends on `domain`,
    `ports` only — no better-sqlite3 (it speaks through the `CatalogDb` port).
  - `@autologger/storage` — the persistence adapters from `server/src/node/`:
    `blobStore`, `kvStore`, `catalogStore` (the `CatalogDb` implementation), `migrate`
    (openCatalogDb + applyMigrations). Depends on `ports`; `better-sqlite3` as
    peerDependency. `KvStore`'s `systemClock` default parameter is removed (clock
    becomes required; the composition root already passes it explicitly).
- **Facade interfaces retire the appEnv allowance**: explicit interfaces for the
  SessionHub RPC surface, the registry, the Catalog facade, and its five stores,
  colocated in their packages (property-style function-type members, so drift is
  compiler-checked). `server/src/appEnv.ts` and all routers/middleware import
  interface types only; `@autologger/catalog` exports a `createCatalog` factory for
  the per-request construction in `middleware/auth.ts` (lifecycle unchanged);
  concrete classes are named solely by the composition root
  (`server/src/node/config.ts`) and tests, enforced by the boundary repo test.
- **`isAutoGeneratedMetadataJson` moves to `@autologger/domain`** — the pure predicate
  currently in `routers/events.ts` that `eventStore`'s SQL predicate must agree with
  (removing the only session→routers edge, which is test-only today).
- **Boundary enforcement extended, not forked**: `packageBoundaries.repo.test.ts` gains
  the L1 layer entries (incrementally, per extraction phase — the existing test's
  hardcoded edge set would otherwise red every phase gate), a **third-party
  bare-specifier vs manifest check** (closing step 1's recorded residual, now
  load-bearing because packages carry `better-sqlite3`), and an **interface-only
  assertion** making the retired allowance durable rather than one-time-inspected.
- **Toolchain coverage per step-1 mechanics**: per-package `tsc --noEmit` in root
  typecheck, per-package `vitest run` scripts chained from the root test script
  (server's two-tier unit/integration setup preserved verbatim; integration tests
  stay in `server/src/`), `biome.json`/lint coverage, single-copy gates for `zod`
  **and** `better-sqlite3` (JSON-parsed resolved-copy count).
- **web-docs atlas**: the three packages modeled as components in
  `web-docs/model/components.ts`, edge snapshot regenerated with per-edge attribution,
  root `npm run docs:check` green.

## Capabilities

### New Capabilities

(none — this change extends the two architecture capabilities established/updated by
step 1 rather than introducing a new observable capability)

### Modified Capabilities

- `package-architecture`: the layer graph grows an L1 (session-core, catalog, storage —
  siblings above L0, below the apps); the boundary repo test additionally asserts
  third-party bare specifiers are declared in the importing package's manifest; the
  nominal-identity/no-duplication requirement extends to `better-sqlite3` (native
  module, peerDependency + `npm ls` gate); the fixture-chain and singleton requirements
  re-verified across the moves.
- `core-ports-architecture`: the appEnv composition requirement is rewritten — the
  `SessionHubRegistry`/`Catalog` concrete-naming allowance is **retired**; routers reach
  persistence through package-exported facade interfaces; the `SessionRuntime` port's
  normative home becomes `@autologger/session-core`; the catalog migrations directory is
  owned and exported by `@autologger/catalog`.

## Impact

- **HTTP/WS contract impact: none.** Pure refactor — no endpoint, JSON shape, status
  code, or WS emission changes; existing suites plus the frozen-surface fixture chain
  are the parity evidence, with characterization already in place from prior changes.
- **Code**: ~50 files move (with `git mv` + import rewrites), ~29 server files get
  import-path rewrites (routers, aiV2, auth, middleware, logImport, node, test
  helpers, appEnv). **web-docs co-migrates** (panel finding): `erSchema.ts` imports
  three moved modules, two files hard-code the migrations path, and the extractor's
  workspace list + model + edge snapshot gain the three packages — per-phase, since
  web-docs runs in root typecheck/test. Interface extraction adds ~120 mechanical
  signatures across the facade interfaces (51 hub methods + ~67 catalog-store
  methods + registry/facade surfaces; counts per the fact-check pass).
- **Dependencies**: `better-sqlite3` becomes a peerDependency of two packages (the
  server workspace remains the installing dependency; web-docs's devDependency
  declaration dedupes to the same resolved copy); `zod` peer arrangement unchanged.
- **Tests**: package unit tests move with their packages (new vitest projects);
  integration tests (`*.int.test.ts` using the app harness/`setup.int.ts`) remain in
  `server/src/`; the session/db int tests get a server-side home.
- **Docs/atlas**: README annotated tree, CLAUDE.md source layout, web-docs components +
  edge snapshot.

## Non-Goals

- **No wire-behavior change of any kind** (frozen contract untouched).
- `presence` stays in `server/src/node/` — in-memory, not persistence; moving it buys
  no boundary.
- `systemClock` stays in `server/src/node/` (composition root) — packages take `Clock`
  as required parameters instead.
- No router surgery (step 3), no feature packages / SessionToolPort / Config slicing
  (step 4 — the AI-runtime change inherits archived D5's binding inputs), no web split
  (step 5).
- `aiV2/aggregates.ts` stays in `server/src/aiV2/` (web's
  `clientAggregates.pinning.test.ts` imports it by path — successor-change work).
- No second process, no build step, no compiled packages, no `tsc -b`.

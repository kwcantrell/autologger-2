Resolved: tasks.md:117 adds task 5.1, which refuses to archive while `openspec/changes/openbao-secrets/` exists (`test ! -e ... || exit 1`) and re-diffs the MODIFIED block against the then-durable requirement before `/opsx:archive`; proposal.md:96 points to it.
- [x] [major] S2 `STAGE_PUBLIC_BASE_URL=http://localhost[:port]` is a redundant second spelling of the default, with its own branch in `parseStagePublicUrl` (compose-run.mjs ~271), an extra check in `checkStageResolved` (~337) and a test. Evidence: draft compose-run.mjs `else if (u.protocol !== 'http:' || u.hostname !== 'localhost')` and `if (url.startsWith('http://') && url !== ...)`. Resolved: only `https://<dns name>` is accepted, empty = local (compose-run.mjs:258); `cookieSecure: url ? '1' : '0'` (compose-run.mjs:290); the resolved-config http branch is gone (compose-run.mjs:390); the test now lists `http://localhost:8788` and `http://localhost` as refused (compose-run.test.mjs:837); removed from proposal, spec ("unset is the local stage") and design D5. `node --test docker/scripts/compose-run.test.mjs` -> `✔ STAGE_PUBLIC_BASE_URL accepts only a bare https DNS origin`, `ℹ fail 0`.
- [x] [major] S3 A third copy of the security-relevant `env -i` prelude (`RUN`, `RUN_STAGE`, `RUN_CONFIRM` in the Makefile), and `RUN_CONFIRM` splices `$(CONFIRM)` into recipe text. Evidence: draft Makefile `RUN_STAGE = ...` and `RUN_CONFIRM = ... CONFIRM="$(CONFIRM)" ...`. Resolved: one `RUN` macro (Makefile:32) passes `CONFIRM`, `STAGE_IMAGE_TAG`, `STAGE_PUBLIC_BASE_URL`, `DOCKER_CONFIG` by name (`"$${NAME-}"`), exported at Makefile:31; `RUN_STAGE`/`RUN_CONFIRM` removed (`grep -c 'RUN_CONFIRM\|RUN_STAGE' Makefile` -> `0`); `make --eval ... zz CONFIRM=yes STAGE_IMAGE_TAG=abc DOCKER_CONFIG=/x` -> `CONFIRM=[yes] TAG=[abc] DC=[/x]`. The spec (spec.md:76-81) and design D1 state how other stage targets treat the options: `stage-down`/`stage-logs`/`stage-reset` validate and resolve with the same options; `stage-build` always builds `:local` because the wrapper refuses a build step while a tag is set (a refusal rather than silently ignoring the tag).
- [x] [major] S4 Tasks 1.x/2.x were ticked before panel and approval, with the code staged in the same index as the artifacts; the artifacts-first commit must contain only `openspec/changes/stage-public-https/`. Evidence: `git status --short` showed `M ` (staged) on Makefile, README.md and six docker/scripts files next to the `A ` artifacts. Resolved: every non-openspec path is unstaged (`git restore --staged`, working-tree changes kept); only `openspec/changes/stage-public-https/**` is staged. After the panel edits, every task 1.x/2.x command was re-run on 2026-10-03 and each Evidence line refreshed (tasks.md:30-85, including "fails on the base" and new "fails on the draft" runs); a dated note in tasks.md "Panel (2026-10-03)" and the Resolution note below record the order.

## Failure and abuse

- [x] [major] F1 Image/migration skew: migrations, `migrate.sh`, Caddyfiles, init SQL and compose files come from the tree `make` runs in, and nothing tied that tree to `STAGE_IMAGE_TAG`. Evidence: compose.yaml / supabase-db.yaml bind those files from the checkout; the draft wrapper only checked the tag's shape. Resolved: `checkStageTree` (compose-run.mjs:329, called before any OpenBao request at compose-run.mjs:716) requires `git rev-parse HEAD` == tag when `.git` exists, else a regular, small, non-symlink `REVISION` file at the root whose trimmed content == tag; spec requirement + scenario "The tree must be the tagged commit" (spec.md:86-90, spec.md:136); design D4a; README "The tree must be the tagged commit" (README.md:1610). Infra coordination: `~/spark-infra` `roles/autologger_env/tasks/sync_pinned.yml:73-81` writes `<export>/REVISION` with the full 40-hex commit + newline after `git archive` and before the rsync; its excludes (`/.git`, `node_modules/`, `.worktrees/`, `server/data/`, `.env.infisical.*`, `.env.openbao.*`) do not drop it; `ansible-lint roles/autologger_env/` -> `Passed: 0 failure(s), 0 warning(s) ... Profile 'production' ... passed`, `yamllint` rc=0. Test: `✔ with a tag, the tree must be the tagged commit: git HEAD, or a REVISION file without .git` (compose-run.test.mjs:902) and the end-to-end refusal `STAGE_IMAGE_TAG is not HEAD` with no request sent.
- [x] [major] F2 Public posture is not sticky: a later `make stage-up` without `STAGE_PUBLIC_BASE_URL` on the public host recreates `api` with `COOKIE_SECURE=0` and a localhost URL while the tunnel serves it; the untagged form tries to build on a host with no toolchain; the rollback text suggested exactly that. Evidence: draft design "Rollback is `make stage-up` without the variables". Resolved: a tag requires the URL (compose-run.mjs:283; spec.md:85; test `STAGE_IMAGE_TAG ...` asserts `/also set STAGE_PUBLIC_BASE_URL/`, and the end-to-end case refuses before any request); rollback rewritten in design "Migration / Rollback" (design.md:211) and README (README.md:1638): on the public host `make stage-up STAGE_IMAGE_TAG=<previous sha> STAGE_PUBLIC_BASE_URL=...` from a tree at that SHA, migrations are forward-only (previous app on the newer schema), or stop the tunnel first. Residual (owner): an untagged `make stage-up` on the public host is still possible; documented, not enforced (see "Left for the owner").
- [x] [major] F3 D7 overclaimed "two gates, two identities": the app's Google sign-in creates a user for any unseen Google `sub` (no allowlist), so the Access policy is the only membership control; the real second edge control is the connector's `access.required` JWT check for the app's `aud`. Evidence: `~/spark-infra/tofu/cloud/cloudflare.tf:52-54` `required = true`, `team_name`, `aud_tag = [...route[fqdn].aud]`, catch-all `:59 service = "http_status:404"`. Resolved: D7 rewritten (design.md:143); task 3.2 now has owner checks (a) the Access policy admits only named identities and (b) a request without a valid Access JWT for the app, or to an unrouted hostname, gets the connector's 403/404, not the app (tasks.md:92); origin-side JWT verification and an app sign-up allowlist are listed as non-goals/follow-ups (proposal.md:103); README states the Access policy decides who gets in (README.md:1631).
- [x] [major] F4 `DOCKER_CONFIG` only had to be an existing directory (e.g. `/tmp` was accepted); its `config.json` can switch the docker context/host (or load CLI plugins), and that child receives every stage secret in its environment. Evidence: draft `parseStageOptions` used `statSync(dc)` + `isDirectory()` only. Resolved: `checkDockerConfig` (compose-run.mjs:313) mirrors `checkCredFile`: `lstat`, not a symlink, a directory owned by the caller with no group/other write bit, and the same for `config.json` (regular file) if present; with `DOCKER_CONFIG` the child gets `DOCKER_CONTEXT=default` (compose-run.mjs:374), which overrides a `currentContext` and, with no `DOCKER_HOST` in the scratch-built child env, pins the default socket; without `DOCKER_CONFIG` behaviour is unchanged. Verified: scratch `config.json` `{"currentContext":"nonexistent-ctx"}` -> `docker compose ls` fails `context "nonexistent-ctx": context not found`; with `DOCKER_CONTEXT=default` it lists projects. Tests, one per refusal (compose-run.test.mjs:874): symlink dir, symlink `config.json`, `/tmp`, other uid, 0770 dir, 0620 `config.json`, a file, missing, relative; end-to-end run asserts `DOCKER_CONTEXT=default` in the child env. The `~/spark-infra` login dir is `mkdtemp` 0700 owned by the deploy user, so it passes.
- [x] [minor] F5 (reviewer note, no severity given) D1's "a value cannot inject shell" is too strong: `make` itself expands the values (in `ifeq` and `export`). Evidence: Makefile `ifeq ($(strip $(STAGE_IMAGE_TAG)),)` and `export STAGE_IMAGE_TAG ...`. Resolved: D1 (design.md:38-50) and the Makefile comment (Makefile:17) now say the values are never spliced into the recipe's shell text but are expanded by make, so they are operator input with the operator's privileges, not a boundary against untrusted input.

## Assumption tester

- [x] [major] A-1 Same gap as F1: no assumption covered "the tree is the tagged commit". Resolved: assumption A12 added (design.md:186) with evidence: `node --test docker/scripts/compose-run.test.mjs` -> `✔ with a tag, the tree must be the tagged commit: git HEAD, or a REVISION file without .git`, `ℹ fail 0`; infra `sync_pinned.yml` `- name: Write REVISION (the full commit) into the exported tree`, `content: "{{ autologger_env_commit }}\n"`.
- [x] [major] A-2 A8 (Cloudflare `X-Forwarded-For` append semantics) and A9 (Access cookie on Google's callback redirect) had no evidence before approval. Repo-side facts support them: `docker/Caddyfile:53-54` `trusted_proxies static ...` + `trusted_proxies_strict` (right-most trusted hop), the callback is a top-level GET (`server/src/routers/auth.ts:82`) with single-use state (`:111 takeOauthState`). Resolved: A8 cites https://developers.cloudflare.com/fundamentals/reference/http-headers/ (fetched 2026-10-03: with an existing header "Cloudflare will append the IP address of the HTTP proxy connecting to Cloudflare to the header"; otherwise it equals `CF-Connecting-IP`); A9 cites https://developers.cloudflare.com/cloudflare-one/access-controls/applications/http-apps/authorization-cookie/ (SameSite "Admin choice (Default: None)"; Lax is sent "with top-level navigations"). Both rows now say "documented, not yet observed end to end" (design.md:183-184). Explicit fallbacks: D6 (design.md:138) if 3.4 fails the client IP is attacker-chosen, so stage MUST NOT set `IP_ALLOWLIST` (also in README and task 3.4); D7 (design.md:160) if 3.3 fails set the Access cookie SameSite to `Lax` (never `Strict`), else the owner chooses between an Access bypass for `/auth/google/callback` only and holding the public stage.

# Panel: shadcn-shared-wrappers
Tier: 1 · Reviewers: assumption tester · Date: 2026-10-06

- [x] [critical] The real tree already contains a banned `window.prompt` (`BatchImportModal.tsx:106`, pinned by `BatchImportModal.test.tsx:104-114`), so the planned guard can't pass within the approved scope, and the spec's "zero occurrences" scenario is already false. Evidence: `grep -nP '(?<![\w.])(confirm|prompt)\s*\(|\bwindow\.(confirm|prompt)\s*\('` -> `BatchImportModal.tsx:106: const raw = window.prompt('Paste a public Google Sheets URL …')`. Resolved: the owner chose to fix it in this change (2026-10-06). The new shared `useTextPrompt()` (design D3b) replaces the call, and task 1.1 rewrites the test. The proposal names this one consumer change.
- [x] [major] D6's custom numeric toast ids collide with sonner's auto-increment ids, which start at 1, so a persistent toast and an unrelated toast overwrite each other. Evidence: scratch `toast('auto one')` then `toast(…,{id:1})` -> `auto one present: false`. Resolved: D6 now stores the id sonner returns, and `toast.persistent` keeps returning a number through a facade map. A2 was re-tested (`assume/a2.test.tsx` -> `Tests 1 passed (1)`), and task 3.6 covers the collision case.
- [x] [major] On mobile the vaul Drawer doesn't move focus into the dialog or confirm (`autoFocus` defaults to false), so Enter or Space re-fires the trigger behind it. Evidence: `grep -n autoFocus node_modules/vaul/dist/index.mjs` -> `autoFocus = false … if (!autoFocus) { e.preventDefault();`; scratch -> `FOCUS vaul -> Delete row`. Resolved: D2 sets `autoFocus` on the Drawer root, and tasks 3.1 and 3.2 assert focus lands inside the dialog.
- [x] [major] D1 appended V5 classes onto shadcn's base strings, and twMerge keeps `sm:max-w-lg`, `bg-background`, `rounded-lg` and `zoom-in-95`. `sm:max-w-lg` would cap the `md:!w-[min(38rem…)]` overrides. Evidence: scratch `cn.test.tsx` -> `… sm:max-w-lg glass-panel … md:!w-[min(38rem,96vw)]`. Resolved: D1 now requires replacing the base strings, and task 2.1 adds a failing-first smoke case that checks no `max-w-`, `bg-background` or `zoom-in` class remains on content with a consumer width override.
- [x] [major] The R13 requirement that the inert LazySelect trigger match the mounted control was unverified: shadcn's `SelectTrigger` adds its own classes and chevron. Evidence: scratch `sel.test.tsx` -> `EXTRA in mounted: rounded-md whitespace-nowrap shadow-xs …`, `ICONS: 1`. Resolved: D5 makes `select.tsx`'s trigger classes and `SelectTriggerIcon` the single source for both triggers. Task 3.5 adds a parity test: equal className, role, name and ARIA state, and exactly one svg each.
- [x] [major] vaul's `handleOnly` defaults to false, so the whole sheet becomes draggable, unlike today's handle-only drag. A vetoed close (Settings' "Keep editing") leaves the sheet half-dragged, because `closeDrawer()` doesn't reset it. Evidence: `grep -o "handleOnly = false" node_modules/vaul/dist/index.mjs` -> `handleOnly = false`; vaul `onRelease` calls `closeDrawer()` with no `resetDrawer()`. Resolved: D2 sets `handleOnly` and uses `Drawer.Handle`, and a vetoed close resets the sheet. The re-key approach in the first draft was superseded by the in-place reset; see the Re-panel section. Task 3.1 tests both.

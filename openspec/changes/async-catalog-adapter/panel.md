# Panel: async-catalog-adapter
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-01

Probes are in the session scratchpad (`panel3c-assume/`, `panel3c-failure/`). They ran on node v24.21.0 and, for the assumption tester, also on node v22.23.3 inside `autologger-dev-app`.

- [x] [critical] A parent can end while a child savepoint is still open (an un-awaited `t.tx`, or a sibling-guard rejection inside `Promise.all`). The savepoint's later writes then land in the next request's transaction or autocommit, and a stale `ROLLBACK TO` can undo another transaction's savepoint. Evidence: `node model.mjs` -> M1 `rows (expect only the B row): [{id:1,'req A nested, after A committed'},{id:2,'req B'}]`, M2 `[{id:10,'orphan nested write'}]`; `node sibling.cjs` -> `rows: [ 'B', 'A_after_rollback' ]`; `node raw.mjs` R2 -> tx2's savepoint write gone. (Failure and assumption reviewers.) Resolved: savepoints are removed. The owner chose (2026-10-01) that a nested `t.tx` joins the enclosing transaction (design D1). The one remaining case, a body returning while a joined body runs, rolls back, rejects, and closes the handle so the unfinished body's writes are refused (D3; spec scenario "A body returns before its joined work"; task 1.2 "un-awaited join").
- [x] [critical] If an outer body returns without awaiting `t.tx`, the adapter commits while the savepoint is open, and the savepoint's later writes run outside the transaction. The promise-hygiene test that D4 relied on scans only `server/src`, while 5 of the 7 transaction sites are in `packages/catalog/src`. Evidence: `node model.cjs` G10 -> `BEGIN IMMEDIATE,SAVEPOINT sp2,COMMIT,AFTER_COMMIT,RELEASE sp2`; `promiseHygiene.repo.test.ts` filters on `join(SERVER, 'src')`. Resolved: the adapter now enforces this at runtime: it refuses to commit while a joined body runs, and closes the handle (D3). 3d extends the hygiene test to `packages/catalog/src` (D6.2, ADR 0021).
- [x] [critical] The nested error path ran `ROLLBACK TO` and `RELEASE` unguarded. After a whole-transaction rollback both throw `no such savepoint`, which replaced the original error. Evidence: `node model.mjs` M4 -> `caller sees: no such savepoint: sp4`; `node sqlite.cjs` S2 -> `ROLLBACK TO err: no such savepoint: sp1`. Resolved: there are no savepoints (D1). The root path rolls back only when `inTransaction`, and always rejects with the first error (D3).
- [x] [major] Assumption A5 is false for errors that roll back the whole transaction (SQLITE_FULL, RAISE(ROLLBACK), OR ROLLBACK). A body that catches one and goes on writing autocommits those writes. Evidence: `node raw.mjs` R1 -> `caught … inTx false`, `rows persisted [{id:2,'b-after-autorollback'}]`; `node sqlite.cjs` S3 -> `SQLITE_FULL inTx after false`. Resolved: any error fails the whole transaction, as in postgres.js (A11). A handle statement also checks `inTransaction` first. A5' was added to the assumptions, and there is a test (1.2 "caught error", including a `RAISE(ROLLBACK)` trigger).
- [x] [major] A body that never settles, or a detached root call from an ended savepoint that the outer awaits, wedges the catalog. A module-global lock also blocks unrelated databases. Evidence: `node model.mjs` M3 -> `HUNG (deadlock)`; `model.cjs` G4 (innermost-frame check) -> `TIMEOUT_DEADLOCK`. Resolved: with no savepoints there are no inner frames, and the guard checks the root transaction's state (D4). A 10 s deadline rolls back and releases the lock (D3; spec scenario "A stalled transaction is released"; test 1.2 "deadline"). The lock is per connection (next finding).
- [x] [major] The lock scope was ambiguous. A module-global lock lets one stuck transaction block other databases. A per-instance lock lets two adapters on one connection bring back the A2 leak. Evidence: `model.mjs` M4 on a different database never ran; design D2 said both "process-wide" and "wraps one Database". Resolved: there is one lock per connection, in a `WeakMap<Database, Lock>` (D2), with a spec scenario and test 1.2 "shared lock".
- [x] [major] A failed `ROLLBACK` left the lock released while the connection stayed inside the transaction, so later callers either join a dead transaction or are all refused with no clear signal. Evidence: `node raw.mjs` R5 -> `ROLLBACK with open iterator throws … busy executing a query inTx true`. Resolved: the connection is marked broken, and every later or queued call rejects with `CatalogAdapterBrokenError` without touching it (D3). 3d makes the error fatal (D6.4). Spec scenario and test 1.2 "broken".
- [x] [major] Unhandled rejections crash Node: stale savepoint `RELEASE` errors and misuse thrown in detached work. Evidence: `model.mjs` M1 -> `[unhandledRejection] no such savepoint: sp1`; `grep unhandledRejection server/src` -> none. Resolved: there are no savepoints. Misuse always rejects the caller's own promise, and internal promises never reject unobserved (D4). The test file installs an `unhandledRejection` trap (1.2).
- [x] [major] The task 1.2 test list missed several failure modes: a failed COMMIT, auto-rollback errors, un-awaited and parallel nesting, the deadline, a failing BEGIN, a failing ROLLBACK, two adapters on one connection, an unhandled-rejection trap, and a stress run. Evidence: raw.mjs R3 -> `COMMIT throws SQLITE_CONSTRAINT_FOREIGNKEY inTx still true`; tasks.md as drafted. Resolved: all are named cases in 1.2 except the savepoint-specific ones, which no longer apply.
- [x] [major] The design claimed that two store transactions nest inside router transactions. None nests at runtime, so savepoints and the parent-while-savepoint guard were speculative. Evidence: `grep -rn "\.tx(" packages/catalog/src server/src/routers/{teams,auth}.ts` -> 7 sites, none reachable from another body; `authStore.ts:389-390`. Resolved: the Context was corrected, and nesting now joins (owner decision, D1).
- [x] [major] The ADDED requirement was SQLite-specific and would be false after slice 4's pooled postgres.js adapter. Evidence: draft spec "at most one transaction at a time"; proposal "slice 4 can swap the engine". Resolved: it is split into "The catalog transaction contract" (engine-neutral, which slice 4 keeps, including the root guard because postgres.js would silently escape the transaction) and "The SQLite catalog adapter serialises each connection" (worded "until … slice 4").
- [x] [major] 3d's central mechanism was unspecified: transaction bodies need stores bound to `t`. Router bodies use the root-bound facade, and store-internal transactions call `this.*` helpers. Evidence: `middleware/auth.ts` `createCatalog(c.env.ports.catalog)`; `authStore.ts:117-121` `this.authGetUserById` inside `this.db.tx`. Resolved: the port shape serves it, because a `Catalog` over `t` works unchanged and joining makes store-internal `tx` compose. D6.1 records that 3d gives the facade a `tx` building a `Catalog` over `t`, and must settle the registry snapshot. Ambient routing through `AsyncLocalStorage` was considered and rejected because it departs from the owner's scoped-handle decision.
- [x] [major] 3d's size was not estimated, although the split depends on it. Evidence: `grep -c "this\.db\." packages/catalog/src/*.ts` -> 62 sites; 3b counted 169 lines for callers alone. Resolved: D6.5 records that 3d is plausibly over 400 and measures it with a retype probe before proposing. The owner moved `KvStore` into 3c (D5), which shrinks 3d.
- [x] [minor] The unwired adapter would be dead code for one PR. Evidence: `config.ts:44` `new KvStore(catalog, clock)`. Resolved: the owner chose to fold `KvStore` in (D5, tasks 2.1-2.2, live check 3.3).
- [x] [minor] The raw-transaction guard has to run after the lock is acquired, because `inTransaction` is true while another adapter transaction holds the lock. Evidence: the failure reviewer's first model run rejected a waiting root read with "raw tx open". Resolved: stated in D2 and D4, and covered by the "wait" test.
- [x] [minor] The raw-transaction guard targets something no code does today. Evidence: `kvStore.ts` single statements. Resolved: kept, because it is a one-line `inTransaction` check after the lock, and it also catches a raw `BEGIN` left by a failed `BEGIN IMMEDIATE` path.
- [x] [minor] Handle validity could be judged through `AsyncLocalStorage` from the wrong request's context. Evidence: design D4 as drafted. Resolved: handle state lives on the handle, `AsyncLocalStorage` only detects root misuse, and it uses `als.run`, never `enterWith` (D4).
- [x] [minor] Fire-and-forget root work that runs while its transaction is still open is rejected, although waiting would be safe. Evidence: `model.cjs` G5 -> `REJECTED root used inside open tx`. Resolved: this is accepted and documented (D4). The rejection reaches that call's own promise, and dropping it is a hygiene violation.
- [x] [minor] Shutdown with a transaction open is atomic but unmanaged: the body and any waiters get a raw `TypeError`. Evidence: `raw.mjs` R4 -> `close() with open tx: ok`, `rows after reopen {c:0}`; `config.ts:133-140`. Resolved: an adapter `close()` is a 3d item (D6.4), because 3c opens no transaction in the server.
- [x] [minor] BEGIN IMMEDIATE with `busy_timeout=5000` can block the event loop if an external process holds the write lock, and BEGIN must release the lock if it fails. Evidence: `migrate.ts` `busy_timeout = 5000`. Resolved: BEGIN runs inside the try/finally that releases the lock (D3; test 1.2 "release"). The external-writer stall predates this change, and the data-dir lock excludes other servers.
- [x] [minor] The postgres.js mapping held for the API shape but not for the semantics (caught errors, root inside `begin`, isolation). Evidence: postgres 3.4.9 `cjs/src/index.js:251-290`. Resolved: D1 now states the engine-neutral semantics that slice 4 keeps. Isolation is irrelevant while SQLite serialises, and slice 4 decides it.
- [x] [minor] The spike ran only on node 24, but CI and the images use node 22. Evidence: `docker/Dockerfile` `node:22-bookworm-slim`; the assumption tester's re-run on v22.23.3 was identical. Resolved: noted in the design's evidence preamble.
- [x] [minor] `CatalogTxMisuseError` cannot live in `@autologger/ports`, which has no runtime exports. Evidence: `packages/ports/src/index.test.ts` `expect(Object.keys(ports)).toEqual([])`. Resolved: the error classes live in `packages/storage` (D4).
- [x] [minor] The proposal claimed the existing synchronous requirement "stays true", but its text doesn't say "wired". Evidence: `core-ports-architecture/spec.md:76-93`. Resolved: the proposal now says the two coexist, the old one describing the seam the stores are wired to, until 3d modifies it.
- [x] [minor] Some spec clauses had no scenario (FIFO order, the savepoint clause), and "no deadlock" could only show up as a test timeout. Evidence: draft spec. Resolved: scenarios were added for call order, the shared lock, the deadline and the broken adapter, and the savepoint clause is gone. "Arrival order" is now "the order they were called". Tests race a 200 ms timer.
- [x] [minor] D5 omitted migrations, and the evidence logs were not named. Evidence: `config.ts:42-43`; tasks.md 2.2. Resolved: D6.6 lists migrations, and tasks.md names the log files.

## Re-panel 2026-10-01
Scope: the revision (no savepoints; joined `t.tx`; any error fails the transaction; per-connection lock; deadline; broken state; `KvStore` wired onto the adapter). Reviewer: failure and abuse, fresh context. Probes: `panel3c-repanel/model.mjs`, `kvtake.mjs`.

- [x] [major] An un-awaited `t.tx` still crashed the process. Its handle closes, its next call rejects, and the dropped promise rejects with nobody observing it. A dropped failing `t.run` does the same. Evidence: `node model.mjs` -> `U1 caller: misuse: joined body running` then `[unhandledRejection] handle closed`. Resolved: every promise a handle returns is marked handled before it is returned, and any handle error fails the transaction, which carries it (D4). The 1.2 "un-awaited join" case asserts the trap stays silent.
- [x] [major] D3 contradicted itself: a domain error from one parallel joined body could be replaced by `CatalogTxMisuseError` because a sibling was still running. That would turn a 409 or 400 into a 500 once 3d moves the bodies. Evidence: design D3 "End" versus "Joined body still running"; `node model.mjs` U2. Resolved: the first error always wins, and misuse applies only when nothing else failed (D3; spec scenario "A domain error survives a still-running joined body"; test 1.2 "first error wins").
- [x] [major] D5's "KV ordering unchanged" claim holds only while no transaction holds the lock across a macrotask. In 3d, `takeOauthState`'s get-then-delete stops being single-use under contention, and `get`'s expiry delete can remove a value re-put in between. Evidence: `node kvtake.mjs` -> `take A true take B true`. Resolved: `get`'s expiry delete is now conditional (D5, test 2.1). The D5 claim is corrected. The OAuth atomic take is auth and the owner's decision, so it is not changed here. It moves from the slice 4 list to a 3d prerequisite in ADR 0021 (D6.7), and it is raised with the owner at approval.
- [x] [minor] The deadline did not stop a timed-out body writing through the root, which autocommitted while its handle writes rolled back. Evidence: `node model.mjs` -> `U3 caller: timeout`, `rows [ 'zombie-root' ]`. Resolved: root calls from a transaction that ended failed or timed out reject, citing its error as `cause` (D4; test 1.2 "deadline" and "detached after failure").
- [x] [minor] D3 didn't say the end protocol runs once. A second run (deadline, then the body settling) would see the next transaction's `inTransaction` and roll it back. Evidence: design D3. Resolved: the end protocol runs once, before the lock is released, and a late body is ignored (D3; test 1.2 "deadline" covers a late settle during the next transaction).
- [x] [minor] The deadline timer was not cleared or `unref()`ed, which would delay process exit. Evidence: design D3. Resolved: D3 now specifies both.

# Panel: catalog-roles
Tier: 2 · Reviewers: assumption tester, failure and abuse, scope and simplicity · Date: 2026-10-02

Reviewers report only critical and major findings (ADR 0024).

- [x] [critical] D5 ran each bound root statement as a short transaction on a postgres.js `reserve()`d connection. The archived adapter design measured that API and banned it. If the reserved connection's backend is lost, the next statement crashes the process, and the server has no `uncaughtException` handler. A connection released mid-transaction returns to the pool, so later root statements run inside it as the previous caller's role and user id; in 6b-2 that becomes a cross-user leak. Found by failure and abuse, and by the assumption tester (reproduced). Evidence: `node p2.mjs kill` (reserve, BEGIN, preamble, `pg_terminate_backend`, statement) -> `UNCAUGHT Cannot read properties of null (reading 'write')`, exit 3; `node p2.mjs release-in-tx` -> 4 of 6 later pool queries ran as `catalog_user` inside the open transaction; archived `2026-10-01-postgres-catalog-adapter/design.md` A5, A6, D3. Resolved: the bound root short transaction runs on adapter-owned `max: 1` clients managed like the transaction slots (tracked on close, retired rather than released, never reused in an unknown state). The root rules stay: 5 s deadline, no cancel once sent, no retry, `settled`. New pg tests cover a backend killed mid-transaction (the call rejects, the process survives, the client is retired) and a failed or timed-out COMMIT (no open transaction reaches another caller).
- [x] [major] The rollback was one-way. It left `20261006000000` in `supabase_migrations.schema_migrations` and the policies in place, so redeploying 6b-1 after a rollback failed every call. Its pg test would also have revoked cluster-wide role memberships and broken parallel suites. Evidence: after the probe's rollback, `select version … desc limit 1` -> `20261006000000`, and set role -> `permission denied to set role`; `docker/supabase/migrate.sh:44-46` skips recorded versions. Resolved: (owner, 2026-10-02) no rollback file or test. The design and the ADR entry document complete rollback SQL: revoke the memberships, restore grants, disable RLS, drop the policies, and delete the history row so a redeploy re-applies the migration.
- [x] [major] The cost gate could not see the new load risk. Bound root calls grow from 1 round trip to about 4 on a 3-connection root pool, with at least three calls per request including assets, and the suites never load that pool. Evidence: `postgresCatalogStore.ts:236-238` `rootMax = 3`, `rootTimeoutMs = 5_000`; `app.ts:175` `app.use('*', authContext)`; D14 measured only suite wall time. Resolved: (owner, 2026-10-02) a concurrency probe (parallel signed-in requests against one adapter, measuring root p95 and the timeout rate, before and after). Pipelining BEGIN, the preamble and the statement is mandatory. Stop and ask if root p95 more than doubles or any root timeout appears.
- [x] [major] The retry-count hook (`onRetry`, `CATALOG_RETRY_STATS`, baseline runs) was an untraced production API with nothing to measure in 6b-1, since allow-all policies read no tables. Evidence: design D2, D14; no spec mentions `onRetry`. Resolved: (owner, 2026-10-02) cut; retry counting moves to 6b-2.
- [x] [major] A root call's result was not pinned to a confirmed COMMIT. A statement could succeed and its COMMIT then fail (deferred constraint) after the caller saw the result, which breaks read-your-writes for the session mirror and KV. Evidence: `catalogDbContract.ts:149` tests the deferred-FK COMMIT failure on the transaction path only. Resolved: a bound root call resolves only after the COMMIT reply, and a COMMIT failure rejects it; a spec scenario and a root-path contract test were added.
- [x] [major] About 19 integration test files (51 calls) use `env.ports.catalog.first|all|run|tx` directly; they would stop compiling, contradicting "suites pass unchanged" and forcing a mid-implementation re-approval. Evidence: `grep -rn "env\.ports\.catalog\.\(first\|all\|run\|tx\)" server/src packages | wc -l` -> `51`. Resolved: the files are named in a task, adapted through a test-only system binding helper; 5.4's claim is corrected.
- [x] [major] Task order left the adapter pg suites and the whole integration project red from 2.2 to 5.4, because the migration revoked `autologger_app`'s grants first. Evidence: tasks.md "from task 2.2 … until task 5.4 … fail". Resolved: 2.2 keeps the app role's grants; a final group adds the revoke and the bare-role-refused test, so every commit stays green.
- [x] [major] ADR 0021's Decision text ("`set local role authenticated` with the caller's JWT claims") and `docs/supabase.md`'s root time-limit paragraph contradicted the change. Evidence: `docs/decisions/0021-…md:31-32`; `docs/supabase.md:152-155`. Resolved: task 6.1 edits both.
- [x] [major] The ADDED scenario "A system handle inside a user transaction is refused" had no task or test. Evidence: tasks 3.1-4.1 had no cross-binding case. Resolved: a test was added (misuse error plus rollback).
